## 홀드아웃

`scripts/build_holdout.py`가 `tests/fixtures/holdout/`에 변형 문서 6종(HO-01~HO-06, 결함 63건)을 만든다.
본 테스트셋과 결함 유형은 같고 값과 문장은 다르다. 예를 들어 불가능 날짜는 2020.4.31·2019.6.31·2024.9.31, 사건부호는 대법원+가단,
선고연도가 접수연도보다 앞서는 사건번호, 없는 특례법, 행정소송법 제71조를 넣었다. 인젝션은 흰 글자+ZWSP·덮개·0.8pt·Tr 3·페이지 밖
좌표·메타데이터·주석·첨부파일 경로로 넣었다. 개선 규칙은 홀드아웃 문서를 보고 만들지 않는다. 점수 차이가 10점 안인지만 확인한다.

홀드아웃 생성기 수정: Tr 3 문장 뒤에 렌더모드를 되돌리지 않아 HO-03의 뒤 문장·바닥글까지 보이지 않게 그려졌다
(PDF 렌더모드는 그래픽 상태에 남는다). 저장·복원으로 고쳐 다시 만들었다. v1 코드의 홀드아웃 점수는 25.9로 같다.

## 3-1 근본 원인(R1~R11) 수정

재현 시험: `tests/test_v2_root_causes.py`(각 원인을 일반 입력으로 재현한 뒤 수정).

| # | 원인 | 수정 |
|---|---|---|
| R1 | 다른 업로드 서면을 조항 원문으로 사용 | 조항 원문 후보에서 소장·준비서면·답변서·의견서·보고서를 뺀다(사용자가 `SOURCE_TEXT`로 지정한 문서는 예외). 조항 표제는 줄 첫머리·문장 끝 뒤에 올 때만 인정. 법령 인용 안의 "제N조"와 첨부문서를 가리키는 말이 없는 참조는 대조하지 않는다(`internal_citation.py`, `pipeline._internal_citation_check`) |
| R2 | 인용문이 엉뚱한 인용에 결합 | ±400자 최근접 결합을 없애고, 같은 문장 안에서 인용문 뒤 괄호 출처(판례 우선) → 뒤 판례 → 앞 인용 순으로 하나에만 결합(`citation_extractor.bind_quotes`) |
| R3 | 줄바꿈으로 법원·선고일 유실 | 줄 블록을 한국어 줄바꿈 규칙으로 이은 '읽기 본문'에서 한 번만 추출(`document_engine/reading_text.py`) |
| R4 | 검색 결과 첫 건 결부 | 사건번호 검색은 번호가 정확히 같은 기록만 records·result_id로 채택, 나머지는 원 응답에만 보존(`law_go_kr.search_case`) |
| R6 | 바닥글이 본문에 섞임 | 여러 쪽 가장자리에 반복되는 줄·쪽 번호 줄을 `running_head`로 표시하고 본문에서 제외(시험 문서 고지 판단에만 사용) |
| R7 | 줄바꿈 공백이 단어를 쪼갬, 법령명에 앞 문장 혼입 | 읽기 본문 결합 + 법령명을 끝에서부터 법령명 구성 토큰만 남기는 규칙(`normalize.law_name_suffix`). "공공기관의 정보공개에 관한 법률" 같은 긴 법령명 보존, "같은 법"은 앞 법령으로 해석, 두 글자 법령명(민법·형법·헌법) 추출 |
| R5 | 조문 본문을 확보하고도 대조하지 않음 | 인용 문장에서 문서가 그 조문에 대해 주장한 부분(`claim_text`)을 떼어 조문 본문과 대조(`provision_content.py`). 규칙 수치(분수, N일 이내 등 기한)가 다르면 CONTRADICTED 발견사항, 수치·핵심어가 맞으면 본문 대조 완료. 괄호 근거 표시는 수치만 비교. 기준일까지 확인되면 VERIFIED, 기준일이 없으면 PARTIALLY_VERIFIED로 두고 `content_confirmed`로 따로 센다 |
| R8(파서) | Tr 3·흰 도형 가림 지시문이 본문으로 읽힘 | pdfminer 그리기 단계에서 렌더모드·그리기 순서를 읽어 줄 단위 `INVISIBLE_RENDER_MODE`, `COVERED_BY_SHAPE` 숨김 사유 부여(스캔본 OCR 글자층은 제외) |
| R8(탐지) | 지시문이 AI 판별 항목으로 분류, 페이지 밖·첨부 지시문 누락 | 숨은 레이어는 같은 숨김 경로의 줄 묶음, 보이는 본문은 문장 단위로 분류하고 경로(`injection_path`)별 발견사항을 낸다. 첨부파일(글자 파일) 내용도 검사. 검증 생략·결과 변경·은폐 요구 변형 패턴 보강. AI 작성 판별 모델에는 지시문 블록을 통째로 가려 보낸다 |
| R9 | 증거·타임라인 산출물 없음, 표 안 판례 미추출 | `claim_engine/evidence_consistency.py`: 호증 목록(표·목록형)의 달력 날짜, 제출일 이후 작성, 대상 사건 이전 분석, 결번·목록 누락, 진술인 계급·소속 불일치, 서명 생략, 지각 범위 밖 단정(C), 의료 문서 입증취지 불일치(C), 진술 부분의 타 서면 문장 복사. 괘선 없는 표는 줄의 칸 좌표로 복원 |
| R10 | AI 판정 축과 문서 결과가 모순 | 축의 문서별 판정을 규칙·모델 교차판정 하나로 통일하고 문체 통계는 보조 신호로만 표시 |
| R9(일부) | 표 안의 판례 미추출 | 표 칸 단위 추출(칸 안 줄바꿈 결합), 표 영역의 줄 블록은 `table_line`으로 문장 분석에서 제외 |
| R11 | 같은 조문 중복 추출 | 블록·쪽 두 번 훑기 폐지, (정규화 키, 블록) 단위로 한 번만 |

두 자리 연도 사건번호(예: 94누4615)도 추출한다.

## Phase 1 판정 체계

| 항목 | 수정 |
|---|---|
| 인용마다 최종 판정 하나 | `verification_engine/finalize.py`: 같은 citation_id의 판정 finding을 우선순위(형식상 성립 불가 > A등급 불일치 > 불일치 > 조회 범위 내 미발견 > 미확인)로 하나만 남기고 나머지는 하위 판정 근거(`merged_findings`, evidence)로 합친다 |
| 필수 필드 | 모든 finding에 document_id·page·bbox(블록 기준)·rule_id(`엔진:유형` 기본값)를 채운다 |
| 비식별 표기 | ○○○·김○○·△△·010-0000-0000은 미기재 자리표시·예시 번호로 보지 않는다(`common/anonymization.py`). "[원고 주소 입력]", "[날짜]" 같은 각괄호 자리표시는 초안 흔적으로 잡는다 |
| 문서 종류별 문구 | 예시 문서 고지 finding의 "실제 계약서로 취급" 고정 문구를 문서 제목 줄에서 판별한 종류(소장·준비서면·답변서 등)로 바꾼다 |
