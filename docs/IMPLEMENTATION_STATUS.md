# ACAS_LAW Verifier 구현 현황

기준일: 2026-09-18. 프로그램 v0.4.0, 규칙 버전 2026.09.18.1.
개선 계획의 코드 구현과 실환경 검증을 구분한다. 최초 평가 계획은 당시 상태를 보존하며,
현재 완료 여부는 이 문서를 기준으로 한다. 법률 판단·진정성립·증명력을 자동 확정하지 않는다.

## 사용자 요구사항

- 제품명 ACAS_LAW Verifier, 업무용 표·탭 중심 반응형 화면과 쉬운 시스템 용어.
- 프로젝트 기본값 자동 입력, 한 번의 생성, 재요청 중복 방지, 생성 후 사건정보 편집.
  사건번호·당사자·법령 기준일 등 사건 사실은 임의 생성하지 않는다.
- 업로드 문서의 개별/일괄 제외·재포함, 제외 사유·이력, 중복 업로드 시 기존 상태 유지.
  원본을 삭제하지 않으며 변경 후 과거 결과와 새 검증 범위를 구분한다.
- 증거번호·제출자·문서 역할·제출일, 담당자·대리 당사자, 쟁점·요건사실·쟁점별 기준일 편집.
- 주장·쟁점 대조표, 주장/인정/부인/불지/가정적·예비적 주장, 지지·반박 근거와 부족 자료.
  자동 참조 연결은 입증력 판단이 아니며 변호사 의견과 분리된다.
- PDF 원문 대조, 공식 출처 확인, 검토 상태·판단·담당자·우선순위, 일괄 처리, 임시 저장,
  다음/이전 검토와 변경 이력. 버전 충돌 시 다른 검토 내용을 덮어쓰지 않는다.
- 초안/수정본/제출본 관계와 가시 본문 변경 비교, 해당 사건에서 포함된 자료의 단어 검색.
- 이율 변경·부분 변제·초일/말일·일수 기준·반올림을 명시한 Decimal 계산표와 JSON 내보내기.
  법정이율·변제충당 순서·시효를 임의 적용하지 않는다. 사용자가 근거와 가정을 확인한다.
- 내부용/공유용 보고서, 사전 점검과 명시적 확인, 초안과 별도 확정본, 작성자·확정시각·해시.
  PDF/DOCX/XLSX/CSV/JSON/Manifest의 기술 기록 보존. DOCX 외부 수정본은 원 확정본과 구별한다.

공유 DB 기반 비용 원장은 월/원 실행별 예약·정산을 원자적으로 관리한다. 불확실한 이미 전송된
호출의 예약은 장애가 났다고 해제하지 않는다. 한도 0은 무제한이며 가격·토큰 한도 설정이 필요하다.
현재 조직 정책은 작업 시작과 실제 외부 호출 직전 모두 확인한다. 이미 전송된 요청은 회수할 수 없다.

## 검증 근거

- 최종 전체 회귀 테스트: 559개 수집, 552개 통과, 7개 건너뜀, 실패 0개 (288.51초).
  PostgreSQL 미설정 3개, Tesseract 미설치 3개, Celery 브로커 미설정 1개를 건너뛰었다.
  결과 파일: artifacts/pytest-release-0918f.xml.
- JavaScript 5개 모듈 구문 검사와 git diff --cached --check 통과.
- 신규 SQLite와 기존 c82d01 데이터베이스의 head 마이그레이션 및 재적용, 기존 자료 보존 테스트.
- 권한·OIDC 검증·세션·CSRF·다운로드·감사 범위, 동시 비용 예약·작업 복구·취소·펜싱 회귀 테스트.
- 보고서 원본 보존·공유용 가림·봉인 내용 차단·수식 삽입 방어·형식 간 상태 일치·해시 변조 탐지.
- 가상 문서로 기본값 생성, 업로드, 제외/재포함, 증거정보, 쟁점과 근거 연결, 검토 저장,
  원문 이미지, 문서 비교·관계 저장, 사건 내 검색, 6종 초안과 별도 확정본 생성을 실제 브라우저에서 확인했다.
- 1440px 대조표와 확정 전 점검, 390px 보고서, 360px 계산 입력·결과의 겹침과 페이지 폭을 확인했다.
  브라우저 오류 로그는 없었고 가상 계산 36,500원 x 연 10% x 10/365의 이자 100원을 확인했다.
- 보고서 렌더링·산출물 저장은 DB 쓰기 전에 끝내도록 하여 SQLite 작업 임대 갱신을 막지 않는다.
- 계산표는 1440/768/390px, 소수 문자열 전송, 프로젝트 변경 중 요청 취소·이전 결과 차단을 검사했다.
- PDF는 한글 글꼴 포함 및 실제 페이지 렌더링 확인. DOCX는 ZIP·본문·관계·보안 검사를 통과했으나
  LibreOffice 미설치로 Word/LibreOffice의 시각적 페이지 렌더링 검증은 하지 못했다.
- 테스트·스크린샷·가상 자료·DB·실행 산출물은 artifacts/에 보관하고 Git에서 제외한다.

## 외부 검증과 남은 한계

1. 국가법령정보·LLM 실제 인증값, 기관 SSO/KMS, PostgreSQL·Celery 브로커, 한국어 OCR 실환경 검증은
   해당 환경을 구성해야 한다. 모의 응답 회귀 테스트는 공식 서비스 최신 응답이나 모델 품질 보증이 아니다.
2. 실제/비식별 사건 단위 전문가 라벨, 정밀도·재현율·잘못된 확인 완료 비율, 검토 시간·비용 파일럿은
   자료와 법률 검토자가 필요하다. 평가 CLI와 의도적으로 불완전한 합성 예제를 구현했으며,
   합성 예제 지표를 제품의 실무 성능으로 주장하지 않는다.
3. 경과조치의 법적 적용, 요건사실·입증책임의 정답, 후속 판례의 선례 변경과 사건 적용 결론,
   의미 기반 유사 사건 검색은 자동 확정하지 않는다. 현재 검색은 사건 내 단어 후보 검색이다.
4. 자동 표/서식의 모든 의미 복원, 모든 문서 종류별 법률 검토, 전자서명·인증서·타임스탬프의
   암호학적 유효성 검증, 법적 기한·시효 확정은 지원 범위 밖이다.
5. 자료·DB 암호화, 파일 접근권한, 키 백업·복구, 실제 비식별화 누락 검증과 기관 정책 검토를
   마치기 전 실제 비밀 사건자료를 외부에 공개하지 않는다. 공유용 가림도 수동 확인이 필요하다.
6. 비용 원장은 설정 가격·상한에 대한 호출 승인 통제이며 공급자 청구액 보증이나 다른 DB/프로그램
   호출 통제가 아니다. 사고 후 불확실한 예약은 실제 사용량 대사 후 정산해야 한다.

## GitHub 통합 주의

이번 구현은 be69f61에서 시작했다. 최종 fetch에서 origin/main이 9c5d374로 이동했고,
별도 비밀번호 로그인·세션·RBAC 및 Render 부트스트랩 변경이 추가된 것을 확인했다.
인증·라우터·DB·화면 영역이 겹치므로 기존 원격 작업을 덮어쓰지 않고
codex/acas-law-verifier-v0.4 브랜치에 전달한다. main 병합·배포는 수행하지 않았다.
병합 시 두 인증 체계의 세션·계정·권한·부트스트랩과 마이그레이션 분기를 일관되게 통합하고
보안 회귀 테스트를 다시 수행해야 한다. 아래 검증 결과는 이 기능 브랜치에 대한 결과다.
