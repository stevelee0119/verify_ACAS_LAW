## 2. 평가 도구 변경과 v1 재채점

변경 내용(`scripts/eval_testset.py`, 채점 방식 v2):

1. 대조군 오탐을 센다. 대조군(정답지 expected=PASS) 문서의 CONTRADICTED 판정과 A·B등급 SUSPICIOUS 판정은 FP-TRAP과 맞지 않아도 모두 오탐이다.
   - 정답지는 바닥글의 '가상 문서 표시'를 평가 대상에서 뺀다. 그래서 SPECIMEN_DOCUMENT_DECLARED는 채점하지 않고, 따로 목록으로 적는다.
2. 결함 유형 ↔ finding 유형 대응표(DEFECT_TYPE_MAP)를 둔다. 표에 없는 조합은 점수가 없고 '유형 대응표로 점수를 주지 않은 일치'에 적는다.
   - 예: 가공 인용문(CIT-FAB-Q)에 붙은 UNCERTAINTY_NOT_DISCLOSED 판정은 점수를 받지 못한다.
   - 예: AI 작성 흔적(AIGEN)에 붙은 LEGAL_ARGUMENT_INVALID 판정도 마찬가지다.
3. '모델 의견 서술' 0.5점은 모델이 실제로 응답한 실행에서만 준다. 그때도 모델이 낸 글만 인정한다. 규칙 판별기의 이유 문장과 '모델을 쓰지 못함' 안내문은 모델 의견이 아니다.
4. 블라인드 비교(`scripts/findings_diff.py`)는 새로 생긴 CONTRADICTED·A/B 판정 전체를 '오탐 후보' 목록으로 낸다. `eval_compare.py`와 `findings_diff.py`는 환경 지문이나 채점 방식이 다르면 '비교 불가 항목'을 먼저 적는다.

## 4. 완전 환경 재실행

- 테스트셋 v1·홀드아웃: CI 테스트셋 평가(공식 DB·AI 3종·한국어 OCR)를 이 커밋으로 돌린다. 결과(채점 JSON·MD, 파이프라인 결과 gzip, 실행 번호)는 CI가 `docs/eval_ci/`에 기록한다. 영역별 결과는 CI 결과가 나온 뒤 이 장에 적는다.
- 블라인드 v2·v3: 사용자가 별도로 완전 환경에서 실행하기로 했다. 실행 방법은 다음과 같다(키는 환경변수로 준다).

```
LV_ALLOW_NETWORK=1 LV_LAW_GO_KR_OC=… OPENAI_API_KEY=… ANTHROPIC_API_KEY=… GEMINI_API_KEY=… \
  python scripts/findings_diff.py run <블라인드 폴더> --out blind_full_v2.json
python scripts/findings_diff.py diff <이전 결과>.json blind_full_v2.json --out 비교.md --json 비교.json
```

결과 JSON의 `run_manifest.environment`에 환경 지문과 필수 자원 상태가 남는다. 비교 보고서는 지문이 다르면 비교 불가 항목을 먼저 적는다.
