# 기록형 답안 분석 품질 개선

## 확인 범위와 한계

- 사용자가 제공한 기록형 문제 PDF, Gemini Spark 생성 답안 DOCX 및 기존 실행 JSON을 대조했다.
- 답안 DOCX의 ZIP에는 core/app 문서 속성이 없었다. 사용자가 밝힌 생성 경위는 이번 평가의 정답이지만, 파일 내부에서 검증 가능한 AI 생성 이력은 아니었다.
- 기존 JSON에서 최종 작성 주체는 이미 판단 보류였다. 오류는 Gemini의 개별 인간 작성 유력 의견과 그 근거 해석에 있었다.
- 실제 Drive에서 판례집 세 권을 읽기 전용으로 내려받아 로컬 추출·색인·검색을 재실행했다. Drive 전체 40권 및 운영 환경의 세 LLM을 재실행한 결과는 아니다.
- 사용자 원본, 실행 JSON 및 판례집 파일은 저장소에 추가하지 않는다. 회귀 테스트는 합성 자료를 사용한다.

## AI 작성 판정

전문적 문체, 법리 정확성, 자연스러운 한국어와 AI 흔적의 부재는 인간 작성의 증거가 아니다. 인간 작성 이력 없는 모델의 HUMAN_AUTHORED_LIKELY 의견은 UNCERTAIN으로 보류하고 원래 의견(raw_verdict)과 미채택 이유를 보존한다.

분석기가 직접 인용을 가린 공백을 모델이 원 문서의 암기용 빈칸으로 잘못 해석한 것도 확인했다. 프롬프트에 마스킹의 출처를 명시했다. 인용 오류와 문서 속 지시문은 작성 주체의 증거로 사용하지 않는다.

이 수정은 이 답안을 강제로 AI 작성으로 분류하는 장치가 아니다. 출처 흔적이 없는 AI 문서는 여전히 판단 보류일 수 있다. 한국어 법률문서에 대한 교정된 확률·정확도도 확보되지 않았다. 향후에는 실제 생성 경위가 확인된 AI/인간/공동 작성 문서로 문서 종류별 평가를 구성하고, 오탐률·미탐률·판단 보류율을 함께 측정해야 한다. 검증 가능한 생성 서비스 내역 또는 서명된 출처 이력의 별도 수집이 문체 판별보다 강한 근거가 된다.

탐지 한계에 관한 연구: [Can AI-Generated Text be Reliably Detected?](https://arxiv.org/abs/2303.11156).

## 6,000자 제한과 자원 영향

기존 6,000자는 전체 문서 파싱 제한이 아니라 작성 주체 검토 LLM의 입력 표본 상한이었다. 기존 JSON 기준 본문 8,803자 중 2,803자(31.8%)가 모델 입력에서 빠졌다. 현재 파서로 첨부 DOCX를 다시 읽은 본문은 8,567자이며, 두 수치는 서로 다른 실행의 정규화 결과이므로 동일한 계측값으로 취급하지 않는다.

- 기본 상한을 24,000자로 변경했다. 이번 답안은 두 계측 기준 모두 상한 내이므로 작성 주체 검토 대상 본문 전체를 한 번에 전달한다. 직접 인용·지시문 제외 정책은 유지한다.
- `LV_AUTHORSHIP_MAX_CHARS`로 6,000~48,000자 사이에서 조정한다. 상한을 넘으면 앞·중간·뒤 표본과 누락 범위를 기록하고 전체 작성 판정 승격을 막는다. 무제한 전문 분석은 아니다.
- 기존 보고서의 8,803자를 기준으로 하면 모델별 본문 입력이 2,803자, 46.7% 증가한다. 세 모델 모두 응답한다면 합계 추가 입력은 8,409자다. 호출 수와 출력 토큰 상한은 늘리지 않는다.
- 전체 작업 시간·비용이 46.7% 증가한다는 뜻은 아니다. 실제 증가는 공급자별 토큰화·입력 단가·출력 길이·대기시간·재시도에 달려 있다. 운영 환경에서 계측하지 않은 초 단위 지연이나 금액은 제시하지 않는다.
- 문서 파싱은 이미 전문을 읽었으므로 이번 변경의 주된 추가 자원은 외부 모델의 입력 처리다. 로컬 문자열 증가만으로 서버 메모리를 크게 증설할 근거는 없다. 동시 분석 수와 대형 PDF의 파싱 메모리는 별도로 관찰해야 한다.
- 기존 JSON의 모델 실행 43건은 법률 검토 등을 포함한 전체 호출이다. 이를 작성 주체 판별 3건의 비용·시간으로 오인해서는 안 된다.

## 참고문헌 처리

형사소송법 판례집의 “적법하다고 평가할 수 없다”는 법률 서술이 출력 조작 명령으로 오탐돼 파일 전체가 격리됐다. 비명령형 가능·부정 서술을 좁게 제외하되 실제 명령, 숨김 지시문 및 광범위 공격 격리는 유지했다. 추출기 버전을 올려 기존 격리 캐시를 다음 분석에서 다시 읽는다.

대형 판례집의 pypdf 텍스트 추출은 로컬에서 약 57~81초가 걸렸다. 기존 설치된 pypdfium2를 우선 사용하고 실패·빈 텍스트 쪽은 pypdf로 재확인한다. 동일 세 권의 격리 프로세스 재검증에서는 약 12~19초로 30초 제한 안에 완료했다. 이는 단일 PC의 실측이며 Render 성능 보장은 아니다. 암호화 검사, 256MB 프로세스 한도, 1,500쪽·300만자 상한과 인젝션 검사는 유지한다.

| 자료 | 텍스트 색인 | 미추출 쪽(원본 PDF 순서) |
|---|---:|---|
| 형사소송법표준판례 | 392/401쪽 | 2, 30, 32, 38, 40, 68, 70, 326, 378 |
| 2023 형법표준판례 선정연구보고서 | 451/454쪽 | 26, 192, 194 |
| 형법표준판례 연구보고서 | 473/477쪽 | 2, 28, 30, 196 |

부분 색인은 파일 전체 미검토가 아니다. 반대로 텍스트 미추출 쪽을 모두 빈 쪽이라고 단정하거나 전문 검토 완료로 표시하지도 않는다. 이미지로 된 실질 내용이 있다면 OCR된 검색 가능 PDF로 보완해야 한다.

검색은 한국어 종결어미 조각을 제거하고, 긴 답안의 쟁점 구간별 질의를 병행한다. 분야명이 맞는 표준판례집은 별도 본문 검색을 수행하고 관련성이 확인된 책의 발췌 슬롯을 우선 확보한다. 파일명만 맞는 자료는 통과시키지 않는다. 검색어 빈도는 일괄 조회해 반복 SQL 비용을 줄였다.

세 권으로 구성한 로컬 검색 재현에서 모두 발췌 대상으로 선택됐다. 실제 선택된 위치에는 형사소송법 311·358·387쪽, 형법 330쪽, 2023 형법 325쪽이 포함됐다. 색인 범위와 AI에 제공한 최대 6개 발췌문은 서로 다른 검토 범위다. 관련 책 모두의 모든 쪽을 LLM이 검토한 것이 아니다.

화면·DOCX·PDF의 제목은 `주요 참고문헌 검토 결과(RAG)`로 통일한다. 자료별 사유는 처리 기록 한 곳에 모으고 공통 오류만 별도 표시한다. 원본 JSON 감사 기록의 issues/inventory는 보존한다.

## 인용 취지와 사안 적용

인용 평가 칸 하단에 기존 공식 원문 기반 의미 검토를 연결한다. 문구 차이, 법리 취지, 사실관계·적용 조건을 나눠 설명하도록 하고 모델별 근거 인용과 판단 한계를 함께 표시한다. 근거 문구가 해당 공식 원문에 없거나 다른 인용의 검토이면 채택하지 않는다. 추가 LLM 호출은 하지 않는다.

“할 수 없다”고 판시했다는 전달 표현과 말미의 `(등 참조)` 때문에 부정 의미를 놓치는 문제, 쟁점의 종속절 부정을 최종 서술어 부정으로 읽는 문제도 보강했다. 진짜 의미 반전은 계속 탐지하는 회귀 사례를 추가했다.

기존 분석 JSON은 변경하지 않는다. 새 검토 범위, 갱신된 참고문헌 색인 및 인용 맥락 의견을 얻으려면 배포 후 답안을 다시 검증해야 한다.
