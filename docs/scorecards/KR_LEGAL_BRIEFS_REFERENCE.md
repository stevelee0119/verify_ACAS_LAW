## 등록 상태

`KR-LEGAL-BRIEFS-30`, `1.0-draft`를 **검토 대기 중인 평가 기준서면**으로 등록했다. 수신 자료의 무결성 확인은 완료했으나 실제 독립 한국 변호사 검토자는 **0명**, 법률 적용은 `PROVISIONAL`, 정답 라벨은 미확정이다. 원문의 주장·법률 적용을 정답으로 간주하지 않는다. 프로그램 실행·채점·first-touch 측정은 아직 하지 않았다.

실제 한국 변호사 **1명**이 검토한다. 검토자 자격·제작 및 라벨 결정 참여 여부·관계와 이해관계·독립성을 기록하고, 판단하기 어려운 사항은 보류한다. 제3판정자나 복수 채점자 일치도를 요구하거나 확보했다고 표시하지 않는다.

## 구성과 적용 범위

사례별 Word/Markdown 30건, A/B/C 각 10건의 합성 입력이다. 층화는 형사 실체·절차, 행정소송, 수사권·재판권 관련 편의 구성이다. 일부 사례는 공소장 제출안 2부를 포함하므로 사례 수와 제출안 수를 구별하고, 여러 파일 형식을 별도 독립 표본으로 세지 않는다. 실제 사건 모집단의 대표성은 확인되지 않았다.

- **지금 사용 가능:** 입력 형식·문서 구조의 평가 자료 준비 및 범위 설계. 실제 프로그램 시험 결과는 별도로 기록한다.
- **변호사 검토·정답 확정 후:** 법률 정확성, 쟁점·요건, 사실-근거 연결, 반론, 불확실성·적절한 유보 평가. 정상 주장에 대한 오탐과 근거 없는 단정에 대한 누락을 함께 라벨링한다.
- **현재 보장되지 않는 범위:** 실제 연락처·주민등록번호·성명 마스킹, 판례 진위, OCR, 실제 Drive 대조, 실제 사건 품질. 입력은 합성 토큰이며 확인되지 않은 판례 인용·실제 개인정보를 포함한 전용 시험을 대신하지 않는다.

`source_review.md`와 법령 조회 snapshot은 검토 근거로 보존한다. 일부 최초 HTTP 200 응답은 오류 페이지이므로 법령 근거로 사용하지 않는다. 정상 대체 조회 본문도 행위일 적용 버전·부칙·하위법령·필요 판례·관할·기간·절차의 최종 확인을 대신하지 않는다. 출처 검토 기록 자체를 독립 법률 검증 완료로 승격하지 않는다.

## 정답 확정과 측정 절차

1. 독립 한국 변호사 1명이 사례별 원문·조회 근거와 적용 시점을 검토하고 `APPROVE / REVISE / HOLD` 및 정확한 검토 문서 해시를 기록한다. 공소장 사례의 복수 제출안·분리 메모도 포함한다. 수정본은 재검토하며 전체 검증 완료는 30건 모두 최종 승인된 뒤에만 표시한다.
2. 비공개 라벨 작업표에 필수 쟁점·근거 snapshot·적절한 유보·잘못된 단정·정상 주장 대조 항목·채점 근거를 확정한다. 빈 라벨은 오류 0이나 정답 0으로 집계하지 않는다. 보류 사례는 채점 분모에서 제외하고 사유·건수를 별도 기록한다. 검토·수정 후 새 버전과 해시를 만들고 검토자가 최종 해시를 확인한다.
3. 제품 수정 전에 대상 코드 SHA·입력/정답 버전·설정·환경·법률 기준일·측정 범위를 고정한다. 오프라인 측정 명세가 완성되면 `scripts/probe_document.py record`로 실제 first-touch를 남긴다. 정답이나 실행이 없는 이번 등록을 first-touch 결과로 기록하지 않는다.
4. 법률 품질은 기존 TK-75 평가의 다섯 축(법적 정확성, 쟁점·요건, 사실-근거 연결, 반론·적용 차이, 불확실성·유보)을 각 0–2점으로 적용할 수 있다. 사용 전 해당 사례의 채점 기준을 변호사가 확정한다. 운영본·후보 또는 Claude OFF/ON 비교 시 같은 입력·모델·근거·설정을 사용하고, 한 명의 변호사에게 조건을 가린다. 모델 출력과 정답/검토 메모는 분리한다.
5. 실제 Claude 시험은 사용자가 정한 **릴리스 후 Render 측정** 일정과 현 예산 한도 내에서 수행한다. 사전 확정한 실행 계획 없이 30건 전체 또는 반복 수를 자동 확대하지 않는다. API 키는 보관 자료나 저장소에 넣지 않는다. 품질·실패·usage 기반 비용·재시도/fallback 포함 지연을 함께 남긴다.
