# 일자별 개선 추이표

평가 에이전트(Codex 평가 세션)가 관리한다. 사용자 지시(2026-10-04)에 따라 1일 단위로 프로그램의 개선 추이를 한 표로 본다.
평가 결과를 제시할 때(판정 기록·사용자 보고·PR 코멘트 요약)마다 이 표의 최근 행을 함께 낸다([CLAUDE.md](../../CLAUDE.md), [AGENT_ROLES 2.1](../AGENT_ROLES.md)).

## 작성 규칙
1. **한 날짜 한 행.** 날짜는 **한국 시각 기준 평가 측 측정일**이다. 커밋 시각은 재기록 등으로 서술상 날짜와 어긋날 수 있어 쓰지 않는다.
2. **보조 기능 표시(2026-10-04):** 연락처·주민등록번호 외 개인정보 지표는 '참고'로 적는다(판정 미반영).
3. **이 표는 요약이다.** 모든 칸은 [HISTORY](HISTORY.md) 절·[판정서](f1_gate_verdict.md)·티켓에 근거가 있어야 한다. 근거 절을 '평가 개요' 칸에 적는다. 새 수치를 이 표에만 적지 않는다.
4. **성능 점수 칸**
   - 고정 시험: `dev / holdout / 오탐`. 하루에 여러 SHA를 쟀으면 그날의 범위를 적는다.
   - 처음 보는 서면·비공개 세트: 이름(세트)·SHA·점수를 함께 적는다.
   - **조건(입력·채점 규칙·환경·세트)이 같을 때만** `→`로 증감을 표시한다. 서면마다 명세가 다르면 나란히 적고 증감 표시를 하지 않는다.
   - 비공개 세트는 건수만 적는다. 문장·이름은 적지 않는다.
5. **주요 기능·개선 칸:** 그날 측정에서 **확인된** 개선만 적는다. 구현 보고서에만 있고 평가 측이 재현하지 못한 것은 적지 않는다.
6. **회귀 칸:** 새로 확인된 회귀를 티켓 번호와 함께 적는다. 없으면 '새 회귀 0(근거)'로, 측정하지 않았으면 '측정 안 함'으로 적는다.
7. **평가 개요 칸:** 측정한 증분·SHA, 판정, 측정 조건, 측정하지 못한 것, 근거 절.
7. 구현이 없던 날(평가·도구만 바뀐 날)도 행을 남긴다. 제품 코드가 그대로면 점수 칸에 '제품 코드 변화 없음(=SHA)'을 적는다.
