# 같은 입력으로 재시도 복구

## 확인한 운영 원인

운영 화면의 실패 상세에서 `Snapshot execution setting changed: rule_version`이 세 차례 반복되고, 작업 기록에서 각 시도가 자료 처리 전에 끝난 것을 확인했다.

기존 수동 재시도는 원본 자료뿐 아니라 이전 배포의 실행 설정을 복사했다. 워커는 현재 전역 설정과 저장된 설정이 다르면 재현성이 보장되지 않으므로 실행을 거부한다. 이 충돌을 일시 오류처럼 세 번 자동 재시도하므로 배포 후 같은 실패가 반복됐다.

별도로, 과거 실행에서 재시도를 다시 누르면 이미 실패한 자식 실행을 반환하는 경로와 결과 조회에 실패할 때 진행 상태 추적도 시작하지 않는 화면 경로를 재현했다.

## 변경 범위

- 수동 재시도는 저장된 입력의 해시를 먼저 검증한다. 원본 파일·SHA-256·사건 조건·분석 범위·보안 정책은 유지하고 현재 배포의 실행 설정을 새 실행에 기록한다.
- 설정이 바뀌면 규칙·프롬프트·모델 구성 버전과 검증 키도 새 설정에 맞춘다. 부모 실행과 결과는 수정하지 않는다.
- 원래 네트워크가 금지된 실행의 외부 전송을 새로 허용하지 않는다. 비용 한도와 누적 비용 원장 연결을 유지하며, 현재 프로젝트·조직의 더 엄격한 정책도 기존 워커 경로에서 적용한다.
- 실패·취소·부분 완료된 재시도 이력을 따라 새 실행을 생성한다. 진행 중이거나 성공한 자식 실행은 재사용한다. 프로젝트 행 잠금으로 다른 이력에서 동시에 재시도해도 중복 작업을 만들지 않는다.
- 자동 복구는 원래 저장된 설정을 계속 요구한다. 설정 불일치는 `EXECUTION_SETTINGS_CHANGED`로 한 번에 종료하고 수동 재분석 방법을 안내한다. 일시적인 워커·연결 실패의 기존 재시도는 유지한다.
- 재시도 화면은 아직 없는 결과를 기다리지 않고 새 실행의 상태를 추적한다. 완료 이후 결과를 읽으며 일시적인 조회 실패는 기존 폴링 복구 로직을 따른다.
- 입력 기록이 없는 옛 실행은 임의로 현재 문서들을 같은 입력이라고 간주하지 않는다. 자료를 선택한 새 검증이 필요하다고 명확히 알린다.

## 검증 범위

`tests/test_retry_recovery.py`는 배포 설정 변경, 실패 이력 재시도, 동시 요청, 원본 무결성, 네트워크·비용 제한, 실제 DOCX 재분석·결과 저장을 검사한다. `tests/test_frontend_retry.py`는 데스크톱과 모바일에서 재시도 버튼·확인·진행 추적·완료 표시를 검사한다. 기존 작업 관리·인증 세션·권한·프로젝트 삭제·워커 테스트도 함께 실행한다.

이 변경은 기존 분석 결과를 덮어쓰지 않는다. 운영 재시도 시 등록된 외부 AI 정책과 공급자 상태에 따라 실제 분석 시간이 달라질 수 있다.
