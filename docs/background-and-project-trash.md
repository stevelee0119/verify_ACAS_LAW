# 백그라운드 검증과 프로젝트 휴지통

## 사용 흐름

- 서버가 접수한 검증은 브라우저 탭의 타이머가 아니라 서버 작업 큐에서 실행된다.
- 다른 탭이나 프로젝트로 이동해도 검증을 취소하지 않는다. 탭 복귀, 페이지 복원, 네트워크 복구 시 기존 작업 상태를 다시 조회한다.
- 왼쪽 `진행 작업`에서 접근 권한이 있는 프로젝트의 진행 중 작업과 최근 24시간 내 종료된 작업을 확인하고 해당 결과로 이동한다.
- 작업 목록은 최대 50건이며 진행 중 작업을 우선 표시한다. 진행 건수는 표시 개수와 별도로 전체를 집계한다.
- 로그인 만료 시 자동 로그인 팝업을 반복하지 않는다. `다시 로그인`으로 인증한 후 기존 작업 조회를 재개한다.

브라우저나 운영체제가 숨겨진 탭을 정지시키면 화면 갱신은 늦어질 수 있으나 서버 작업 취소로 처리하지 않는다. 서버 자체의 종료, 호스팅 중지, 저장소 장애까지 브라우저 기능으로 방지하는 것은 아니다. 지속적인 장시간 처리는 실행이 유지되는 서버와 영구 DB/원본 저장소가 필요하다. 서버 재시작 후에는 기존 DB 작업 복구와 실행 임대 정책을 따른다.

## 프로젝트 삭제와 복원

- 프로젝트 제목 옆 휴지통 아이콘은 프로젝트 관리 권한이 있는 사용자에게 표시된다. 자신이 만든 프로젝트의 소유자도 삭제할 수 있다.
- 확인 후 프로젝트를 휴지통으로 이동한다. 검토 목록에서 숨기고 일반 문서·결과 API 접근 및 새 검증 실행을 차단한다.
- 대기·진행·재시도 예정 검증이 남아 있으면 서버가 삭제를 거절한다. 완료를 기다리거나 기존 검증 취소 기능을 사용해야 한다.
- 왼쪽 `휴지통`에서 복원한다. 업로드 원본, 검증 결과, 검토 내용과 활동 기록은 유지된다.
- 삭제·복원 행위를 활동 기록에 남긴다. 다른 조직이나 접근 권한이 없는 프로젝트는 목록에 노출하지 않는다.

이 기능은 **복구 가능한 삭제**이며 영구 파기나 저장 공간 회수가 아니다. 자료 파기 의무, 보존 기간 또는 별도 영구 삭제 정책을 대신하지 않는다.

## 운영과 데이터 변경

배포 시 `alembic upgrade head`가 프로젝트에 `deleted_at`, `deleted_by`와 삭제 일시 인덱스를 추가한다. 신규 리비전은 `a72e10`, 이전 리비전은 `f3a91c`이다. 기존 자료를 삭제하지 않는다. 삭제 이력을 잃는 스키마 다운그레이드는 거부한다. 되돌려야 할 때에는 검증된 백업을 기준으로 복원해야 한다.

삭제와 검증 접수·재시도·파일 저장은 동일한 프로젝트 잠금을 사용한다. SQLite는 쓰기 트랜잭션, PostgreSQL은 프로젝트 행 잠금으로 순서를 보장한다.

## 제목 글꼴

상단 제목은 22px, 600 굵기의 로컬 한글 웹폰트로 표시한다. 좁은 화면에서는 제목을 별도 줄에 배치한다. 외부 폰트 서버를 호출하지 않는다.

- 원본: [Google Fonts Noto Sans KR](https://github.com/google/fonts/tree/main/ofl/notosanskr)
- 배포 파일: `apps/web/static/fonts/acas-title.woff2` (제목에 필요한 문자만 포함)
- 라이선스: `apps/web/static/fonts/OFL-NotoSansKR.txt` (SIL Open Font License 1.1)

## 회귀 검증

- 프로젝트 삭제·복원 권한, 조직 간 격리, 직접 문서·결과 접근 차단, 원본 및 감사 이력 보존
- 대기/실행 중 검증 삭제 차단, 삭제된 프로젝트의 새 작업·재시도 차단
- 기존 스키마 업그레이드 및 데이터 보존
- 브라우저 조회 없이 서버의 대기 작업 실행·결과 저장
- 탭 생명주기 복원, 프로젝트 전환, 중복 검증 방지, 휴지통 확인·취소·복원
- 1440/768/390/320px 헤더 및 글꼴 로딩, 모바일 휴지통 배치
