# 국가법령정보센터 무응답 대비 정책 (재시도·캐시·UNVERIFIED)

국가법령정보센터(law.go.kr) 등 공식 출처가 응답하지 않을 때 검증기가 어떻게 동작하는지 정리한다. 수치는 모두 현재 코드의 기본값이며, 괄호 안은 설정 환경변수다. 근거 코드는 `packages/source_adapters/transport.py`, `packages/legal_engine/verifier.py`, `packages/verification_engine/pipeline.py`, `packages/common/config.py`이다.

## 1. 원칙

1. **조회 실패는 부존재가 아니다.** 응답을 받지 못한 인용은 UNVERIFIED(미확인)로 남긴다. "존재하지 않는 판례"라고 판정하지 않는다.
2. **정상 응답에서 일치 기록이 없을 때만 NOT_FOUND를 쓴다.** 이때도 판정 범위를 "조회 범위 내에서 찾지 못함"(`absence_scope: SEARCHED_SCOPE_ONLY`)으로 적는다. 미공개 판결이나 DB 수록 범위 밖일 수 있다는 설명을 함께 단다.
3. **헌법재판소 결정은 조회 결과가 없어도 NOT_FOUND를 쓰지 않는다.** 헌재결정례 DB에서 확인하지 못하면 UNVERIFIED로 두고, 조회한 DB·방식·건수를 근거로 남긴다.
4. **형식상 성립할 수 없는 표기는 조회와 무관하게 판정한다.** 대상은 달력에 없는 날짜, 법원과 사건부호의 불일치 등이다. 이 판정은 출처 무응답의 영향을 받지 않는다.

## 2. 요청 단위 재시도

| 항목 | 값 | 설명 |
|---|---|---|
| 요청 시간 한도 | 12초 (`LV_HTTP_TIMEOUT`) | n번째 시도는 한도 × n. 최대 45초이며, 남은 문서 조회 예산을 넘지 않는다 |
| 최대 시도 | 3회 (`LV_SOURCE_LOOKUP_ATTEMPTS`, 1~5) | 같은 요청의 자동 재시도 |
| 재시도 대기 | 1·2·4초…(최대 8초) | 서버가 `Retry-After`를 주면 그 값을 따른다 |
| 재시도 대상 | 시간 초과, 연결 오류, HTTP 408·429·5xx | 요청 자체의 오류(400 등)는 다시 보내도 같으므로 재시도하지 않는다 |
| 즉시 중단 | HTTP 401·403 | 인증·권한 문제이므로 같은 출처 조회를 멈추고 "출처 접근 권한 확인 필요"로 남긴다 |
| 요청 간격 | 같은 출처에 최소 0.3초 (`LV_SOURCE_MIN_INTERVAL_SECONDS`) | 연속 조회에서 응답이 끊기는 구간이 실측되어 처음부터 간격을 둔다 |

## 3. 출처 단위 일시 차단(회로 차단)

- 같은 출처에서 재시도 가능한 실패가 2번(`FAILURE_THRESHOLD`) 누적되거나 429를 받으면, 그 출처를 15초 동안 조회하지 않는다.
- 차단 중인 조회는 기다리지 않고 "외부 출처의 반복 장애로 조회를 잠시 보류"로 끝난다. 결과는 UNVERIFIED이다.
- 문서가 바뀌면 실패 누적은 초기화한다. 인증 실패와 서버의 `Retry-After`는 유지한다.

## 4. 문서 단위 예산과 지연 재조회

| 항목 | 값 |
|---|---|
| 문서당 조회 예산 | max(120초, 인용 수 × 30초), 최대 900초 (`LV_SOURCE_LOOKUP_BUDGET_SECONDS`, `LV_SOURCE_LOOKUP_MAX_DOCUMENT_SECONDS`) |
| 지연 재조회 예산 | 문서당 1회, 120초 추가 (`LV_SOURCE_LOOKUP_RECOVERY_SECONDS`) |

1. 인용을 차례로 조회하면서 재시도 가능한 실패가 남은 인용을 모아 둔다.
2. 문서의 모든 인용을 한 번 본 뒤, 모아 둔 인용만 추가 예산으로 다시 조회한다. 차단 중인 출처는 해제 시각까지 한 번 기다린 뒤 조회한다.
3. 재조회 결과는 인용마다 `recovery_status`로 남긴다.
   - `RECOVERED`: 모든 요청이 응답을 받음
   - `RETRY_EXHAUSTED`: 재시도 후에도 응답 없음
   - `UNAVAILABLE`: 그 밖의 조회 불가
4. 재조회 후에도 응답을 받지 못한 요청이 남았는데 판정이 NOT_FOUND였다면 UNVERIFIED로 되돌린다. 시간 초과된 보조 검색은 부존재의 근거가 아니기 때문이다. 판정 근거에는 "외부 출처 자동 재조회 후에도 확인하지 못한 요청이 남아 있다(HTTP 시도 n회). 출처 연결 회복 후 재검증이 필요하다"가 붙는다.

## 5. 캐시

| 캐시 | 범위 | 내용 |
|---|---|---|
| 실행 단위 응답 캐시 | 한 번의 검증 실행 안에서만 | 정상 응답(2xx)만 저장한다. 최대 64건·16MB이며 오래된 것부터 버린다. 실행이 끝나면 비운다. 다른 프로젝트·실행과 공유하지 않는다 |
| 내부 미러(`config/legal_mirror`) | 저장소에 포함 | 공식 원문 수집(`scripts/fetch_official_sources.py`)으로 받아 검토한 판례·조문이다. 조회 전에 먼저 확인하므로, 출처가 무응답이어도 미러에 있는 원문은 대조할 수 있다. 미러 기록에는 출처 URL을 남긴다 |

실패 응답은 캐시하지 않는다. 한 번 무응답이었던 요청도 다음 조회에서 다시 시도한다.

## 6. 보고서 표시

- UNVERIFIED 인용은 보고서의 '미확인 항목'에 남는다. 함께 적는 내용은 사유, 조회 기록(`source_lookup`: HTTP 시도 수, 캐시 적중, 요청별 상태), `recovery_status`이다.
- 미확인은 '결함 없음'이 아니다. 요약 점수의 미확인 비율에 들어가고, 사람 확인 대상이다.
- 출처 전체를 쓸 수 없는 경우(인증키 없음, 네트워크 차단)는 `unavailable_sources`로 따로 표시한다.

## 7. 실연동 통합 테스트(CI)에서의 처리

- 법령정보센터가 응답하지 않아(TIMEOUT·RATE_LIMITED) 기준을 채우지 못한 실행은 '판정 보류(unreachable)'로 기록한다. 통과로도 실패로도 세지 않는다.
- 응답을 받은 조회 가운데 하나라도 틀리면 실패로 기록한다.
- 판정 보류 항목은 작업 요약과 경고 주석에 드러난다(`scripts/live_summary.py`). 감사표는 직전에 실제로 응답을 받아 통과한 기록(`last_pass`, 커밋·시각 포함)이 있을 때만 그 기록을 근거로 쓴다. 그런 기록이 없으면 '미확인'이다.

## 8. 운영자 조치

| 증상 | 확인 | 조치 |
|---|---|---|
| 미확인 인용이 많고 `recovery_status`가 `RETRY_EXHAUSTED` | 출처 응답 지연 | 출처가 회복된 뒤 같은 문서를 다시 검증한다 |
| "출처 접근 권한을 확인해야 합니다" | HTTP 401·403 | 인증키(`LV_LAW_GO_KR_OC`)와 등록 정보(IP·도메인)를 확인한다 |
| `unavailable_sources`에 법령정보센터 | 인증키 없음 또는 네트워크 차단 | 환경변수와 네트워크 정책을 확인한다 |
| 실연동 CI의 판정 보류 경고 | 러너에서 출처 무응답 | 코드 결함이 아니다. 출처가 회복된 뒤 `[live-integration]`으로 다시 실행한다 |
