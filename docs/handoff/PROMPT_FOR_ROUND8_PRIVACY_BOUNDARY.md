## 1. 작업 묶음

### R8-A. TK-51 구조화(JSON) 요청의 전송 전 검사 (P1, 첫째)
원인(TK-51): `privacy.py::_walk_fields`가 사전 키 중 `{"성명","대표자","대표이사","주민등록번호","연락처","이메일"}`만 `키: 값`으로 문맥을 되살리고, 나머지 키·형제 필드·배열 이웃은 값만 `detect()`에 넘긴다. 또 `router.py`가 `SYSTEM_BASE`를 앞에 붙인 뒤 검사해 system의 JSON 구조가 깨진다.
1. **라벨 정의를 한 곳에서** 가져온다 — `detector.py`의 라벨 어휘(`PARTY_AND_TITLE_LABELS` 등)를 전송 전 검사도 쓰게 하고, `_walk_fields`의 하드코딩 키 목록을 그 출처로 대체한다. 키 몇 개를 더하는 것으로 끝내지 않는다.
2. 사전은 **모든 문자열 값에 대해 `키: 값`** 문맥으로 검사하고, 같은 사전의 형제 값들을 **원래 순서로 이어 붙인 문맥**(예: 역할 값 다음 이름 값)도 검사한다. 배열은 이웃 원소를 이어 붙인 문맥도 검사한다. JSON 문자열(문자열 안의 JSON)도 같은 규칙으로 푼다.
3. system·schema는 **조립 전 원본**을 검사하거나(검사 결과를 조립 뒤에도 보존) 조립 문자열에서 원래 JSON 구간을 복원해 검사한다.
4. **fail-closed:** 판정이 서지 않거나 검사 중 예외가 나면 **원문을 보내지 않는다**. 실제 `LLMRouter.run` + 가짜 공급자 시험으로 확인한다.
5. **대조(과차단 방지):** 사람이 아닌 당사자 값(`대한민국`, `○○시`, `주식회사 ○○`, 기관명 등)과 사건 서술 값은 차단하지 않는다. 등록된 고정 system/schema의 정적 오탐 인정 규칙(`is_registered_system_prompt`·`is_registered_schema`)은 유지한다.
- 시험(3종 세트): 평탄·중첩·배열·문자열 JSON × user/system/schema, 형제 필드 쌍(역할/이름), 배열 쌍, 예외 시 미전송, 비인명 당사자 값 대조, 이전 성공(평문 R6-01·R7-12) 대조. 입력은 구현 측이 새로 짓는다(보호 시험·평가 측 입력 재사용 금지).
- 수용: TK-51 보호 시험 4건 XPASS, R6-01 라우터·R7-12 유지, 평가 측 비공개 구조화 도달 **0/324·0/216**, 평문 도달 0 유지.
