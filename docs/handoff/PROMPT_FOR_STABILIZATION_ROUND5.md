### U3. TK-28 전송 전 검사의 system/schema 예외 — 종류 목록이 아니라 출처 확인
**증거(평가 측 확인, e6b58fd):** 4차 S6은 허용 종류 목록(전화·주민번호·이메일·사업자번호·계좌·주소·의료·차량)에 한해 system·schema에서도 차단한다. 그러나 **이름·생년월일·운전면허번호·군번·법인명은 system에서 여전히 `STATIC_PROMPT_FALSE_POSITIVE`로 `PASSED`** 된다. 현재 모든 system 프롬프트는 고정 문자열이라 사용자 값이 흘러드는 경로는 확인되지 않았다(Astra도 유출을 단정하지 않았다). 다만 "system은 언제나 고정 문자열"이라는 전제에 기대며, 문서 값을 system에 넣는 변경이 생기면 검사가 조용히 꺼진다.
**개선:** 예외는 **출처가 확인된 고정 텍스트에만** 준다. 코드가 실제로 쓰는 system·schema 상수를 한 곳에 등록(상수 id·내용 해시)하고, 요청의 system·schema가 등록된 상수와 **정확히 같을 때만** 그 안의 탐지를 정적 오탐으로 본다. 등록되지 않은 system·schema(동적 값이 섞인 것 포함)에서의 탐지는 **종류와 무관하게** 차단한다. 종류 목록 방식은 없앤다.
**수용:** 모든 PII 종류(PERSON·DOB·DRIVER_LICENSE·MILITARY_ID·COMPANY·PHONE·EMAIL·ADDRESS·ACCOUNT…)를 system에 넣은 요청이 `BLOCKED`, **코드의 모든 실제 system·schema 상수가 `PASSED`**(정상 안내문 오탐 대조를 상수 전체에 대해 자동으로 도는 시험), 동적 값을 섞은 변형(상수 + 문서 값)이 `BLOCKED`. 실제 모델 호출은 하지 않는다(요청 조립만 검사).

### U4. TK-22 입력 계층 문단 복원을 PDF·docx에도 적용하고 소비자별 땜질을 정리 ← 가장 큰 작업
**증거(평가 측 측정):** 4차 S2는 `reconstruct_paragraphs_from_text`를 `TextParser`에만 연결했고 PDF용 `reconstruct_page_blocks`는 호출자가 없다. 개발 서면 6종을 reportlab 내장 CID 글꼴 PDF로 줄 폭만 바꿔 만든 24개 조합 **모두에서 실패 항목이 4차 전후 같다**(`test_layout_invariance_pdf.py` KNOWN_OPEN 10건: 인젝션 표지 INJ-1이 줄 폭 40·48자에서, 인용 CIT-6이 폭 40자에서 등). 비공개 서면 3도 PDF는 4차 전후 17·17·16·15(원본·64·48·40자). 서면9에서 Drive 대조가 빠진 원인(규정 인용 문장이 PDF 줄 단위 블록 3토막으로 쪼개져 주장 70개 중 1개만 연결)은 **PDF 입력이라 해결되지 않았다.** 소비자별 줄 결합(`citation_extractor._join_hard_wrapped_citations`·`legal_rules`·`temporal_review`의 길이 보존 언래핑)도 그대로 남아 있다.
**개선:**
1. `PdfParser`(와 docx·hwp 파서)가 블록을 만들 때 같은 복원 규칙을 적용한다. 블록의 `text`는 문단, 물리적 줄(`lines`)과 좌표(`bbox`)·쪽·읽기 순서는 속성으로 **보존**한다. 줄 단위가 의미인 영역(당사자 표시란·표·번호 목록·서명란·머리표)은 줄을 유지한다. 줄바꿈 자리의 한글 낱말 사이 공백은 유지한다.
2. **병합하기 전의 줄 단위 정보에 의존하는 기능은 깨지면 안 된다**: 숨은 텍스트·레이어 불일치·렌더 모드 탐지(`pdf_parser`의 forensic 경로), finding의 `span`/`bbox`/`page` 근거 표시, OCR 입력, 표 추출. 복원은 이 탐지가 끝난 뒤 또는 원본 줄을 보존한 채로 한다. 문단 블록에서 원래 줄·좌표로 돌아가는 대응을 속성으로 둔다.
3. 복원이 한 곳에서 되면 소비자별 언래핑 3곳을 **지운다**(남기면 이유와 함께 요청서에 적는다). 지운 뒤에도 기존 시험이 모두 통과해야 한다.
**수용:** `tests/acceptance/test_layout_invariance_pdf.py`의 `KNOWN_OPEN` 10건 해소(풀린 목록을 `requests/`에 알림. 평가 측이 표시를 지운다), 텍스트 입력 시험·서면6~9·변형 1·2의 primary·text 점수 유지, 당사자 표시란 개인정보 시험 유지. **구현 측 새 시험(필수):** 같은 새 서면을 **txt·PDF(reportlab CID 글꼴)·docx(python-docx)** 세 형식으로 만들어 줄 폭 36·44·56·64자와 CRLF·빈 줄 변형까지 **결과가 모두 같음**을 보이는 형식 간 불변 시험, 숨은 텍스트 PDF·표가 있는 PDF·쪽을 넘는 문장이 있는 PDF 각 1건(복원 뒤에도 탐지·좌표·표가 유지됨). 사용자 온라인 재실행에서 서면9 `claim_coverage.linked_claims`가 늘고 제22조 모순이 잡히는지는 사용자가 확인한다(실제 Google Docs PDF 원본이 필요).

### U5. TK-26 민법 군집을 큐레이션 목록이 아니라 체계로 닫는다
**증거:** 4차 S1은 헌법 제10~39조(제2장 전체)·제119조, 형법 제20~24조를 **체계로 닫았다**(좋다). 그러나 민법 항목은 12개 조문(2·103·104·137·201·202·203·390·734·741·746·750)을 고른 목록이다. 이 밖의 면책·소멸·효력 부정 법리 — 상계(제492조)·변제(제460조)·면제(제506조)·해제(제544조)·표현대리(제125조) — 로 쓴 **같은 구조의 주장 5건을 모두 놓친다**(`test_generalization_guards.py::test_unseen_doctrine_overclaim[setoff·performance·release·rescission·apparent-agency]`). 목록의 203·734·741은 평가 측 시험·티켓에 나온 번호다(티켓이 예시로 적은 것이므로 위반은 아니나, 목록이 시험에 나온 번호의 부분집합이면 일반화로 인정하지 않는다).
**개선:** 민법 항목을 **편·장·절 범위**로 정의한다. 설정에 `{"from": 460, "to": 507, "basis": "<편·장·절 제목>", "source_url": "<국가법령정보센터 조문 주소>"}` 형식으로 근거를 적고 코드가 범위를 읽는다. 평가 측이 예시로 드는 후보 범위(**원문 대조 전이므로 따르지 말고 구현 측이 국가법령정보센터 원문의 편·장·절 체계로 직접 확인해 맞는 범위만 쓴다. 틀리면 `requests/`로 알린다**): 채권의 소멸(변제~혼동, 제507조 혼동이 끝인 것은 평가 측이 확인), 법률행위의 무효·취소(제137~146조 전후), 대리(제114~136조 전후), 계약의 해제·해지(제543~553조 전후), 소멸시효(제162~184조 — TK-24와 연계되므로 포함 여부는 `requests/`에 적고 판정 구조는 바꾸지 않는다). 시험에 나온 몇 개만 고른 부분집합은 승인하지 않는다.
**수용:** 5건 XPASS(**이 입력은 개발 자료가 되므로 평가 측이 다음 측정에서 새 입력으로 다시 잰다**), 대조군(요건을 소명한 서면·판례를 정확히 인용한 서면) 유지, 새 `rule_id` 0, 고정 시험 오탐 0. 구현 측 새 시험: 평가 측 입력과 다른 법리·다른 문장 양성 5건, 대조군 3건. `check_hardcoding_diff.py`의 강한 신호가 나오면 범위 정의의 근거(원문 편·장·절)를 요청서에 적는다.

### U6. TK-28 3절 시점 군 사전 보완(입원 등)
**증거:** `입원 당시 혈압 190/110` ↔ `퇴원 시 혈압 125/80`이 `CONTRADICTS`로 나온다. `config/timing_groups.json`에 `입원`이 없어 한쪽만 시점이 명시된 쌍으로 취급되기 때문이다(2차 지시서의 "한쪽만 명시되면 배제하지 않는다" 규칙이 기존 양성 시험 `p3`을 지키기 위해 있다).
**개선:** 시점 군 사전을 병원 경과의 **닫힌 체계**(내원·입원·수술·회복·퇴원·전원 등 진료 경과 단계 전체)로 채운다. **판정 규칙은 바꾸지 않는다**(시점 정렬을 확정하지 못한 쌍의 표시 수준 — CONTRADICTS 대신 "시점 정렬 불명" 참고 의견 — 은 사용자 결정 사안이라 `requests/`에 제안만 올린다).
**수용:** 입원↔퇴원이 CONTRADICTS가 아니고, 내원↔초진(같은 군)·`p1·p2·p3`·서면5·TK-19 대조군이 유지된다.

## 2. 일반화·안정화 설계 원칙 (4차와 같음, 요약)
1. 표현이 아니라 **역할·구조**를 잡는다. 어휘는 의도·법리 **군집별로, 설정 한 곳에**, **법·체계로 닫힌 집합**으로.
2. **배치 불변**: 줄바꿈·같은 줄·블록 경계·띄어쓰기·CRLF·빈 줄 **그리고 입력 형식(txt·PDF·docx)** 이 달라도 결과가 같아야 한다.
3. **열거하지 말고 체계를 따른다.** 목록의 모든 항목에 근거(편·장·절, 조문 범위, 원문 주소)를 붙인다.
4. **불확실은 불확실로 표시한다**(R3). 읽지 못한 것·부분 일치·후보가 여럿인 것은 확정도를 올리지 않는다.
5. **보호 장치는 허용 목록이 아니라 출처 확인으로.** 종류·낱말 목록으로 막으면 새 종류에서 같은 틈이 열린다.

## 3. 어길 수 없는 규칙 (4차 0절 B 재확인)
시험 입력·정답지·티켓의 낱말·문장·조문 번호·식별자·값을 키·목록·정규식·메시지에 옮기지 않는다. 특정 서면·시험 환경을 알아보는 분기, 채점 항목에 맞춘 출력, 시험 기대값을 바꿔 통과시키기, skip, `xfail` 임의 추가·삭제, 보호 경로 수정, 기준선 수정, 불확실을 확정으로 바꾸기, 소비자별 땜질, 환경을 숨긴 점수 보고, 출처 미확인 법령·판례 정보를 쓰지 않는다. **새 `rule_id`·새 설정 파일·새 탐지 유형은 0개여야 한다**(이번 라운드의 설정 변경은 기존 `legal_defense_groups.json`·`timing_groups.json`의 범위·사전 보완에 한한다). 하나라도 있으면 그 커밋은 되돌린다.
