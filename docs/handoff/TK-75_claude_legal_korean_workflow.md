## 2. 실제 활용 범위
- Claude for Legal은 독립 API 모델이 아니라 공개 법무 플러그인/스킬/워크플로우 참조다. 현재 Claude·OpenAI·Luna 등 운영 모델/프로바이더 설정을 유지한다. Astra for Law는 이번 범위에서 제외한다.
- 1차 범위는 기존 한국법 참고자료 검토 요청(문서 단위/주장 단위)에 쟁점→요건→자료 속 사실/근거→반대 해석→적용 한계·불확실성을 검토하도록 반영하는 것이다. 최종 의견은 기존 스키마의 source_id/claim_quote/source_quote/relationship/explanation으로 반환하며 내부 점검 과정을 새 출력 필드로 노출하지 않는다.
- 공식 자료의 검증 상태/증거 우선순위, 인용 검증, 기존 grounded_observations, TK-70 승격 조건, TK-74 표 격리를 그대로 사용한다. 한국법 관할·기준일이 자료에서 확인되지 않으면 임의로 채우지 않는다. 미국법 기본 예시를 한국 사건의 판단 기준으로 가져오지 않는다.
- 공식 참조: https://github.com/anthropics/knowledge-work-plugins/tree/95bdacc803aa5cfdb10f35e5b9fb2d4b11100133/legal (고정 참조 SHA 95bdacc803aa5cfdb10f35e5b9fb2d4b11100133, Apache-2.0). 채택/한국법 조정 범위와 출처를 설계 메모에 기록하고 원문을 재사용하면 라이선스·고지 의무를 준수한다.
- 공용 프롬프트라는 특성상 실제 선택 provider와 장애 시 fallback을 확인한다. 법률 워크플로우는 수용된 범위의 Claude 경로에 적용하고 다른 provider의 기존 계약은 유지한다. 문서/주장 양쪽 실제 경로 및 fallback을 시험한다.
- 추가 MCP 연결·플러그인 전체 자동 설치·별도 유료 서비스·모델 추가·신규 호출 단계는 이번 최소 범위에 포함하지 않는다. 기존 호출 안에서 워크플로우를 반영한다.

## 3. 보안·호환·비용
- 기존 API/응답 스키마·F3 요청 whitelist·PII 마스킹/inspect_request/LLMRouter.run·출력 검사·주입 격리·LOCAL_ONLY/QUICK 정책을 유지한다. system 지침과 비신뢰 자료를 구분한다.
- 문서/주장당 호출 상한·fallback/retry·토큰/시간/비용 예산을 늘리지 않는다. 단순 호출 수뿐 아니라 입력/출력 토큰·실측 비용·지연·커버리지를 전후 비교한다. 비용/시간 악화나 검토 누락을 숨기지 않는다.
- 되돌릴 수 있는 설정과 기존 동작 경로를 둔다. 구현/평가 중 기본 OFF, 수용된 범위는 다음 릴리스 설정에서 활성화하며 OFF 시 기존 동작을 재현한다. 단순 비활성 코드 추가를 활용 완료로 보고하지 않는다.
- 실행 기록의 기존 prompt_version 등으로 워크플로우 적용 여부와 출처 버전을 추적한다. 원문/PII나 평가 입력을 로그에 추가하지 않는다.
- 사건 값 특례·보호 시험 수정·기준선 완화·버전 변경 금지. 제품 코드는 구현 세션만 수정한다. 평가/구현의 대화·환경·비공개 자료 분리를 유지한다.

1. 설계 메모를 제품 코드보다 먼저 제출한다. 한국법 조정·양쪽 요청 경로·provider/fallback·설정/되돌림·예산·시험 계획을 쓴다. 평가 측은 수용 판정 전 품질 평가 입력·채점표·반복 횟수·비교 조건을 고정하며 후보 결과를 본 뒤 바꾸지 않는다.

3. 평가 측이 동일 입력/모델/자료/파라미터/예산에서 OFF 기준과 ON 후보를 비교한다. 실제 모델의 한국법 검토 품질(쟁점·요건·근거 연결·반대 해석·불확실성)에 확인 가능한 개선이 있고, 새 근거 없는 단정/허위 인용·오탐은 증가하지 않아야 한다. 온라인 입력·루브릭·반복 횟수는 제출 전에 별도 확정한다. 가짜 provider 시험이나 오프라인 고정 점수만으로 AI 품질 향상을 판정하지 않는다.
4. 같은 비교에서 기존 호출/예산 상한 유지·검토 커버리지 감소 없음, 토큰·실측 비용·지연의 전후 원본을 제출한다. 실제 비용이 늘거나 예산 경계에서 누락이 늘면 자동 수용하지 않고 보완한다. 온라인 검증 환경이 준비되지 않으면 품질 평가는 대기로 남긴다.
