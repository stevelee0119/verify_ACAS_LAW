# TK-17 개인정보: 법인 대표이사의 띄어쓴 성명, 사업자등록번호

- 근거 서면: 서면8(2026가합48192 답변서). 구현 에이전트가 보지 못한 상태의 첫 점수에서 발견

## 증상·증거(오프라인 PDF·텍스트 모두, 서면8 PII-1·PII-7)
정답지는 피고(법인)의 인적사항 8개 항목(대표이사 성명·생년월일·주소·연락처·이메일·사업자등록번호·법인 계좌·대표자 운전면허)을 모두 마스킹하라고 한다. 실제 마스킹 결과(서면 머리):
```
피    고 주식회사 [COMPANY_001]
[ADDRESS_001]
대표이사 정 해 승 ([DOB_001])               ← 성명 미마스킹
연락처: [PHONE_001], 이메일: [EMAIL_001]
사업자등록번호: 129-81-94820, 법인계좌: 기업은행 [ACCOUNT_001]   ← 사업자등록번호 미마스킹
대표자 운전면허번호: [DLICENSE_001]
소송대리인 법무법인 화인
담당변호사 [PERSON_001]                      ← 변호사 성명만 마스킹
```
- **대표이사의 성명이 남고 변호사의 성명이 마스킹된다.** 성명 탐지가 `담당변호사 강 민 호`(라벨 있음)는 잡고 `대표이사 정 해 승`(같은 띄어쓴 형식)은 놓친다. 사용자 온라인 보고서도 PERSON 1건뿐이다.
- 사업자등록번호 `129-81-94820`(3-2-5자리, 라벨 `사업자등록번호`)가 어떤 종류로도 탐지되지 않는다. 사용자 온라인 보고서의 종류 목록(`ACCOUNT, ADDRESS, COMPANY, DOB, DRIVER_LICENSE, EMAIL, PERSON, PHONE`)에 해당 종류가 없다.

## 수용 기준
- 서면8 PII-1·PII-7 통과(pdf·text): `python scripts/probe_document.py run --spec tests/fixtures/probes/case8_delay_penalty.json [--text]`.
- 성명: 직책·지위 라벨(대표이사·대표자·이사·원장·소장 등 법인·기관 대표 지칭)과 음절 사이를 띄운 표기(`정 해 승`)를 일반 규칙으로 처리한다. 서면8의 낱말(`정해승`, `대표이사`만 특정)을 코드에 고정하지 않는다. 양성 3건(라벨·띄어쓰기·성씨가 다르게), 대조군 3건(`대표이사 선임 결의`, `이사회` 같은 일반 명사구, 법령 조문)을 둔다.
- 사업자등록번호: `NNN-NN-NNNNN` 형식 + 라벨(`사업자등록번호`·`사업자번호`) 문맥으로 새 종류를 만든다. 계좌번호·전화번호와 섞이지 않게 대조군(전화 `031-928-3741`, 계좌 `110-345-678901`, 날짜)을 둔다.
- 변호사 성명 마스킹은 현행 유지(이번 결정은 주소에 한정).

## 사용자 결정(2026-10-02) — 사업자등록번호는 **마스킹 원칙**
요청 08 선택지 1을 사용자가 선택했다. 현재 코드(마스킹)가 결정과 같으므로 제품 코드는 바꾸지 않는다. 구 시험 `tests/test_procurement_claim_efficacy.py::test_sec01_identifier_preservation`의 기대를 평가 측이 \"사업자등록번호는 마스킹, 계약번호·사건번호·법인등록번호는 보존\"으로 갱신했다. 이로써 전체 시험의 사업자번호 정책 실패 1건이 해소된다.
