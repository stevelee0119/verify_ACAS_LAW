# TK-09 설계(명세만): 모델 의견을 판정에 쓰는 구조
- 유형: 설계 · 기준 커밋: 4ad64a7 · 작성: evaluator 2026-09-30 · **구현 전에 사용자 승인 필요**

## 문제(서면6·7 측정에서 같은 모양)
- 정규식·규칙 경로(`rules.json`, `patterns.py`, `exhibit_facts.py`)는 서면마다 새 문구로 들어오는 결함을 일반화하지 못한다(TK-03·05·08). 처음 보는 서면의 첫 점수가 서면6 PDF 4/19(텍스트 9/18), 서면7 PDF 10/24(텍스트 16/24)로, 서면이 바뀔 때마다 새 문구를 추가하는 구조다.
- 온라인 실행에서 모델 3개는 **이미 같은 모순을 찾아냈다**: 서면7의 `2025. 3. 1. 개정 규정을 2024. 2. 20. 처분에 적용` 모순(anthropic, `MODEL_FACT_REMARK`), Drive 훈령 제15조 제3항과의 정면 모순(`rag.observations[0].relationship = CONTRADICTS`, 인용문 검증 통과). 그러나 앞의 것은 `UNVERIFIED` 참고 의견으로만 남고, 뒤의 것은 `advisory`로 finding 목록에 오르지 않았다. 사무관리·정당행위 주장의 타당성은 모델에 묻지도 않았다(TK-05).

## 요구(명세)
1. 모델은 **후보를 제안**하고 결정적 검증기가 **받아들이거나 버린다**. 후보 형식: 주장 인용문(원문 그대로), 결함 유형, 근거(조문·자료 인용문).
2. 검증기: 인용문이 원문에 실제로 있는가(이미 `grounded_observations`에 있음), 근거 조문·자료 인용문이 공식 원문 또는 Drive 원문에 실제로 있는가, 날짜 모순은 서면 내부 날짜로 재계산되는가(`MODEL_FACT_REMARK`의 "재계산 대상" 경로를 완결).
3. 통과한 후보는 finding(SUSPICIOUS, 사람 확인 대상)으로 **목록에 오른다.** 통과 못한 것은 `rejected`로 남기고 이유를 적는다. 모델이 "틀렸다"고 말한 것만으로 결론을 바꾸지 않는다.
4. 모델 의견 일치·불일치는 판정에 쓰지 않고 표시한다(현 정책 유지).

## 수용 기준(온라인 측정, 사용자가 키를 가진 환경)
- 사용자가 새 서면과 함께 주는 온라인 보고서 JSON을 `scripts/score_report.py`(평가 작성)로 채점해 첫 점수를 기록한다. 서면7 보고서 기준 4ad64a7의 온라인 첫 점수가 기준이다.
- 오프라인 측정은 모델 경로를 재지 못한다(`LV_ALLOW_NETWORK=0`). 모델 호출 결과를 녹화해 재생하는 방식은 **연동·검증 논리의 회귀**만 확인할 수 있고 모델 판단의 품질은 확인하지 못한다.
