# TK-10 증거 계층: 로컬 미러 자동 보강이 없는 값을 채우고 조문을 뭉갠다
- 유형: 증거 계층(데이터 정확성) · 기준 커밋: 4ad64a7(`feat(mirror)` 커밋) · 작성: evaluator 2026-09-30

## 증상·증거
`packages/source_adapters/local_mirror.py`는 `config/legal_rules/rules.json`의 `sources`를 기본 오프라인 미러로 자동 등록한다. 평가 측이 미러를 읽어 확인한 것:
1. **시행일을 지어낸다.** 등록된 34건 모두 `effective_from: "1980-01-01"`, `effective_to: null`, `paragraph: "1"`이다. `rules.json`에는 시행일이 없다. `source_review.py`는 이 값을 "사건 특정 기준일 당시 시행 법령(시행일: …)" 문구와 `temporal_review.py`의 버전 범위 판단에 쓴다. 1980년 이후 제·개정된 조문도 1980년부터 시행된 것으로 보게 되어 행위시법·처분시법 검토가 조용히 통과할 수 있다. 재현: `LV_ALLOW_NETWORK=0`으로 "형법 제20조 … 군인사법 제59조"를 인용한 한 줄 텍스트를 파이프라인에 넣으면 출력(engine_data)에 `"effective_from": "1980-01-01"`이 8곳 나온다.
2. **가지조문·항이 기본 조문으로 뭉개진다.** 정규식 `제\s*(\d+)\s*조`가 `조의2`·`제2항`을 버린다. `군인사법 제59조의2`(징계시효)가 **군인사법 제59조**로, `민사소송법 제202조의2`가 **제202조**로, `군인사법 제51조의2`가 제51조로, `헌법 제13조 제2항`·`헌법 제37조 제2항`·`민법 제398조 제2항`이 각각 제13조·제37조·제398조(항 1)로 등록된다. 실제 제59조·제202조·제51조를 인용한 서면이 다른 조문의 본문과 대조된다.
3. **본문이 조문 원문이 아닐 수 있다.** `민사소송법 제202조의2`의 `url`은 판례 페이지(`precInfoP.do?precSeq=618533`)이고, `rules.json` 해당 항목의 `version`은 "판결요지 … 확인"이다. `text`가 조문이 아닌 판결요지·발췌인 항목이 섞여 있다.
4. **오프라인 동작이 바뀌었고 점수가 올랐다.** 이전에는 `config/legal_mirror`에 README만 있어 미러가 비활성이었다(`available == False`). 지금은 항상 활성이다. 같은 채점기·같은 환경(오프라인, OCR 5.3.4)으로 커밋별로 재측정한 결과(평가 측, `scripts/scorecard.py`):

## 수용 기준
- 미러에 시행일·항을 **알 수 없으면 `null`**로 둔다(지어낸 값 금지). 시행일이 없는 조문은 행위시법·처분시법 검토에서 "시행일 확인 불가"로 다루어 통과시키지 않는다.
- `조의N`·`제N항`을 보존한다(또는 등록하지 않는다). `군인사법 제59조`를 인용하면 `제59조의2` 본문과 대조되지 않는다. 시험: 가지조문 3종, 항 지정 3종이 기본 조문과 섞이지 않는다.
- 본문이 조문 원문인 항목과 판결요지·발췌인 항목을 구분한다(`detail_link`도 조문 링크만). 구분이 안 되면 등록하지 않는다.
- 미러 출처를 증거 등급·보고서에 "사용자 자료(공식 DB 아님)"로 표시한다(Drive 자료와 같은 원칙, `authority: USER_REFERENCE_NOT_OFFICIAL`).
- 수정 뒤 점수가 위 표와 달라지면(자료가 정확해져 TC-06·HO-06이 내려갈 수 있다) 그 사유를 커밋 메시지에 적는다. 기준선(`docs/scorecards/baseline.json`) 조정은 사용자 승인 사항이다(평가 에이전트가 요청).
