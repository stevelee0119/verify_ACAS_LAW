# TK-71 보완 설계 — 단건 보안 검사와 동기화 이어 읽기

- 근거: PR #57 재판정 6080721034, 사용자 통합 지시 (7). 같은 일괄 검사 접근을 폐기한다.
- 보안: `packages/adversarial_engine/`의 TK-71 변경을 Steve의 단건 검사 코드로 복원한다. 사전 필터와 행 연결을 제거하고 각 행을 기존 `AdversarialScanner.scan`에 그대로 넣는다. 숨김·흰 글자·수식·메타데이터 검사를 유지하며 미검사 행은 검색하지 않는다.
- 이어 읽기: XLSX/CSV를 매 동기화의 기존 30초 격리 추출 안에서 재개한다. 내부 시간 예산에 닿기 전에 검사 완료 범위(시트·실제 행), 누적 처리 수·격리 근거와 원본 SHA/파서 버전을 반환한다. 완료 전 사유는 `REFERENCE_PARTIALLY_READ`다. 새 결과는 그 배치의 검사 완료 행만 담고 SQLite 트랜잭션에서 같은 revision의 이전 배치에 추가한다. 최종 완료 후에만 전체 적재로 표시한다.
- 캐시/권한: 이어 읽기 상태는 로컬 SQLite files payload에 저장한다. 같은 원본 hash·Drive revision·파서 버전만 이어 받는다. 매번 최신 목록·권한·다운로드 후 revision/hash 검사를 통과해야 하며 실패한 실행에서는 이전 행을 적격 코퍼스에 넣지 않는다. 일반 실패 캐시는 종전처럼 재시도하지 않고, 진행되는 표만 다음 동기화에서 재개한다. 중간 프로세스 실패는 기존 체크포인트를 보존한다. 제외 상한 초과 시 이전 배치까지 원자적으로 제거하고 파일 전체 격리로 종료한다.
- 시간/자원: 행 검사 앞뒤에서 시간을 확인하고 직전 처리량으로 다음 행을 시작할 여유가 있는지 보수적으로 판단한다. 한 행이 예산을 넘는 경우 실패 사유를 보존한다. 다운로드·행/셀·ZIP·출력·DB 상한은 유지한다. 프로그램 버전과 모델 요청/응답 허용 키는 변경하지 않는다.
- 상태: 표가 있어도 기존 `INCOMPLETE_COVERAGE`·`NOT_RELEVANT` 조기 반환을 유지하고 사건정보 대조 기록만 덧붙인다. 사용자 지시 D.3의 지정 범위로 `review.py` 조건만 고친다(TK-68은 이 PR 병합 뒤 시작).
- 시험: 단서 낱말이 섞인 합성 법률 문장 4,000행·400만 자 XLSX를 여러 격리 배치로 끝까지 적재하고 마지막 행 검색·누적 수·범위·30초/256MB 제한을 확인한다. 보안은 모든 INSTRUCTION_PATTERNS의 합성 적중 예와 기존 적대 시험 문자열에서 단건 행 경로와 비교한다. 권한 철회·판본 변경·배치 실패·격리 상한 누적·안내 시트 제외·조기 반환과 머리글/행 분할 2,000회 시간 시험을 보강한다. 실제 Drive 자료는 저장소에 넣지 않는다.
