# 8E 설계 메모 — 사람 신호 우선, 값 검사 범위 한정

## 방법

1. 키를 정규화하되, 기존 사람 라벨과 사람 전용 이름 필드 신호를 접두 판정보다 먼저 찾는다. 신호가 있으면 키 앞의 다른 낱말은 이를 지우지 않는다. 사람 신호가 없으면 현재 비인명 키 판정을 유지한다. 신호 없는 역할 명사 키를 새로 추정하거나 값만 보고 사람 키로 승격하지 않는다. 그 입력 유형은 평가 측 strict xfail 24건으로 계속 알려진 미해결 상태에 둔다.
2. 값의 비인명 여부를 접두·접미 낱말 목록으로 판정하지 않는다. fail-closed는 명시적인 사람 이름 필드 형태에 한정한다. 역할 라벨 키는 원문을 계속 검사하고, 간결한 이름 구조가 확인될 때에만 라벨 문맥을 더한다. 다중 토큰 기관·행정·직무 표현에는 이름 문맥을 만들지 않는다. 이는 이름 필드가 아닌 역할·분류 라벨에서 강제 차단 범위를 줄이는 구조 규칙이다.
3. 명시적 이름 필드 아래의 비어 있지 않은 불확실 값은 fail-closed로 유지한다. 이 필드 트리 검사는 조립 전 원본 system과 user 양쪽에 적용한다. 사람 라벨이 앞에 다른 낱말과 결합된 경우에도 라벨 문맥은 생성하므로 단순 실명은 전송되지 않는다. 이름 필드 값 fail-closed와 역할 라벨의 문맥 검사는 별도 경로라 서로의 범위를 바꾸지 않는다.

## 이전 회신 및 시험

8D 메모 회신 1은 열린 형태 추정과 키 신호 없는 값 기반 차단을 지적했다. 8E 사용자 결정에 따라 그 추정을 넓히지 않고, 미해결 범주를 고정한다. 회신 2의 과차단 우려는 값 낱말 목록을 제거하고 fail-closed 범위를 사람 이름 필드로 한정해 반영한다. 회신 3의 영문 복합 키 우려는 새 접두 사람 라벨 회귀 시험과 기존 영문 정규식 불변 시험으로 확인한다.

새 합성 입력으로 비인명 접두+사람 라벨 아래 실명은 차단하고, 사람 라벨 아래 다중 토큰 비인명 구조는 전송하며, 8D의 불규칙 이름 값과 이름 필드 검사 예외는 계속 차단한다. 평가 측 strict xfail 24건은 실행 시 XPASS가 없는지 확인한다.
