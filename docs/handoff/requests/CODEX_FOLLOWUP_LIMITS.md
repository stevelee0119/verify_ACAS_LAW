# 다음 안정화 작업에 남긴 실제 한계

기준 제품: a1f3d1e. Codex 법리 수정에서는 개인정보 및 문단 복원 제품 파일을 변경하지 않았다. 아래는 실제 실행 또는 코드 경로로 확인한 기존 한계이며, 7D 완료나 F1 착수 승인으로 묶지 않는다.

## 1. 구조화된 개인정보 요청 검사 (우선순위 높음)

새 합성 이름 3개와 성명, 대표자, 원고, 담당자, 작성자, 이름의 6개 라벨을 user JSON, system JSON, schema 객체에 넣은 54개 요청을 검사했다. 외부 연결은 강제 차단하고 실제 LLMRouter.run에 가짜 공급자만 붙였다.

- user: 18개 중 12개가 가짜 공급자에 원래 합성 이름을 전달.
- system: 18개 모두 전달. 직접 검사에서는 성명/대표자가 차단되지만, 라우터의 고정 프롬프트 결합 뒤 JSON 문맥이 소실된다.
- schema: 18개 중 12개 전달.
- 실제 네트워크 연결 시도는 0회다. 이 결과는 실제 개인정보 유출 사고 기록이 아니다.

원인은 privacy._walk_fields가 일부 이름 키만 문맥으로 복원하고, 조립된 system 문자열의 JSON 파싱 실패 시 다른 검출 경로가 이를 보완하지 못하는 것이다. 다음 수정은 이름 라벨 정의와 구조화된 요청의 문맥 보존을 함께 다뤄야 한다. 단순히 기존 목록에 이름 몇 개를 추가하는 방식으로 완료 처리하지 않는다.

별도 이름 경계 문제도 남는다. 일부 당사자 라벨 뒤 이름과 직함 앞 이름의 마지막 음절을 조사로 확정하면서 탐지를 누락한다. 일반 명사 과마스킹 대조를 함께 유지해야 한다.

수용 조건: 같은 합성 경계에서 가짜 공급자 도달 0, 원래 차단 대조 유지, 정상 법률 명사 대조 보존, 중첩 객체/배열/문자열 JSON/프롬프트 조립 전후/system/schema/metadata 각각 검사. 실패 시 원문 전송 없이 종료하는지 실제 router에서 확인한다.

## 2. 문단 복원

a1f3d1e는 오른쪽 경계와 문자 단위 줄바꿈 추정을 문단별로 계산하도록 개선했다. 이를 되돌리지 않는다. 그러나 괄호 뒤 짧은 단어, 한 음절 독립어, 조사처럼 보이는 다음 줄 첫 음절을 무조건 붙이는 규칙은 여전히 모호한 입력을 오판한다. TK-41 원래 assertion은 보존한다.

pdf_parser에서 텍스트를 strip()한 뒤에는 원래 행끝/행시작 공백의 증거가 사라진다. 다음 작업은 원본 글리프와 경계 정보를 별도 메타데이터로 보존하고, 확실한 단어 내부 분절과 모호한 경계를 구별하는 설계부터 시작한다. 불확실한 경우의 표현 및 검색용 정규화가 원문 표시를 바꾸지 않도록 계약을 정해야 한다.

수용 조건: 공백 보존과 단어 복원 양쪽, 다른 문단 추가/폭 변경 불변성, 실제 PDF 입력, 기존 법원명과 조사 결합 대조. 테스트 기대값 수정이나 특정 단어장 증대로 해결로 판정하지 않는다.

## 3. 이번 법리 수정 뒤에도 남는 한계

별도 합성 33개 중 요건 부정 경고 유지가 3/8에서 7/8로 늘고 정상 대조 17/17은 유지됐다. 이 결과는 개발 피드백을 거친 회귀 검증이다. 인용문 내부의 문장 종결과 발화자 정보가 분리되는 경우 등을 포함한 인용/재반박 대조 5개 중 기존 4개 오탐, 뒤 서술의 불가능 표현 1개 미탐은 그대로 남았다.

새 규칙의 범위를 무제한 늘리기보다, 발화자/인용 범위와 요건 절 분석을 별도로 설계하고 처음 보는 입력으로 평가한다. 이번 결과를 법률요건 전체 충족 판정이나 봉인 시험의 성능 향상으로 확대 해석하지 않는다.
