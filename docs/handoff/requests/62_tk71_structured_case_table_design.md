# TK-71 설계 메모 — 표 형식 표준판례 참고자료

- 작성: 구현 에이전트 Codex, 2026-10-09
- 기준: `Steve_ACASiaLAW` 최신 `3daf7b6`
- 브랜치: `codex/tk71-structured-case-table`
- 상태: 설계 메모 전용. TK-70·TK-68이 `Steve_ACASiaLAW`에 병합되고 평가 측 회신이 올 때까지 제품 코드와 보호 시험을 바꾸지 않는다.

## 문제와 경계

현재 XLSX 경로는 시트·행을 보존하지 않은 평문으로 만들고, 비 PDF 크기 상한과 포괄 예외가 원인 코드를 가린다. `ReferenceLibrary`는 파일 단위 발췌 제한과 문서 단위 선택에 의존하므로 행별 사건 머리, 주장별 전체 검색, 사건번호 정확 조회가 끊긴다. 이 작업은 Drive 권한·마스킹·인젝션 검사·기존 예산을 통과한 참고자료만 대상으로 하며, 표준판례 행은 후보와 편집 요지의 출처로만 쓴다. 판례 목록이나 번호 일치만으로 공식 확인·주장 지지·현재 사안 적용을 확정하지 않는다.

## 제안 방법

1. **자료 유형과 행 레코드**: 파일명이나 ID가 아니라 헤더/열 의미와 등록된 자료 유형으로 `structured_case_table`을 판별한다. 스트리밍 XLSX 리더를 사용해 헤더·개요를 제외하고 한 행씩 처리한다. 사건 기본정보와 논점 행을 분리한 parent/issue 레코드에 원본 파일 식별자·revision/hash, 시트·실제 행·셀 범위, 과목, 논점명, 원문 사건정보, 정규화 사건번호·법원·선고일·재판유형, 쟁점·사실관계·선정이유·판결요지·hyperlink를 저장한다. 빈 셀은 열을 당기지 않고 `MISSING_SUMMARY` 같은 품질 경고로 남긴다. 행정법의 사실관계 열은 쟁점으로 재분류하지 않는다. 표 안에서 재인용된 사건번호는 대상 사건과 별도 목록으로 보존한다.
2. **제한·실패·원자성**: 파일/ZIP 팽창, 셀·행 길이, 총 행·메모리·시간·DB 용량 예산을 설정값으로 검사하고, 행 처리 수를 성공·보류·오류·격리 합계로 기록한다. `REFERENCE_TEXT_LIMIT`, `REFERENCE_PARSE_TIMEOUT`, `UNSUPPORTED_REFERENCE_FORMAT`, 보안 격리 등 안정된 사유 코드를 캐시와 manifest에 그대로 남긴다. 임시 인덱스를 완성한 뒤 원자적으로 교체하며 중단 시 이전 적격 인덱스를 사용하지 않고 `PARTIAL`/`UNAVAILABLE`을 반환한다. 파서·인덱스 버전은 키에 넣어 필요한 실패 캐시만 재처리한다.
3. **주장별 검색**: 기존 SQLite/FTS5·BM25를 재사용해 parent/issue 단위 레코드와 행 위치를 검색한다. 각 적격 claim마다 사건번호는 숫자를 제거하는 일반 토큰과 분리한 경계 일치 exact lookup을 먼저 수행하고, 인용이 없으면 주장 문맥·법률 개념·요건을 질의로 사용한다. 문서 단위 결과가 비어도 주장별 검색을 시도하되 COUNT/TIME/COST 예산을 넘은 claim은 분모에 남기고 사유를 기록한다. 판결요지 발췌를 claim 요청의 우선 자료로 넣되 기존 `inspect_request`, 허용 키, 발췌 상한을 확장하지 않는다.
4. **공식 대조와 상태 분리**: 기존 `verify_case` 및 `prec`/`detc` adapter를 신규 후보의 후속 단계로만 호출한다. 문서 인용, 표 행 원문/정규화값, 공식 사건정보를 별도 보관하고 법원·선고일·사건번호의 일치/불일치/모호/미확인을 `reference_status`의 새 값으로 표현한다. `official_status`, 기존 finding, `SUPPORTED`의 의미는 바꾸지 않는다. 번호 일치는 동일성 단서일 뿐이며, 공식 원문 확보 범위와 판결요지의 주장 관계(지지·일부 지지·반대·관련성만·근거 부족·미검토)는 별도 필드로 둔다. 추천 판례와 문서에 실제 인용된 판례를 결과와 보고서에서 분리한다.

## 일반화 근거와 위험

헤더 의미·행 구조·명시적 자료 등록을 사용하므로 특정 파일명, 사건번호, 과목 행 수에 맞추지 않는다. parent 레코드와 행 위치를 모든 chunk에 함께 넣어 인접 사건 혼합을 막는다. 주요 위험은 스트리밍 라이브러리의 수식/hidden 셀 누락, 복수 사건번호 오인, 공식 검색의 모호한 결과, 판결요지와 사실관계의 의미 혼동, 대형 자료의 예산 초과다. 각 위험은 원자료 보존·품질 경고·모호 상태·미검토 사유로 보수적으로 중단하며, 기존 결정론적 finding·점수·PII·인젝션 결과를 변경하지 않는다.

## 시험 계획

보호 경로는 건드리지 않고 합성 XLSX/Drive/API 대역만 사용한다. 서로 다른 양성 3건 이상과 대조 3건 이상으로 (a) 대형 다중 시트 행 적재와 처리 합계, (b) 빈 열·행정법 열·hyperlink·복수/참조 사건번호·결측 요지·행 위치, (c) 경계 일치 exact lookup과 법원/날짜 불일치, (d) 첫 문서 선택에 없던 행의 주장별 검색 및 요지 우선 전달, (e) 번호 일치만으로 `SUPPORTED`가 되지 않음, (f) `prec`와 `detc` 공식 대조, (g) 권한/삭제/시간 초과/중단 복구·캐시 갱신을 시험한다. 새 분석 경로는 수천 회 반복 입력 시간 시험을 둔다. 기존 Drive·관련도·조각 창·TK-09·TK-65·문서 엔진 시험과 기준 203 passed를 그대로 실행한다.

구현은 TK-70·TK-68 병합 후 최신 `Steve_ACASiaLAW`를 병합 커밋으로 반영하고, 평가 측이 이 설계의 API 상태·허용 키·새 `reference_status` 값에 회신한 뒤 시작한다. 실제 Drive 파일·운영 색인·비공개 온라인 결과는 이 메모에서 검증했다고 주장하지 않는다.
