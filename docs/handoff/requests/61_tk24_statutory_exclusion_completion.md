# TK-24 구현 전달 — 법정 규정 적용 배제 주장

승인된 [설계 메모](60_tk24_statutory_exclusion_design.md)와 [PR #53 평가 회신](https://github.com/stevelee0119/verify_ACAS_LAW/pull/53#issuecomment-6076296068)의 보완을 반영한다. 최종 커밋 SHA, diff stat, 성적표 원문, pytest 요약 및 동일 SHA CI 결과는 [PR #53](https://github.com/stevelee0119/verify_ACAS_LAW/pull/53)의 본문·완료 코멘트에 기록한다.

## 구현

- `statutory_exclusion.py`에서 법정 기간·요건·면책 및 책임한도 규정이라는 닫힌 대상을 정의·형평·자연법·유추·준용·상위 규범으로 배제하는 결론을 검토한다. 조문 번호나 사건 문구로 판정하지 않는다.
- 기존 절 경계와 극성 판정을 사용한다. 인과·수단 절에서만 대상·근거를 이어 받고, 다른 주어의 적용 부정·인용·타인 주장·부정·조건절은 제외한다. 범주적 한정어 없이 무조건 적용을 부정한 결론, 당위 및 청구 형태도 포함한다.
- 인용 근거와 법정 예외의 충족 주장이 연결된 경우는 제외한다. 인용만 있거나 예외를 부정하거나 다른 종류의 기간에 관한 예외이면 자동 제외하지 않는다. 이는 법정 예외의 실체적 타당성을 확정하는 판정이 아니다.
- 새 `CLAIM.STATUTORY_RULE_EXCLUSION`은 `LEGAL_ARGUMENT_INVALID`·`SUSPICIOUS`·`MEDIUM`의 검토 후보다. 근거는 배제 결론절이며, 생략된 주어가 앞 인과절에 있으면 그 대상도 보존한다. `NO_BASIS_REMEDY`와 독립적으로 생성한다.
- 기존 `LITIGATION_REQUIREMENT_EXCLUSION`이 같은 대상의 같은 배제 결론을 이미 분류하면 기존 분류를 유지하고 중복 후보를 추가하지 않는다. 배제 대상 규정의 인용만으로는 새 후보를 억제하지 않는다.

## 시험 및 평가 인계

합성 양성은 대상·근거·결론 형태를 바꾸고, 한정어 없는 적용 부정을 포함한다. 합성 대조군은 법정 예외 정확 원용, 한정어 있는 예외 주장, 부정·인용·타인 주장·다른 주어·조건부 주장을 포함한다. 결론 발췌, 동일 문장의 기존 청구 규칙과 병존, 문서 파이프라인, 새 정규식을 포함한 반복 입력 시간도 시험한다.

LEG-2 두 strict xfail 표시는 변경하지 않는다. 해당 두 건의 strict XPASS 외 실패가 없는지 PR 증거로 인계하며, 표시는 평가 측이 정리한다. 보호 경로와 다른 구현 담당의 세 파일은 수정하지 않는다. 비공개 정상 항변, 은퇴 세트 및 수용 SHA의 `verify_all` 전체 모드 결과는 평가 측 판정에 따른다. 릴리스 전 새 봉인 세트 시험도 별도로 필요하다.
