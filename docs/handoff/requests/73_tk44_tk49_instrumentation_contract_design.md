# TK-44 / TK-49: public instrumentation and boundary contract

Base: `5deaac7452e8eba65fda46b52896ac65d3ff717e`; implementation track `codex/10h-track-a`. This design follows approved PR #63 (`e20bd6c`) and changes no product code. Stage 2 waits for the evaluator's explicit contract-ready message. Implementation uses only this public clone; document-specific measurements remain evaluator work.

1. **Collection before classification.** Reuse `PdfParser.parse`'s existing `page.chars` and grouped lines. Preserve leading/trailing whitespace before `.strip()`, original glyph indices, text-local x0/x1, font/size/upright consistency, median nonspace advance and adjacent gap, measured explicit-space width, and normalized endpoint gaps. Keep the source glyph ranges and bounded numeric summaries in line attributes; do not introduce a second extraction library, document strings, or word dictionaries. Hidden, OCR, table, rotated, overlapping, mixed/unusable geometry and unresolved PUA/disagreement paths must not manufacture evidence.
2. **Paragraph-local diagnostics.** After the existing paragraph grouping, compute right edge, repeated endpoint distribution, representative advance and spacing from that group only. Remove the page-width floor as an evidential input. Record each boundary's signal and reason, direct whitespace evidence, normalized endpoint residual, and the paragraph's `char_wrap_state`. Wrap mode and boundary are distinct: a paragraph candidate mode does not imply JOIN for every boundary. An endpoint near the right edge or missing whitespace alone proves neither word continuity nor word separation.
3. **API under evaluator confirmation.** Add keyword-only `boundary_signal="UNKNOWN"` after the existing four arguments to `join_lines`. Valid tokens are `JOIN_CONFIRMED`, `SPACE_CONFIRMED`, and `UNKNOWN`. An explicit signal decides the separator before legacy word-fragment heuristics; UNKNOWN preserves the current base behavior and legacy positional callers. Empty inputs and punctuation handling need precise contract confirmation. Do not add lexical exceptions or alter original/pinned ledger expectations. TXT, DOCX and fallback calls default to UNKNOWN.
4. **Evidence and limits.** A retained boundary space glyph supports SPACE only when visible line geometry is usable and paragraph adjacency is established. A direct, traceable continuity observation may support JOIN; neither a packed endpoint nor absence of a space glyph is enough. Initial instrumentation must expose counts and reasons without claiming a geometric distinction unavailable in the PDF. If actual document boundaries are mostly UNKNOWN, report that limitation before another heuristic attempt. Public synthetic measurements are implementation evidence, not substitutes for evaluator measurements of real inputs.
5. **Public verification plan.** Add related, synthetic-only tests outside protected paths: at least three explicit JOIN examples, three SPACE controls, and three UNKNOWN compatibility examples; same text with opposite direct boundary evidence; fonts/width/other-paragraph placement changes; malformed/rotated/overlapping evidence; and an actual generated PDF glyph-to-`parse_document` path. Verify original regression and pinned ledgers without edits. Keep stage-1 diagnostics distinguishable from any proposed classification; complexity is linear in glyphs plus boundaries. Evaluator owns contract protections, private signal distributions, real PDF/DOCX ledgers, scoring and xfail removal.
6. **Separate TK-45 increment.** After boundary acceptance and accepted TK-24 integration, submit a new design memo before legal changes. Parse requirement subject/object, clause predicate and negation attachment separately from limited conclusion, quotation, opponent assertion and rebuttal; preserve uncertain findings as requirement-confirmation requests and existing rule identifiers. Public tests will cover each structure in both directions and the real TXT pipeline. No private-source access, expected-value changes, new rule IDs or deployment changes are proposed.
