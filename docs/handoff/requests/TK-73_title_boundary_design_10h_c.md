# TK-73 title-boundary design (public synthetic inputs only)

Branch `codex/10h-track-c`; base `5deaac7452e8eba65fda46b52896ac65d3ff717e`. Product changes await evaluator precheck under TK-73 §5. No retired document, answer key, or evaluator workspace was inspected.

**Method.** Keep `split_items`' existing exhibit-span boundaries. Add a duplicate-comparison title key for line rows only, leaving original name/date/author/purpose and other checks intact. Normalize Unicode width and whitespace. Scan the original item tail once, protecting balanced brackets and quotation marks. A top-level comma/colon is a possible title boundary only when the immediately following clause has structural description evidence: a sentence-final Korean predicate, or a numeric page/line coordinate ending the clause. Noun-only subtitles remain part of the title; delimiters inside protected text never divide it. Choose the first boundary with this evidence, preserving preceding subtitle clauses. Remove the description and sentence punctuation from the comparison key only. If no supported boundary exists, retain the existing name comparison. Explicit table title cells remain complete titles, with width/space normalization only.

**Scope and generalization.** Do not broaden section headings in this change: unknown list headings remain ordinary rows, so success must come from title extraction rather than suppression. Keep TK-64 amendment 1 section-key filtering and body rows unchanged; genuine different-title duplicates without a list section, invalid dates, and numbering gaps must remain detectable. Existing `EVI.EVIDENCE_NUMBER_DUPLICATE` stays A; new rule IDs: zero. Multi-exhibit paragraphs are handled by the existing span splitter before title parsing. If a date occurs inside an explicitly separated caption, use the original tail for comparison rather than its date-truncated name, while retaining existing date extraction.

**Risks / countercontrols.** Bare punctuation cannot distinguish arbitrary noun-only location descriptions from legitimate subtitles. Such ambiguous tails retain existing comparison behavior instead of treating every shared prefix as identity. Quoted sentence titles, comma/colon subtitles, differing subtitle suffixes, date/place captions, numeric-coordinate titles with following nouns, distinct table title cells, and descriptions containing multiple clauses need controls. Unquoted titles that are themselves complete sentences or terminate in a coordinate remain structurally ambiguous; evaluator must reject the approach if its prior public acceptance requires those to be treated differently. No document-specific words, values, exception lists, or semantic title dictionaries are proposed.

**Public diagnostic / tests.** Three different-title positive pairs and three same-title/different-description pairs, with base/branch numbers and section/no-section inputs; additional punctuation/quotes/date-caption and multi-item countercontrols. Existing TK-64 and related evidence tests stay byte-for-byte unchanged. A single-pass boundary scan plus bounded regex checks on disjoint clauses avoids repeated suffix searches; benchmark thousands of repeated separators and normal items against the ticket's 0.1-second bound. Run only related tests locally, never `verify_all`. Evaluator owns retired/fixed measurements and protected tests. Diagnostic results will be appended before product approval.
