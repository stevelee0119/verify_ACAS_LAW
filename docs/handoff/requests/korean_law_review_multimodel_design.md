# OpenAI·Gemini 고도화 검토 — 설계 보충 (2026-10-10)

사용자의 추가 요청을 반영한다. 최초 설계의 모델 유지·1단계 MCP 미추가·평가 분리는 유지한다.

**판단:** OpenAI·Gemini에도 근거 확인·쟁점/요건 분석·반론 방법론을 적용할 필요가 있다. 현재 `consult_all`은 같은 요청을 모든 가용 공급자에게 전달하므로 Opus 전용 스킬 런타임보다 공급자 공통 서버 검토 프로필이 적절하다. 첫 구현의 `_KOREAN_OPINION_SYSTEM`은 세 모델에 모두 적용된다. 공급자별 별도 지침/모델 변경/자동 검색은 도입하지 않는다.

**구현 포함:** Anthropic `system`, OpenAI `messages[system]`, Gemini `systemInstruction`에 실제 지침이 전달되는지 각 HTTP 어댑터의 대역 시험을 추가한다. 동일 공개 합성 입력 3종을 세 공급자의 실제 `LLMRouter.run` 경로에서 켬/끔으로 검증한다. 역할 우선순위·기존 consult_all 호출 수·같은 공식 원문·마스킹·입출력 검사·예산/timeout은 유지한다. 모델별 추론 지연/토큰·비용은 기존 실행 기록으로 평가한다. 공급자별 독립 실행이나 추가 자기평가 호출은 없다.

**커넥터 판단:** 첫 단계 추가는 필요성을 입증할 자료가 없다. 기존 한국 공식 DB/원문 대조가 이미 있으며 이번 입력의 원문 누락은 그 결과를 전달해 해결한다. 해외 법률 커넥터를 추가해도 한국법 수록 범위·최신성·공식 원문 확인이 보장되지 않는다. 공급자마다 별도 검색을 시키면 같은 근거로 지침을 비교하는 조건이 깨지고 비용·개인정보 전송·시간 상한 검증 범위가 늘어난다. 현재 서버 어댑터는 텍스트/JSON 호출이며 Claude Code·ChatGPT·Gemini 앱에 설치한 스킬/MCP가 서버 API에 자동 적용되는 구조가 아니다.

**후속 조건:** 별도 평가에서 한국 공식 판례/법령 연혁 원문 접근 부족이 확인될 때만 공통 SourceRegistry 뒤에 읽기 전용 검색 어댑터 또는 MCP를 별도 제안한다. 국가법령정보센터·대법원·헌재 범위와 시행본/수록범위/원문 대조·접근 권한·비용·전송 보호를 먼저 검증한다. 연결된 작업 앱이나 미국 법률 스킬을 한국법의 법적 근거로 쓰지 않는다.

**평가 측 인계:** 공급자별로 동일 입력·근거·모델 ID·temperature·출력 상한을 고정한 지침 비교를 한다. 정확성·근거·반론/적용 차이·무근거 주장·오탐/누락·유보·비용/지연을 함께 판정한다. 대역 시험 통과는 법률 품질 개선의 증거가 아니다.
