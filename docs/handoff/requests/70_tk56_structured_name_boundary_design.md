# TK-56 재개: 구조화 성명 경계 설계 (2026-10-10)

- 기준: 최신 Steve `03fdcdb`, 새 브랜치 `codex/tk56-structured-name-boundary`. TK-43 수용은 사용자 전달문 (15)으로 확인했으며 그 구현 PR은 변경·병합하지 않는다. TK-55의 사람 표지 없는 역할 명사 키는 범위 밖이다.
- 키 판정: 기존 사람 역할 어휘와 비인명 키 분류를 재사용한다. 이름 필드의 문법적 표지(한글 성명 접미와 영문 name/nm)를 정규화하여 복합 키를 처리한다. 새 비인명 예외 낱말 사전은 만들지 않는다. 알려진 역할/명시 성명 필드와, 주체를 알 수 없는 일반 `…Name` 필드는 구분한다. 후자는 키만으로 사람이라고 단정하지 않고 값 구조를 함께 검사한다.
- 값 판정: 이름 문맥을 붙이는 단일 이름 추출과 전송 차단 판단을 분리한다. 띄어쓴 성명·조사·직함·목록은 한 이름 꼴로 실패했다는 이유로 통과시키지 않는다. 이름 표지가 있는 불확실한 비한글/비문자열 값은 fail-closed로 차단한다. 이미 가명화된 값은 구조를 확인하며, 장소·직무·법인 등 기존 비인명 값은 원문 검사를 계속한다. 일반 이름 키의 비인명 값과 명시 성명 필드의 불확실 값은 같은 규칙으로 무조건 면제하지 않는다.
- 경계·위험: 사용자/system/schema/metadata 및 중첩·문자열 JSON에서 같은 수집 경로를 쓴다. 검사 실패는 기존 router의 미전송 계약을 따른다. 비인명 판정은 탐지를 건너뛰는 허가가 아니며 연락처·주민번호·본문 성명 탐지는 항상 유지한다. 서로 구별할 수 없는 값은 차단하므로 잔여 과차단이 있을 수 있다. 키 분류와 이름 주변 탐색은 사전 계산·유한 창으로 입력 길이에 선형으로 둔다.
- 시험: 합성 이름/목록/띄어쓰기/조사/직함과 불확실 값에 각 3건 이상, 일반 키·비인명 값·가명화 값의 대조 각 3건 이상을 추가한다. 실제 LLMRouter.run에서 user와 원본 system의 공급자 도달/미도달을 함께 확인한다. 목표 r8d/r8e 21건 strict XPASS 외 실패 0, r8a/r8c·구조화/프롬프트 등록·연락처/RRN 관련 시험 및 수천 회 0.1초 시간 시험을 실행한다. 보호 시험·기대값·표시는 고치지 않는다. scorecard 전후와 시험 편집 점검을 보고하고 비공개 수용·verify_all·봉인은 평가 측에 맡긴다.
