# TK-73: document-path title provenance redesign

Base: `04a30fda7b5341536e30d94437e137f1a65f3042`; responds to PR #79 review `5481563349`. Implementation branch: `codex/tk73-document-provenance`.

**Public preflight.** 295 unchanged related tests pass locally. A newly generated TXT and PDF both reproduce a false duplicate when a numeric location and its qualifier occupy separate physical lines. `_exhibit_lines` appends the qualifier with `join_separator`'s default JOIN, erasing its boundary. Changing another suffix pattern cannot establish document-path invariance.

**Changed approach.** Keep the document parsers and legacy display/date/section rows unchanged. Build comparison-only mention provenance from `ReadingText` segment offsets and each block's preserved physical `attributes.lines` (or the visible block text). Align source fragments by NFKC non-whitespace character identity; mismatched alignment falls back conservatively. Store block/page/line and source offsets separately from the reconstructed tail. Extend an accepted mention with explicit continuation fragments, rather than reinterpreting its concatenated display name. Segment the mention into title, numeric-location metadata, prose, and creation-date spans; once metadata starts, later physical fragments retain that role until the next mention or existing continuation boundary. Protected title punctuation and all protected dates survive. This changes only duplicate comparison, not global line reconstruction (tracks A/B), section recognition, TK-64 filtering, or date/gap checks.

**Corroboration and risk.** A location with qualifiers (including a balanced parenthetical coordinate) is weak evidence: remove it only when a distinct mention with a structurally delimited prose description has exactly the same complete normalized title, for the same party/number/branch. A generic prefix, two location captions, or two sentence subtitles cannot corroborate each other. Unsupported/unbalanced syntax retains the existing comparison. No title vocabulary, case values, retired text, new rule IDs, gate/baseline/version edits, or private inputs.

**Public preflight extension.** New document-path controls also expose a continuation line containing a qualifier followed by another colon-labelled exhibit definition, and a closing metadata bracket followed by a creation date. Track comparison continuation independently of the legacy display-name length/date guard. Recover a following list definition only when the preceding extent proves numeric-location metadata and the next exhibit has an explicit definition colon; do not promote an arbitrary inline reference or a protected title reference. Original accepted row fields remain unchanged; the previously missed definition becomes a separate row. Unsupported/unbalanced continuation returns the exact legacy comparison result. This extension is documented before its product edit.

**Public tests.** At least three false-positive controls and three genuine duplicates, main/branch numbers, recognized list sections and no section; TXT and generated PDF via `parse_document`, one-line and forced/natural wrap variants, multiple entries/paragraphs, punctuation/parentheses, sentence subtitles, protected multi-date titles and later metadata. Assert source-span receipts and unchanged original rows. Retain the unchanged TK-64/TK-67/title/date tests and the ticket's 0.1-second repeated-input bounds. Run related tests only, then request evaluator review after same-SHA CI; evaluator alone determines private/retired acceptance and integration.
