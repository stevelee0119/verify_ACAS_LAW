# TK-58 설계 메모 — 숫자 구분 구조와 종류 표시

- 방법: 연락처 정규화 뷰에서 기존 13자리 후보의 앞 여섯 숫자 사이에 구분 기호가 있는지 검사한다. 공백·개행은 정규화에서 제거되므로 허용하고, 여섯째 숫자 뒤의 구분 구조는 제한하지 않는다. 해당 후보는 RRN으로 표시하지 않는다. 기존 계좌 표지 정규식의 문맥 또는 기존 계좌 형태 규칙에 맞으면 ACCOUNT로 표시하고, 종류를 특정할 수 없는 후보는 PII로 표시하여 기존 가림을 유지한다. 원문 위치 매핑·신뢰도·라우터 차단은 그대로 둔다.
- 일반화: 숫자 값, 날짜, 검증 숫자, 사건 문장을 사용하지 않는다. NFKC·Unicode 구분 기호 정규화와 기존 계좌 어휘를 재사용한다. 3-4-4-2, 4-4-5 등 묶음과 줄표·가운뎃점·전각 표기를 함께 다룬다. 새 라벨 어휘는 추가하지 않는다.
- 위험: 종류를 바꾸면서 후보를 버리면 가림이나 차단이 약해질 수 있다. 따라서 후보의 원문 구간을 유지한다. 정상 6-7 RRN과 앞 여섯 숫자 사이 OCR 공백은 RRN으로 남겨 과소 탐지를 막는다. PII는 특정 종류를 주장하지 않는 가림용 표시다.
- 시험: 합성 계좌 양성 3건 이상과 6-7·OCR 공백·뒤쪽 분할 RRN 대조 3건 이상, 마스킹 원문 구간 및 user/system/구조화 입력 차단, 라벨 없는 불명확 후보의 가림 유지. 기존 관련 시험 85건은 수정하지 않는다. 정규식은 변경하지 않지만 구조 검사의 반복 입력 시간도 확인한다. 고정 성적표 전후와 최종 SHA CI를 보고하고, PDF ACCOUNT 1·RRN 0 및 비공개 필수 게이트/전체 verify_all의 수용 판정은 평가 측에 남긴다.
