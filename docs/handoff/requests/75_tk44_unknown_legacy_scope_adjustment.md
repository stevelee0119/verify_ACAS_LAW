# TK-44 / TK-49: UNKNOWN compatibility scope adjustment

Evaluator direction after public sparse/repeated-endpoint comparisons: preserve exact baseline reconstruction for UNKNOWN, including the existing paragraph-local `prev_full`/`char_wrap_context` calculation and its `0.75 * page_width` compatibility floor. Isolate and name that calculation as legacy behavior; it is not evidence for any newly confirmed boundary or wrap state. Direct source-space classification, paragraph diagnostics and confirmed JOIN/SPACE handling continue to exclude page-width and fullness inference.

Reason: removing the floor made a lone longest endpoint look full. Requiring repeated endpoints fixed that case but still changed short repeated endpoints from spaced baseline output to a fragment join. At repeated x1=500 the baseline joins at widths 420/595 and spaces at width 720, so page-width invariance and complete upstream UNKNOWN parity cannot both hold. Turning off legacy fullness would create the opposite risk for historically successful fragment reconstruction. The evaluator chose compatibility without changing any existing expected text.

Implementation plan: restore the precise base fullness computation in a named helper used only to supply legacy join arguments; explicit signals override those arguments. Keep measured paragraph right edge local and `char_wrap_state=UNKNOWN`; no absent-whitespace JOIN inference. Test sparse and repeated-endpoint UNKNOWN parity at widths 420/595/720, preserve the approved API/provenance protections and original ledgers, and let the evaluator run real PDF/DOCX/width gates.

Residual: UNKNOWN retains historical page-width dependence and lexical fragment heuristics. This is a bounded direct-SPACE improvement, not complete layout invariance or full TK44/TK49 closure. Root owns partial acceptance, remaining ticket scope and release/version decisions after actual gates. No word lists, expected-value changes, protected edits or deployment changes are proposed.
