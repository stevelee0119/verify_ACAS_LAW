# TK-56 보완: 성명 신호와 한국어 비인명 값 경계 (2026-10-10)

- 기준: PR #70 `ef790e7` 불승인 회신의 과차단 상한 초과. 같은 브랜치에서 보완한다. 비공개 자료는 요청하지 않고 공개 합성 자료로 원인을 재현한다.
- 재현 원인: 명시 이름 필드의 단일 이름 추출 실패를 곧바로 전송 차단으로 간주하여, 한국어 기관명·업무·복합 값까지 차단한다. 기존 역할 키에서는 통과하던 동일 값도 이름 접미를 붙이면 실패한다.
- 보완 방법: 키 어휘·등록 출처·평문 detector는 유지한다. 모든 이름 필드에서 동일한 유한 이름 창과 기존 조사 문법을 먼저 검사한다. 이름 모양의 목록·직함·조사와 단일 이름은 차단을 유지한다. 그 구조가 없고 전체가 완성형 한글·공백인 값은 기존 원문 탐지에 맡긴다. 비한글·비문자열·구조가 불확실한 값의 fail-closed, 가명 토큰 전체 일치, 비인명 키의 원문 검사는 유지한다. 새 예외 낱말 목록은 만들지 않는다.
- 일반화·위험: 특정 기관/이름/키를 예외로 넣지 않고 성씨·음절·경계 문법과 문자 종류를 쓴다. 성명과 같은 모양의 기관은 여전히 차단될 수 있다. 원문 PII 검사·형제/배열 문맥 검사는 항상 유지한다. 이 경계가 실제 비공개 과차단 상한을 회복하는지는 평가 측이 판정한다.
- 시험: 합성 비인명 값·같은 키 아래의 실명·목록·직함·복합 조사·비한글/비문자열 값을 각 3건 이상, 실제 LLMRouter.run의 system/user/schema/metadata 양방향으로 시험한다. 새 경로는 수천 회 0.1초 이내를 확인하고 목표 strict XPASS 21건·그 밖 실패 0과 관련 PII/등록 계약을 유지한다. 보호 시험·기대값·표시·다른 담당 파일은 변경하지 않는다. 두 번째 불승인이면 다음 구현 전에 접근을 재검토한다.
