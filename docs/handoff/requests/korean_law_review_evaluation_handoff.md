# TK-75 평가 인계: 릴리즈 후 Render 종합 검토

**최신 사용자 결정(2026-10-10):** 실제 법률 판단·비용·지연 평가는 릴리즈 후 API 키가 설정된 Render 환경에서 실시한다. 평균 비용과 p95 지연의 기존 대비 20% 증가 기준은 **참고 목표**이며, 결과의 유용성과 부담을 함께 보고 적용 여부를 판단한다. 이 결정은 종전의 릴리즈 전 실제 A/B 필수 조건과 복잡한 사전 등록·표본/반복·점수/통계 통과 요건을 대체한다. 구현 제출과 법률 품질 개선 판정은 구분한다.

## 릴리즈 전

구현 경로·기본 꺼짐/복귀·응답 계약·보호 기능을 검토하고 같은 SHA의 필수 CI를 확인한다. 실제 API 비교 결과가 없다는 이유만으로 이 기능의 기술 수용·통합·릴리즈를 보류하지 않는다. 다른 릴리즈 절차·사용자 병합/배포 승인·독립 평가 역할·기존 CI와 기준선은 유지한다. 기본 꺼짐으로 릴리즈하며 실제 개선을 확인했다고 표시하지 않는다.

PR #74의 현재 제출 SHA에서 필수 CI가 완료·성공하고 독립 기술 평가가 수용하면, 수용된 PR #73 변경과 함께 같은 다음 릴리스 후보에 포함한다. 통합 순서는 두 PR의 최종 SHA와 기준 브랜치를 확인해 누락·충돌 없이 정하고, 두 PR의 검토·CI 및 기존 릴리스 게이트와 사용자 승인을 각각 유지한다. 이는 실제 법률 품질 개선의 입증이나 기본 ON 승인을 뜻하지 않는다.

평가 측에는 기존 TK-75 티켓 및 `TK75-AB-20261010-R2`의 사전 온라인 시험 조건을 이 결정에 맞게 정리하도록 요청한다. 구현 측은 보호된 평가 도구·시험·기준선·비공개 자료·평가 기록을 열람하거나 수정하지 않는다.

## 릴리즈 후 간단한 비교

사용자 추가 결정에 따라 **온라인 실행결과 점검에서 Claude 법률 지침 적용/미적용 결과를 상호 대조**한다. 프로그램 전체 경로의 실제 OFF/ON 효과이며, ON의 관할/기준일 context 차이도 기록한다. 실행 순서는 [평가 측 온라인 점검](TK75_ONLINE_OFF_ON_CHECK.md)이다.

1. 평가 측과 사용자가 릴리즈 SHA 및 Render의 정상 동작·서버 API 접근을 확인하고 대표 입력 몇 건을 고른다. 구현 측이 제공하는 입력은 공개 합성 자료뿐이며 실제 사건 자료와 법률 판단은 사용자/평가 측이 관리한다. 키는 서버 안에서 사용하고 저장소·PR·평가 대화로 옮기지 않는다. 별도 비공개 실행기를 만드는 것은 이 기능의 필수 조건이 아니다.
2. 같은 릴리즈·모델·입력·참고자료와 명시 기준일로 기존 기능 OFF와 새 기능 ON의 결과를 비교한다. 자료가 바뀌거나 Claude 대신 fallback이 사용된 경우 그 사실을 적는다. 비교에는 기존 프로그램의 검토 경로·마스킹·입출력 검사·예산·시간 제한을 그대로 사용한다. 지침만 분리한 별도 시험·자동 이중 호출·대규모 반복은 요구하지 않는다.
3. 독립 법률 채점자는 **한국 변호사 1명**으로 한다. 채점 시 OFF/ON 표시는 가리고 결과를 비교한다. 한 명이 평가하므로 복수 채점자 간 불일치나 제3 판정은 두지 않는다. 법률·사실관계가 불확실한 항목은 임의로 결론 내리지 않고 미결로 기록한다.
4. 결과와 기존 실행 기록을 한 번의 짧은 종합 보고로 검토하고 **계속 사용 / 보완 후 재검토 / 기존 지침 복귀** 중 권고안을 제시한다. 필요한 경우에만 표본을 늘린다. 사용자는 운영 부담과 권고를 검토하고 정식 활성화 여부를 결정한다.

| 함께 볼 내용 | 간단한 기록 |
|---|---|
| 법률 판단과 실무 유용성 | 독립 한국 변호사 1명이 정확성·근거 원문 연결·반론/사안 차이·누락/오탐·필요한 유보를 비교. 근거 없는 사건번호/조문/인용·중대한 오류도 확인 |
| 비용과 응답 시간 | 기존 usage/cost_status·실행 비용·응답 시간으로 OFF/ON 변화 확인. 가능한 경우 평균 비용·p95 지연의 20% 참고 목표와 비교. 추정 비용은 추정으로 표시하고, 적은 표본의 p95는 참고값으로만 사용 |
| 안정성과 보호 | 실패·timeout·retry/fallback 및 마스킹/공식 확인 상태를 함께 확인. 성공 결과만 골라 보고하지 않음 |

20%를 넘었다는 이유만으로 자동 탈락시키지 않으며, 법률 검토의 도움과 운영 부담을 함께 판단한다. 표본이 적거나 차이가 불명확하면 개선 미확인으로 기록하고 필요할 때 추가 확인한다. 모델 자기평가·문장 길이·오프라인 고정 점수만으로 개선을 주장하지 않는다. 중대한 법률 오류·근거 없는 인용·보호 기능 회귀가 확인되면 새 기능 사용을 중단하고 복귀/보완한다.

## 실행 범위·현재 상태

Render에서 시험할 때 API/worker의 `LV_KOREAN_LAW_REVIEW_PROFILE`을 함께 재로드하고 OFF/ON 각각 새 실행을 사용한다. 진행 중 작업의 설정은 바꾸지 않으며 다른 사용자의 작업에 영향을 주는 전환은 피한다. ON 캐시는 `+kr2`로 구분되고 `0`으로 재로드하면 기존 지침으로 돌아간다. 시험 지출은 기존 예산/시간 상한과 앞서 평가 측에서 확인한 총 USD 40 상한 중 더 낮은 범위에서 제한하며, 예산이 부족하면 강제 반복하지 않는다. 이 문서는 지금 Render 설정 변경·배포·시험 실행을 수행했다는 보고가 아니다.

현재 기술 수용 head는 `3805e9495985626224c8c28ab06811a8068fb034`(제품/시험은7eab582와 동일)이며, 최종 head CI38094767858·점수38094767864 성공이다. 공개70건 및 별도 통합 교차25건을 통과했고 Steveba12d25에 병합했다. 실제 API 법률 품질·과금·지연은 미측정이다. 기존 RAG 자료/발췌 한도와 원문 인용 검사만으로 법률적 타당성을 보장하지 못하며, 더 긴 지침이 실제 usage·실패/재시도를 바꿀 수 있다. 기본 모델·OpenAI/Gemini 경로·공식 확인 상태는 유지한다. MCP·Claude Code 실행기·새 모델은 추가하지 않는다.
