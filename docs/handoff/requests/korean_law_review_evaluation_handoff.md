# TK-75 보완: 독립 평가 인계 요청

구현 세션의 제출이며 수용 판정이 아니다. 사용자 결정(2026-10-10)은 **이번 PR에서 선별 지침만 기존 Claude 서버 API에 적용, 다른 모델/fallback 유지, MCP는 자료/권한 확인 후 별도 연결**이다. 채택은 법률 품질 개선을 전제로 **평균 비용 및 p95 지연 각각 기존 대비 최대 20% 증가**를 허용한다. 중대한 법률 오류·근거 없는 인용·보호 기능 회귀는 허용하지 않는다. 표본·법률 품질 개선의 최소 차이/불확실성·비용/지연 측정 단위와 집계 방식은 평가 측이 결과를 보기 전에 확정한다. 수용 전 기본 꺼짐을 유지한다.

## 보류 사유의 보완

1. 프로필을 `review_document → LLMRouter.run`의 문서/주장 단위 Anthropic 요청에만 적용했다. 기존 `verify_argument_validity → consult_all` 변경은 원복했다. 공급자 선택 뒤, 개인정보/예산/시간 검사 전에 적용하며 OpenAI/Gemini fallback은 기존 요청과 같다. 공개 합성 경로 시험이 이 경계를 검증한다.
2. 판정의 참조 `95bdacc803aa5cfdb10f35e5b9fb2d4b11100133`은 공개 저장소 commit/tree API 모두 422였다. 확인 가능한 `4a6c651889c97cc9140580363c73e0eb17379c2b`를 유지하며 [출처 기록](korean_law_review_profile_sources.md)에 API 조회·선별 파일/blob·라이선스·변경 사유를 명시했다. 승인 SHA와 일치했다고 주장하지 않는다. 변경 사유 검토 또는 참조 정정이 필요하다.
3. 실제 법률 품질·비용·지연 A/B는 미측정이다. 아래 실제 평가를 별도 평가 세션에 요청한다. 구현 측은 기존 시험/평가 도구·기준선·비공개 입력을 열람/수정/실행하지 않았다.

## 비교 계약

- **지침 효과:** 같은 마스킹된 RAG 요청에서 `build_review_comparison_request(request, korean_profile=False/True, reference_date=...)`를 사용한다. 두 팔의 문서/주장·자료/발췌·관할/기준일·metadata·응답 schema·temperature·출력 상한은 동일하고 system만 다르다. 같은 Anthropic 모델/정책/예산/timeout에서 기존 `LLMRouter.run`을 거친다. 자동 이중 호출이나 새 평가 도구는 추가하지 않았다.
- **운영 전체 효과:** 같은 원본·공식 조회 결과·참고자료 snapshot으로 실제 스위치 OFF/ON을 비교한다. ON의 context 입력 및 프로필 적용·실제 잘림/실패/fallback까지 포함한 전체 효과이며 순수 지침 효과와 구분한다. 운영 캐시에서 과거 결과를 가져오지 않도록 동일 SHA의 두 설정/새 실행을 사용한다.
- **회귀 대조:** 다른 stage·주장 의견·OpenAI/Gemini fallback·QUICK/LOCAL_ONLY 및 공식 확인 상태를 확인한다. 모델 의견/합의를 공식 확인으로 높이지 않는다.

## 측정·판정 요청

| 항목 | 평가 증거 |
|---|---|
| 한국법 판단 정확성 | 공식 시행본/판결 원문과 사실에 따른 변호사 판단. 블라인드 짝 비교·평가자 불일치 처리·반복/오차 범위를 사전에 확정 |
| 근거 충실도 | 쟁점–요건–사실–원문 연결, 실제 인용/위치, 기준일 적용. 인용 문자열 존재만으로 취지/법률 타당성 통과 처리하지 않음 |
| 반론·적용 차이 | 가장 강한 반론·예외·사안 차이를 근거로 설명하는지. 반론을 위해 사실/규칙을 만드는지 |
| 무근거·오탐·누락·유보 | 입력 밖 사건번호/조문/인용/사실, 확인 상태 부당 승격, 오탐/누락, 필요한 유보와 불필요한 과도한 유보를 함께 집계 |
| 비용 | 영향받는 Claude 요청 및 문서 전체 실행을 각각 짝 비교. input/output/cache usage·cost_usd·cost_status와 실제 공급자 청구/단가를 대조. ESTIMATED/RESERVED_UNCERTAIN은 실측으로 처리하지 않음 |
| 지연·안정성 | 요청 및 문서 전체 벽시계 시간의 p50/p95, 실제 호출/재시도·잘림·실패·격리·timeout/fallback 건수. 성공한 요청만 선택하지 않음 |

사용자 비용/지연 조건은 각 비교 단위에서 `평균 비용_ON / 평균 비용_OFF <= 1.20`, `p95 지연_ON / p95 지연_OFF <= 1.20`로 사전 등록할 것을 요청한다. 기존 총 실행에는 변경 없는 공급자/단계가 섞이므로 Claude 단계와 전체 실행을 모두 보고한다. OFF 비용/지연이 0인 범주는 비율 대신 평가 전에 절대 상한/처리를 정한다. 표본 부족·과금 추정뿐·모델 변경·자료 snapshot 차이·불안정한 p95면 통과로 간주하지 않는다.

자기평가·문장 길이·고정 오프라인 점수/대역 시험만으로 개선을 판정하지 않는다. 새 입력의 실제 온라인 검토를 포함하고 동일 모델/입력/자료가 지켜진지 기록한다. 실측 실패 또는 품질 개선 미입증이면 기본 꺼짐 유지/추가 보완/철회 중 권고안을 제시한다. 결과를 보고 기준을 낮추지 않는다.

## 구현 증거·남은 제약

- 새 공개 합성 시험은 실제 `review_document → run → provider`에서 켬/끔 3종 입력·각 공급자·fallback·batch 분할·마스킹/입출력 검사·예산/timeout·기준일·인용 거부·공식 상태 비승격·스냅샷을 확인한다. 실제 API와 변호사 법률 평가가 아니다. 이전 잘못된 경로의 47건 결과를 이번 경로의 증거로 재사용하지 않는다.
- 기존 RAG 선택/발췌 한도를 유지해 공식 시행본·전문·예외가 부족할 수 있다. 새 법률 데이터 수집·해석 검증기를 추가하지 않았다. 유보/누락/오탐 변화는 실제 평가 대상이다.
- 추가 system 지침 829자 및 명시 날짜 context를 넣지만 이를 과금 토큰/실제 비용/지연으로 환산하지 않는다. 기존 호출/예산/시간 상한은 같아도 실제 재시도·출력/입력 usage·한도 거절 빈도는 달라질 수 있다.
- 기본 꺼짐이며 `+kr2`로 기존 캐시와 구별한다. 새 MCP·플러그인 전체/자동 에이전트·Claude Code 실행기·Astra·모델 교체·버전/기준선 변경은 없다. TK-72·74 브랜치/PR은 수정하지 않았다.
