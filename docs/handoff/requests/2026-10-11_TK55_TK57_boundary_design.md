# TK55 §3 / TK57 residual boundary design (implementation proposal)

Scope: exact public base `5deaac7452e8eba65fda46b52896ac65d3ff717e`. TK55 §1/2/6 and TK57 mandatory gates are accepted and remain unchanged. Name protection remains required; phone/RRN remain the automatic mandatory gate. No thresholds, protected tests, versions, or noun dictionaries change.

**TK55 current contract and proposed boundary.** Current `LLMRequest.schema` describes the *response*, not the input. Arbitrary JSON `user` and original `system` are currently accepted; unknown role-only keys intentionally remain outside key inference. Rejecting every unknown key in that legacy contract would also reject benign requests and contradict narrow/no-overblock policy. Proposed implementation: add a separate, explicit input-contract identifier to `LLMRequest`, selected by first-party request builders (never inferred from role nouns or supplied JSON). Closed, path-specific structural contracts mirror the existing AI detection, reference review, claim review, and argument-review payloads; existing claim-review validation is reused. These contracts specify free-text leaf paths and fixed metadata types, forbid extra object keys, and treat a free-text string decoding to a JSON object/array as nested structured input requiring its own approved contract rather than a bypass. `LLMRouter.run` applies the contract after review-profile selection and before provider dispatch, using the preserved original system and assembled request. Existing PII scanning still runs for every text leaf and original system. Response schemas and known static prompt exemptions remain unchanged. Plain-text legacy callers retain current detection behavior. Original-system JSON is accepted only under an explicit closed system contract; registered constant prompts require no contract.

This is a boundary on supported structured input, not a new general name detector. It closes arbitrary role-noun field injection in contracted first-party requests independent of key vocabulary. **It does not claim to resolve the 24 strict xfails for arbitrary legacy requests without a policy decision to require contracts there.** Root must approve whether to (A) preserve legacy arbitrary JSON with residual explicitly recorded, or (B) require an input contract for all structured user/original-system requests and review the resulting compatibility change before implementation. The public tests currently expect benign arbitrary structured requests to pass; B needs evaluator-owned contract/test disposition, not unilateral implementation edits. No product changes until this decision.

Approved direction (evaluator, 2026-10-11): A, first-party improvement; legacy residual remains. Exact integration surface proposed for precheck: `LLMRequest.input_contract` is a separate optional internal field, never inferred from user JSON or metadata. Contracts bind to the exact existing consumer system/output-schema pair. AI detection closes filename/hint/sample/coverage fields. Reference review closes document/references and optional review context. Claim review reuses its current validator and closes review context/source metadata types. Argument review closes the current batch-item fields. All extra object keys are rejected, including nested review context. Contracted free-text leaves that fully decode to JSON objects/arrays are unsupported structured input, while prose containing JSON remains text and receives the unchanged PII scan. This deliberately exposes the possible whole-leaf JSON-evidence compatibility risk rather than silently treating arbitrary nested keys as safe. Original system must match its consumer constant (RAG includes the Korean profile constant); assembled and original system keep existing PII scanning. Unknown contract IDs or payload/metadata markers cannot confer exemption. Cascade mixed prose and every request with no input contract retain existing behavior, including known_open24.

**TK57 offset repair (independent commit).** Keep the accepted normalized detection patterns and classifications. Extend the original span of an already-detected subscriber only when the normalized prefix proves an adjacent international dial prefix (`+` and 1–3 country-code digits, optionally enclosed in balanced parentheses) attached to that same numeric token. Use normalization-to-original positions so fullwidth characters, whitespace, and punctuation map accurately; do not reclassify ACCOUNT/RRN/PII as PHONE or introduce a new detection gate. Reject prefix extension across prose, an unmatched bracket, or a line boundary without explicit attachment. Ensure extension cannot cross a legal-identifier guard or consume neighboring independent numbers.

**Verification and risks.** Each change gets at least three synthetic positives and three controls, with full-span masking assertions and actual fake-provider router user/original-system paths. Run existing R8-C/D/E structured privacy, R8-F contact/RRN, TK58 classification, and TK43/TK56 relevant tests only. TK55 risks are malformed/nested input bypass and unsupported-client overblocking; explicit contracts plus compatibility fixtures expose those limits. TK57 risks are swallowing adjacent legal numbers or malformed prefixes; exact mapped boundaries and non-number context controls constrain extension. Separate commits carry `Agent: implementer`; root evaluates protected gates and publishes/merges/deploys.
