# Claude for Legal 선별 지침의 영향 분석·릴리즈 후 판단

2026-10-10 사용자 요청에 따른 **실측 전 분석**이다. 기존 Claude 서버 API에 검토 방법론을 넣는 변경이며 Claude Code 실행기/새 법률 전용 모델/MCP 설치 분석이 아니다. 해당 추가 기능은 후속 별도 설계 대상이다. 법률 판단 개선을 이미 확인했다는 주장이 아니다.

| 영향 | 기대 및 한계 | 확인 방법 |
|---|---|---|
| 법률 판단 | 쟁점/요건–사실–원문 연결과 반론/불확실성 검토로 단정·누락을 줄일 가능성. 공식 한국법 시행본이나 필요한 사실이 없으면 방법론만으로 정답을 보장하지 못함 | 릴리즈 후 Render에서 동일 입력의 실제 OFF/ON 결과를 사용자/법률 검토자가 비교. 정확성·근거·반론/적용 차이·무근거 주장·오탐/누락/유보를 함께 판단 |
| 시간 | 추가 검색/에이전트/모델 호출 경로는 없음. 더 긴 지침 및 응답 변화·잘림/기존 retry로 지연이 늘 수 있으며 timeout 상한 유지로 검토 실패가 늘 수도 있음 | 요청/전체 실행의 벽시계 p50/p95와 실패·retry·timeout/fallback 포함 측정 |
| 비용 | Anthropic의 해당 요청에만 고정 system 829자와 context가 추가됨. 유효 날짜 context 단독 JSON은 118자이며 원 페이로드 삽입 구분자/인코딩 포함 실제 길이는 다름. 글자 수는 과금 토큰이 아님. OpenAI/Gemini 전송 payload는 그대로 | 공급자 실제 input/output/cache usage·청구 단가로 평균 요청/전체 실행 비용 계산. 호출 수·과금 추정 상태도 함께 보고 |
| 보호·운영 | 기존 마스킹·입출력 검사·공식 확인·예산·시간·응답 계약 유지. 보수적 입력 크기 상한을 넘으면 기존 admission이 호출을 막으므로 성공률도 확인 필요 | 새 합성 계약 시험과 같은 SHA CI, 독립 실제 실패율/회귀 검토 |

비용은 공급자 적용 단가를 `p_in`, `p_out`(백만 토큰당 USD)라 할 때 캐시가 없는 호출의 증가분을 `(추가 input_tokens × p_in + output_tokens 변화 × p_out) / 1,000,000`으로 계산한다. 캐시 할인/쓰기, 실제 retry·fallback·실패 과금은 별도 합산한다. 문서당 영향받는 호출 수와 월 처리량을 곱하면 월 증분을 얻을 수 있지만 현재 실측 usage·처리량이 없으므로 금액을 제시하지 않는다. 기존 예산 예약은 글자 수 추정 대신 설정 입력 cap과 출력 cap에 기반한다. 두 cap/단가는 바꾸지 않아 동일 요청 한도에서 예약 상한은 같지만 이는 실제 청구 증가가 0이라는 뜻이 아니다.

**최신 사용자 결정:** 실제 효과는 릴리즈 후 API 키가 설정된 Render 환경에서 종합 평가한다. 평균 비용·p95 지연 20% 증가 기준은 참고 목표로 유지하고 법률 검토의 유용성·비용·시간·안정성을 함께 보고 계속 사용/보완/복귀를 판단한다. 복잡한 사전 등록·점수/통계 기준이나 실제 API 시험은 릴리즈 전 필수 조건이 아니다. 적은 표본이나 추정 과금의 한계를 적고, 개선 미확인을 개선 입증으로 바꾸지 않는다. 중대한 법률 오류·근거 없는 인용·보호 기능 회귀가 확인되면 새 기능을 중단하고 복귀/보완한다.

**현재 권고:** 기본 꺼짐으로 기술 검토와 같은 SHA의 필수 CI를 거쳐 기존 승인 절차에 따라 릴리즈한다. 그 뒤 Render에서 대표 입력 몇 건의 OFF/ON 결과와 기존 실행 기록을 비교해 정식 활성화를 판단한다. 합성 시험 통과는 연결/보호 증거이며 법률 품질·실제 비용·지연 개선 증거로 쓰지 않는다. 현재 변경은 문서/인계 절차뿐이고 병합·배포·서버 설정 변경은 수행하지 않는다. MCP는 기존 공식 자료 접근의 부족이 확인되고 한국법 자료/서버 권한·비용·시간이 검증된 뒤 별도로 판단한다. 구체적인 간단한 절차는 [평가 인계](korean_law_review_evaluation_handoff.md)를 따른다.
