# 8C 설계 메모 — 이름 키 문맥과 값 게이트

## 방법

구조화 요청 검사에서 JSON 문자열 값은 지금처럼 원문 그대로 항상 검사한다. 키 문맥은 키를 정규화한 뒤에만 추가한다. 이름 키 분류는 `detector.py`의 `PARTY_AND_TITLE_LABELS`를 유일한 사람 라벨 어휘 출처로 사용하고, 라벨을 한글 토큰으로 포함하거나 라벨의 `명`·`이름`·`성명` 꼬리형, 괄호·공백 변형으로 표기한 경우를 인식한다. 흔한 영문 사람 이름 키도 같은 분류 경로에 둔다. 사건·법원·회사 이름처럼 사람 라벨 머리가 없는 단순 `-명` 키는 제외한다. 주민번호·연락처 등 개인정보 종류 키의 기존 처리는 별도로 유지한다.

이름 라벨 문맥은 값 자체가 단일 한국어 토큰이고, 공백을 제거한 2~4음절이며, detector의 성씨 구조에 맞을 때만 합성한다. 호칭·괄호가 붙은 값은 경계를 분리해 같은 검사를 적용한다. 나머지 값은 원문만 검사한다. 구조를 안전하게 분리할 수 없는 키·값 형식은 문맥을 추측하지 않고 요청을 차단한다. 형제 필드와 배열 이웃은 기존 결합 규칙을 유지한다.

## 근거와 위험

정확 문자열 키 비교가 복합·접미·공백 변형 라벨을 놓치는 결함을 직접 줄인다. 라벨 어휘를 한 곳에서 가져오면 detector와 전송 경계의 정의가 갈라지지 않는다. 성씨 기반 값 게이트는 직책·장소·기관 텍스트에 라벨을 무조건 붙여 생기는 추가 차단을 줄인다. 남는 위험은 이름처럼 보이는 장소·직무 단어의 과차단과 새로운 라벨 표기의 미탐이다. 모호한 문맥은 fail-closed로 처리하고, 불용어 목록이나 detector의 이름 판정 규칙은 이 작업에서 바꾸지 않는다.

## 시험 계획

새로 만든 값만으로 회귀 시험을 추가한다. 복합·접미·괄호·공백·영문 이름 키는 이름 값이 차단되는지, 사건·법원·회사 `-명` 키는 키 문맥 때문에 추가 차단되지 않는지 확인한다. 성씨형 이름 값은 차단되고 장소·직무·법인·기관 값은 키 문맥만으로 차단되지 않는지 본다. 검사 예외는 닫히며, 형제·배열 쌍의 기존 이름 차단은 유지되는지 확인한다. 이어 전체 `verify_all.py --base d20cde2`를 실행한다.
