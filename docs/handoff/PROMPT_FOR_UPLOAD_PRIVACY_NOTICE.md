**정책:** 시스템이 자동 마스킹을 **보장하는 것은 연락처·주민등록번호뿐**이다. 성명·주소 등 그 밖의 개인정보는 사용자가 업로드 전에 직접 가려야 한다. 기존 성명 등 자동 마스킹은 '보장하지 않는 보조 기능'으로 남는다.

아래 전체를 Antigravity 작업 설명에 붙여 넣는다. 저장소 루트의 `AGENTS.md`도 함께 따른다.

## 1. 요구
1. **업로드 화면 안내**(`apps/web/index.html` 자료 패널, `apps/web/static/app.js` 업로드 흐름)
   - '파일 추가' 근처에 상시 보이는 안내문을 둔다. 내용은 다음 세 가지다(문구는 사용자 검토 대상).
     - "자동으로 가리는 개인정보는 연락처와 주민등록번호뿐입니다."
     - "성명·주소 등 그 밖의 개인정보는 업로드 전에 직접 가려 주세요."
     - "성명 등 자동 가림은 보조 기능이며 모두 가려진다고 보장하지 않습니다."
2. **확인 체크**
   - 체크박스 "연락처·주민등록번호 외의 개인정보를 직접 처리했습니다"에 체크해야 업로드(파일 선택·끌어 놓기 모두)가 진행된다.
   - 체크하지 않은 채 시도하면 이유를 알리고 업로드하지 않는다.
   - 체크 상태는 프로젝트·세션 단위로 기억하되, 다시 볼 수 있게 표시한다.
3. **서버 측 확인**(`apps/api/routers/projects.py` `upload_document`)
   - 확인 값을 폼 필드로 받는다(예: `privacy_ack`).
   - 값이 없거나 거짓이면 **422**로 거절하고, 화면과 같은 이유를 담는다. 화면만 막고 API로 우회할 수 있으면 안 된다.
   - 확인 사실은 감사 기록(audit)에 남긴다. 사용자, 프로젝트, 문서, 시각, 안내문 판(version)을 기록하고, 원문 개인정보는 기록하지 않는다.
4. **보고서 머리 표시**
   - 검증 보고서(화면·내보내기)의 머리에 자동 마스킹 보장 범위를 한 줄로 적는다. 내용: "연락처·주민등록번호 자동 가림 보장, 그 밖의 개인정보는 사용자 처리"
5. **안내문 판 관리:** 안내 문구는 한 곳(설정 상수)에서 관리하고 판 번호를 둔다. 문구를 바꾸면 판을 올린다.

## 2. 제약
- 바꿀 수 있는 곳: 위 화면·API·감사 기록·보고서 머리, 그에 필요한 마이그레이션(필드 추가 시), 새 시험.
- 하지 않는 것
  - 개인정보 탐지 로직(`packages/pii_engine/`, `packages/llm_router/privacy.py`) 변경(8F에서 Codex가 작업 중 — 파일이 겹치지 않게 한다)
  - 보호 경로 변경
  - 기존 시험의 삭제·수정·표시 변경
- 기존 브라우저 시험 197건이 그대로 통과해야 한다. 기존 업로드 시험이 확인 값 없이 업로드하는 경우, **시험을 고치지 말고** 평가 측에 알린다. 평가 측이 보호 시험 갱신 여부를 정한다.
- 접근성: 체크박스에 라벨을 연결하고, 키보드로 조작할 수 있어야 하며, 거절 사유는 화면 낭독기가 읽을 수 있어야 한다(`aria-live` 등).

## 3. 새 시험(입력은 새로 짓는다)

**보완 범위(이것만 한다)**

   - (가) 로그인 성공 뒤 `loadPrivacyNotice()`를 다시 부른다.
