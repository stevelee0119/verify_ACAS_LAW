## 0. 이번 라운드의 성격과 동결 해제 범위
- **착수 전제(2026-10-03 추가):** 이 라운드는 7차 지시서 2절의 게이트가 충족되고 사용자가 승인하기 전에는 시작하지 않는다. **F3(참고자료 외부 전송 범위 확대)는 추가 조건**(개인정보 비공개 변형 ≥ 98%, 참고자료 발췌가 같은 마스킹·전송 전 검사를 지나는 경로의 평가 측 시험, F2 완료와 TK-29 해소)이 있다. 이유: 6차 독립 감사에서 명시 성명이 후행 문맥 때문에 마스킹·전송 전 검사를 함께 빠져나가는 회귀(TK-39)가 확인되어, F3가 그 영향을 받을 수 있다.
- 4·5차의 "새 기능 동결"을 **F0~F4에 한해** 푼다. 새 모듈·새 API 필드·화면 변경·DB 마이그레이션을 허용한다. 그 밖의 동결(새 `rule_id`·새 탐지 유형 금지)은 유지한다. 이번 일은 **이미 있는 탐지 결과의 표시·연결·참고자료 대조**이며 새 탐지를 만들지 않는다. 새 `rule_id`가 필요하다고 판단되면 구현하지 말고 `docs/handoff/requests/`로 제안한다.
- **예외 — FT(행위시법 검토 보강, 2026-10-04 포함):** FT는 탐지 변경이므로 위 '새 탐지를 만들지 않는다'와 아래 '점수·측정 불변'의 예외다. 규칙은 1절 FT에 따로 둔다. 다른 묶음(F1~F4)의 규칙은 그대로다.
- **사용자 결정 D1~D6은 2026-10-02에 확정됐다**(FR-01 6절). 이 지시서는 아래 결정을 전제로 쓰며 구현 측이 바꾸지 않는다.

## 1. 작업 묶음 (이 순서로, 묶음마다 커밋·요청서)
### F0. 시작 점검과 설계 요청서 (구현 전에 평가 측 회신을 받는다)
1. 7차 지시서 5절 명령으로 기준선을 확인하고 `requests/18_f1_baseline.md`에 붙인다.
2. **설계 요청서** `requests/19_f1_design.md`를 낸다. 평가 측이 검토해 회신하기 전에는 F2·F3 코드를 쓰지 않는다(F1은 설계 없이 시작해도 된다). 포함할 것:
   - `review_items`(통합 탭용 서버 단일 판정 객체)의 필드 안(아래 F2의 제안 형태를 그대로 쓰거나 고친 안), 기존 JSON 필드와의 대응표(기존 경로는 모두 유지).
   - **행별 검토 상태 저장 방식**: 지금 검토 상태·우선순위·담당자는 finding ID 기준(`FindingWorkflow`, `/findings/{id}/workflow`, `/projects/{id}/reviews`)이다. 인용표 행에는 finding ID가 없다. 안 (a) 확인 필요 행은 항상 기존 finding에 연결(없으면 '정보' 상태로 두고 저장 불가 표시) (b) 새 항목 테이블과 마이그레이션 — 각각의 영향, 기존 검토 이력 보존 방법, 낙관적 잠금(`revision`) 유지 방법을 비교하고 권고안을 적는다.
   - 유형→화면 배정표(모든 `FindingType`이 어느 화면 묶음에 속하는지, 미배정이면 시험이 실패하는 구조). 포렌식·위·변조 징후 유형의 배정안(기본 제안: 보안 카드)을 별도 표시한다.
   - F3의 청구 단위 검색·대조 설계(질의 구성, 상한과 배치, 호출 수 추정, 실패·부분 완료 처리).
   - **(2026-10-04 추가) FT 설계 보충** — `requests/19_f1_design.md`에 절을 더하거나 별도 메모로 낸다. 평가 측 회신 전에는 FT 코드를 쓰지 않는다. 담을 것: 목 단위 본문 대조 방식, 동일 시행일 복수 버전의 병기·대조 방식, 번호만 바뀐 개정과 내용이 바뀐 개정의 구분 근거, 오탐 대조군 계획, 기존 `rule_id`로 충분한지(새 `rule_id`가 필요하면 요청서).

### F1. AI 탭을 'AI 작성·보안 진단'으로 축소 (규모 소)
- 탭에 남기는 것: 문서 AI 생성 여부 진단 카드(모델별 의견 포함), 프롬프트 인젝션 검증 카드, **보안 카드**(D3: 작성자·회사 정보 노출 `AUTHORSHIP_METADATA_LEAK`, 저장 경로 노출, 5차 U9-2의 '생성 소프트웨어 정보'(INFO) 등 파일 정보 노출 항목. 정보는 숨기지 않고 심각도는 기존 값 그대로).
- 탭에서 내보내는 것: 판례 인용 오류·미확인 검토 요약과 법률 인용·주장 검토표, 주요 참고문헌 검토(RAG), 추가 관련 법조문 검토. F2 전까지는 이 내용이 **사라지면 안 되므로** F1과 F2는 같은 릴리스 단위로 묶거나, F1 단계에서는 이동 대상을 임시로 기존 '확인할 항목' 탭 하단에 둔다(어느 쪽이든 정보 손실 0).
- 탭 이름은 'AI 작성·보안 진단'(가칭)으로 바꾸되, 화면 안내문에 "인용·법리 검토는 'OO' 탭에서 확인"을 둔다.
- AI·보안 유형 finding(AI 작성 참고 신호·AI 전체 생성 의심·인젝션 격리 등)은 '확인할 항목'(통합 탭)에서 빼 AI·보안 탭에 모은다. 단 **D2에 따라 상단 요약(`renderSummary`)의 격리·AI 판정 노출은 유지**하고, HIGH 이상은 통합 탭 맨 위에 한 줄 고정 안내(AI·보안 탭으로 가는 링크)로 남긴다.
- **유형→화면 배정표**를 한 곳에 둔다. 모든 `FindingType`이 배정되어 있는지 자동 시험으로 막는다(미배정 유형 추가 시 실패).
- 수용: 화면별 변경 전/후(가능하면 스크린샷)를 요청서에 붙인다. AI 탭에 인용·RAG 행 0, 통합(또는 임시) 탭에 AI·보안 유형 행 0, HIGH 이상 AI·보안 항목은 고정 안내로 도달 가능, 점수·probe 동일.

### F2. 통합 '검토 항목' 탭 — 확인할 항목 + 판례 인용표 + (자동 추출) 주장 (규모 중~대)
- 표 형식은 현행 판례 인용표의 4열을 기준으로 한다: **위치 / 문서 주장·인용 내용 / 근거 확인 결과 / 법리 타당성·반박·대응**. 검토 상태(확인 전·수용·오탐·조치 완료)·우선순위·담당자 조작은 행 안에 둔다. 현행 '확인할 항목'의 검색·중요도·검토 상태 필터, 같은 인용에서 파생된 항목 묶음, 상세 보기(문서 쪽 보기·강조)를 유지한다.
- **서버가 단일 판정 객체를 만든다.** 제안 형태(추가 필드, 기존 필드는 그대로 둔다):
  `review_items[] = {item_id, kind(CITATION|CLAIM|TEMPORAL|FACT|REFERENCE_OBSERVATION|UNVERIFIED_SCOPE), document_id, location, claim_text, cited_authority, evidence{ladder, grade, sources[]}, verdict_label, severity, finding_ids[], citation_id, claim_id, issue_ids[], review{state, decision, priority, assignee, revision}, advisory_only, reasoning_sections, counteraction}`.
  - 같은 `citation_id`의 근거 판정·심각도·문구는 **모든 화면에서 하나**다. 실측 불일치(표 "공식 DB 미확인" 대 finding CRITICAL/MEDIUM, 3/3)를 이 한 곳에서 없앤다. 심각도 값은 기존 규칙과 사용자 결정(TK-23 B)을 그대로 쓴다. **심각도 규칙을 이 라운드에서 새로 정하지 않는다**(같은 값을 한 곳에서 보이게 하는 것이 일이다).
  - 근거 사다리(`ladder`): `OFFICIAL_CONFIRMED`(공식 원문 확인) / `REFERENCE_SUPPORTED`(참고자료에서 확인, 공식 아님) / `OFFICIAL_NOT_FOUND`(공식 조회 범위 내 미발견, 부존재 확정 아님) / `UNCONFIRMED` / `NOT_ASSESSED`. 참고자료 일치가 공식 미발견을 **지우지 않는다**(TK-29 원칙).
- **행 구성:** (1) 인용 행(현 인용표 + 해당 finding을 한 행으로), (2) 법리·시점·사실 검토 finding 행(시점 모순·근거 없는 청구 유형 등, 현재 '확인할 항목'에만 있음), (3) 참고자료 대조 행(F3), (4) '미확인 범위' 항목(사유는 **사람이 읽는 문구**로 바꾼다. 예: 내부 오류 문자열 `Multiple versions share the requested effective boundary`를 그대로 노출하지 않는다).
- **주장 표시:** 통합 탭에는 검토 대상(`verification_target`) 주장 중 근거 연결·검토가 필요한 것만 행으로 올린다. 전체 주장 목록은 접힌 보조 목록으로 둔다. **PDF 청구 분할(TK-22)이 해결되기 전에는 주장 행을 켜지 않는다**(조각난 행 방지, 해결 여부는 평가 측이 알린다).
- **쟁점 매트릭스는 합치지 않는다(D1 확정).** 쟁점 작업대·사건 매트릭스·`/claim-assessments`는 별도 '쟁점 정리' 탭으로 유지하고, 통합 탭은 `issue_ids`로 쟁점 필터만 제공한다.
- **호환:** `documents[].findings`, `ai_hallucination_table`, `engine_data.rag`, 보고서(PDF·DOCX·JSON) 필드는 **삭제·이름 변경 금지**, 추가만 한다. 기존 검토 이력(상태·우선순위·담당자·history)은 마이그레이션 후에도 같은 값이다.
- 수용: 서면9 같은 결과 JSON에서 인용당 표시 행 1개, 행별 판정·심각도 단일, **HIGH 이상 finding 전부가 통합 탭 행 또는 고정 안내로 도달 가능**, 기존 검토 이력 보존 시험, JSON 기존 키 불변 시험, 점수·probe 동일, 낙관적 잠금 충돌 시험 유지.

### F3. 참고자료(RAG) 부합성 점검 강화 (규모 대) — F2가 끝난 뒤, 5차 TK-29가 풀린 상태에서
목표: 입력한 서면의 내용이 Drive 참고자료(예: 업무 처리 매뉴얼)에 부합하는지를 **주장 단위로** 추가 점검한다. 학교폭력 매뉴얼은 설명용 예다. **코드·설정·시험 기대값에 분야 낱말을 넣지 않고** 어떤 분야 자료로도 같은 동작이어야 한다(자료 선정은 현행처럼 말뭉치 기준 IDF).
- **F3a 근거 사다리와 위계 표시:** 모든 Drive 출처는 "참고자료(공식 법령·판례 아님, 상위 규범과 충돌할 수 있음)"로 일괄 표시한다. 자료 이름·폴더 낱말로 법령/지침/매뉴얼 유형을 **추측해 분류하지 않는다**(낱말 목록 하드코딩). 불부합은 '참고자료와 다름'이지 '위법'이 아니라는 문구를 고정한다(`authority_limitation` 활용).
- **F3b 주장 단위 검색·대조:** 검토 대상 주장 각각의 문장으로 질의를 만들어(현행 `relevance.py` 점수·임계값 재사용) 관련 발췌(주장당 상한 있음)를 찾고, 현행처럼 **서면 인용문·자료 인용문이 원문에 있는 의견만 채택**한다(`grounded_observations`). 12,000자 한도로 앞부분만 보던 한계는 주장 단위로 풀리지만, 한도·상한에 걸려 **대조하지 못한 주장은 '미대조(사유)'로 표시**하고 `claim_coverage`(검토 대상 주장 N건 중 M건 대조)를 사용자에게 보인다. 현행 문서 단위 경로는 **제거하지 않고** 유지하며, 새 단계는 그 위에 더한다(전후 결과를 비교해 요청서에 보고).
- **F3c 공식 DB 외 존재 확인:** 공식 DB에서 못 찾은 법령·판례 인용이 참고자료 **본문**에 같은 인용(사건번호, 또는 법령명+조문)으로 있으면 `REFERENCE_SUPPORTED`와 출처 링크를 **덧붙인다.** 공식 판정과 심각도는 바꾸지 않는다. 제목 부분 일치·미독 파일로는 올리지 않는다(TK-29 시험 유지). 5차 U1이 정한 일치 규칙을 재사용하고 새 일치 규칙을 만들지 않는다.
- **F3d 출력:** 참고자료 대조 의견은 D4 확정에 따라 **승격 없는 '참고 의견' 행**(배지 구분, 심각도 승격 없음)으로 통합 탭에 노출하고 검토 상태만 기록한다. 서면 인용문·자료 인용문(출처 쪽·Drive 링크 포함)을 함께 보이고, 거부된 의견은 건수만 표시한다. TK-09 후보 승격은 계속 꺼 둔다.
- **F3e 전송·비용(D6 확정):** 모델 호출은 기존 라우터·`external_ai_policy`·전송 전 검사(`llm_router/privacy.py`)를 그대로 거친다. **참고자료 전용 외부 전송 설정을 새로 만들지 않는다.** 참고자료 발췌와 서면 모두 마스킹 대상이다. `LOCAL_ONLY`나 QUICK이면 모델을 부르지 않고 규칙 대조(`provision_quotes`)와 검색 결과만 낸다. 주장 수×발췌 수로 호출이 늘 수 있으므로 상한·배치·호출 수 보고를 둔다.
- **새 결정적 대조 규칙(수치·기한·순서 비교 등)은 이번 범위 밖이다.** 필요하면 `requests/`로 제안한다.
- 수용(오프라인, 가짜 라우터 + 합성 참고자료 라이브러리): 서로 다른 분야의 합성 자료 2세트에서 같은 구조의 동작(주장 단위 연결·`claim_coverage` 정확·참고 의견 행 생성), `LOCAL_ONLY`에서 외부 호출 0, 참고자료 일치가 공식 미발견을 지우지 않음, 제목 부분 일치로 승격 안 됨, 상한 도달 시 미대조 표시, 기존 probe·고정 시험 동일. **실제 모델 대조 품질과 Drive 연동은 오프라인에서 못 잰다(사용자 온라인 재실행으로 확인).**

## 2. 설계 원칙 (이번 라운드 추가)
1. **정보 손실 0.** 화면에서 사라지는 정보는 없다. 이동·통합 전후로 같은 데이터가 어딘가에서 도달 가능해야 한다. HIGH 이상 finding은 언제나 도달 가능해야 한다.
2. **단일 판정.** 같은 대상에 대한 판정·심각도·문구는 서버가 한 번 계산하고 모든 화면이 그 값을 쓴다.
3. **불확실을 확정으로 바꾸지 않는다.** 참고자료·모델 의견으로 확정도를 올리지 않는다. 참고 의견은 참고 의견으로 표시한다.
4. **추가만 한다.** API·JSON은 필드 추가만, 기존 경로 불변. 계약 버전 변화가 있으면 요청서에 적는다.
5. **분야 비종속.** 분야·낱말 목록을 코드·설정·시험에 넣지 않는다. 설명용 예(학교폭력 등)를 구현·시험 기대값에 쓰지 않는다.
6. 사건 값·시험 입력 낱말을 코드에 옮기지 않는다. 표시 문구는 일반 문구로 쓴다.
