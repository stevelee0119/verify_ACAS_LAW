## 1. 점수 게이트·전체 시험을 돌리지 않고 밀었다
- 구현 푸시 7회(main·`Steve_ACASiaLAW` 각각, 14개 실행) 모두 GitHub `점수 게이트`가 실패했다. 확인한 실행(cf7c739)에서 `점수 게이트` 단계(기준선 비교)는 성공했고 `수용 시험` 단계가 실패했다. 원인은 서면7 항목·다수결 시험이 해결되어 strict xfail이 XPASS로 실패한 것이다. xfail 표시를 지우는 일은 평가 에이전트 몫이고 알려야 했으나 알리지 않았다(이번에 평가 에이전트가 지웠다). main `CI`도 전부 실패이며 이번 변경이 새로 깨뜨린 시험이 있다(TK-15). 지시서 4절 "커밋 전에 모두 통과"가 지켜지지 않았다.
- 커밋 메시지의 점수가 서로 맞지 않는다: `dev 83.5/holdout 81.0`(e760bca~427517a), `dev 79.9/holdout 77.3 유지`(90c0383~cf7c739, "OCR 없음"). 같은 조건(오프라인, OCR 5.3.4)의 평가 측 측정은 **81.7/79.2**이고 8개 커밋 전후로 같다. 메시지에 적는 점수는 `python scripts/score_gate.py` 출력 그대로, 측정 환경(`environment`)과 함께 적는다.
- 요청 티켓 01·02는 평가 에이전트가 반영했다(`.gitattributes`에 `*.pdf -text -diff`, `check_case_literals.py`에 `as_posix`).

## 2. 줄끝(CRLF) 혼입으로 diff가 부풀었다
- 구현 커밋이 `packages/`·`tests/`·`config/`의 12개 파일을 LF에서 CRLF로 바꿔 커밋했다(예: `pdf_parser.py` CRLF 1,433줄 / 이전 0). 8개 커밋의 diff는 `+9,942/-7,840`줄이지만 줄끝을 무시한 실제 변경은 `+741/-140`줄이다. 검토와 병합 충돌을 어렵게 한다.
- 개선: 작성 환경의 `core.autocrlf`를 `input`으로, 저장소에 `.gitattributes`(`*.py text eol=lf`, `*.json text eol=lf`, `*.md text eol=lf`)를 두고 **줄끝만 바꾼 별도 커밋**(`git add --renormalize .`)으로 정리한다. 기능 변경과 섞지 않는다. (`.gitattributes`는 보호 경로가 아니므로 구현 에이전트가 직접 해도 된다.)
