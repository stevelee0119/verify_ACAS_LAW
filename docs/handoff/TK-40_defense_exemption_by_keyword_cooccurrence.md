# TK-40 법리 과대주장 경고를 "요건 낱말 + 한정 결론 낱말" 공존으로 면제함
- 유형: 회귀(법리 검토, **P1**) + 지시 위반 소지 · 기준: 6차 최종 01070f6 · 작성: evaluator 2026-10-03 · 근거: 6차 독립 감사 R6-02 + 평가 측 독립 재현 · 상세: [AUDIT_REVIEW_ROUND6](AUDIT_REVIEW_ROUND6.md)

## 증상·증거(평가 측 재현, 문장은 평가 측이 지음)
| 집합 | 기대 | 시작 96019c3 | 최종 01070f6 |
|---|---|---:|---:|
| 요건을 부정·미충족으로 적고 한정 결론을 낸 문장 6(예: 변제공탁을 전혀 하지 않았으나 … 책임을 질 수 없다) | 경고 유지 | 4 | **0** |
| 민사 요건 제시 후 형사·징계책임까지 확장한 결론 4 | 경고 유지 | 3 | **1** |
| 요건을 구체적으로 제시하고 해당 채무로 한정한 정상 항변 5 | 경고 없음 | 3(오탐 2) | **5** (개선) |
- 원인: `legal_rules.py`(`GEN.DEFENSE_OVERCLAIM_WITHOUT_REQUIREMENTS` 제외 분기 297행 부근)가 `config/legal_defense_groups.json`의 `stated_requirements`(17)·`limited_conclusions`(5) 패턴이 **한 문장에 함께 나타나면** 경고를 지운다. "변제공탁"이라는 낱말이 있으면 **그 요건을 부정·미충족으로 적었어도** 면제된다. 다른 책임(형사·징계)으로 확장했는지, 누구의 주장인지(상대방 주장 인용·재반박)도 보지 않는다. 유일한 예외는 `전면 면책|당연무효|전액 면제` 낱말뿐이다.
- 6차 지시서 R3 개선 (2)는 **"경고를 없애는 예외 문장 목록 추가"를 금지**했다. 구현 보고서는 이를 "구조 신호 보강"이라 기록했다. 자동 하드코딩 검사는 시험 입력 값의 유입만 보므로 통과했다(의미상 면제 낱말 목록은 수동 검토 대상).

## 요구(7차 R2)
1. **낱말 공존이 아니라 구조**로 판정한다: (a) 요건이 **긍정적으로 주장·소명**되었는가(부정·미충족·"하지 않았으나" 표현이면 요건 제시로 보지 않는다), (b) **발화 주체**(자기 주장인가, 상대방 주장 인용·재반박인가), (c) 결론의 **책임 범위**(해당 채무 한정인가, 다른 책임까지 확장인가).
2. 판단이 불확실하면 **경고를 지우지 않고 "요건 확인 요청"으로 낮춰 표시**한다(없애는 쪽이 아니라 낮추는 쪽). 확정적 면제는 위 (a)(b)(c)가 모두 구조로 확인될 때만이다.
3. 새 낱말 면제 목록을 늘리지 않는다. 기존 `stated_requirements`·`limited_conclusions`가 구조 판정의 보조 신호로 남는다면 그 역할과 한계를 설정 설명에 적는다. 새 `rule_id` 금지.
4. 편·장 정정의 근거: `basis`에 원문 URL(`source_url`)과 확인일(`verified_at`)을 기록한다(감사 §5-8, 확인한 것만).

## 수용
평가 측 R6-02 시험(요건 부정 4건·타 책임 확장 2건 strict xfail → XPASS, 확장 보존 1건·정상 항변 5건 통과 유지), 기존 정상 항변 오탐 5건(감사 표본)의 해소 여부 보고, 구현 측 새 시험은 **3종 세트**(고칠 입력 / 비슷하지만 결론이 다른 입력 / 이전 성공)로 요건 부정·인용·상대방 주장·재반박을 각 2건 이상 포함.
