## 2. 영향
- 가림·전송 차단에는 영향 없음(같은 자리가 가려진다).
- 보고서와 화면의 개인정보 종류 요약에 없는 '주민등록번호 1건'이 표시된다. 사용자가 원문에 주민등록번호가 있다고 오인할 수 있다.
- 필수 보장(연락처·주민등록번호 누락 0)과는 별개다. TK-57 해소 기록의 '종류 표시 부정확(게이트 밖)'에 해당하는 사례가 실제 문서에서 확인된 것이다.

## 3. 요구
- 낱말·형태 목록을 늘리지 말고 규칙으로 고친다. **앞 6자리 안에 공백이 아닌 구분 기호(하이픈·줄표류·가운뎃점 등)가 있으면 RRN으로 분류하지 않는다**(예: 3-4-4-2 계좌). 이때 앞 문맥에 기존 계좌 라벨('계좌·은행·입금' 등)이 있으면 ACCOUNT로 분류한다.
- 앞 6자리 안의 공백·줄바꿈(OCR식 숫자 사이 공백)은 지금처럼 허용한다. 6자리 뒤 7자리는 지금처럼 묶음 모양을 따지지 않는다.
- 날짜 유효성·검증 숫자로 걸러내지 않는다. 기존 시험과 평가 측 세트는 지어낸 번호(월·일이 성립하지 않는 값 포함)를 쓴다.
- 가림 구간과 차단 동작은 바꾸지 않는다.
- 지시 사전 점검(평가 측): 기존 시험 `tests/regression/test_r8f_contact_rrn.py`(전각·`000000 –\n1 000 000`·`000000·1·000·000`)와 `tests/regression/test_r8f1_rrn_linebreak.py`의 RRN 기대값은 모두 앞 6자리가 붙어 있어 이 규칙과 충돌하지 않는다. 이 시험들은 고치지 않는다. 평가 측 비공개 세트 1·2·3판의 주민등록번호 표기도 앞 6자리 안에 공백 외 구분 기호가 없다(구조만 확인, 입력 비공개).
