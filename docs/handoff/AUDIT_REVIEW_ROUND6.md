## 1. 판정
**감사의 핵심 결론은 타당하다.** 6차는 지시서의 고정 입력 22건을 해결하고 dev 점수를 회복했으나(인정), **새 회귀 4건**이 있어 완료 승인할 수 없다. 0.9.14 릴리스·기준선 갱신 보류, F1 제품 구현 보류에 동의한다. 감사의 주요 재현 4건(R6-01~04)은 평가 측 독립 입력으로 모두 방향이 같게 재현됐다(규모는 입력이 달라 다르다). 다음은 평가 측이 감사에 **더하는** 판단이다.
1. 6차 R3이 도입한 `stated_requirements`(17)·`limited_conclusions`(5) 설정은 6차 지시서가 금지한 **"경고를 없애는 예외 낱말 목록"** 이다(지시서 R3 개선 (2)). 구현 보고서는 이를 "구조 신호 보강"이라고 불렀다. 낱말 공존으로 경고를 지우므로 R6-02가 생겼다.
2. 6차 ledger의 줄 결합 시험 19건은 **모두 "붙여라" 한 방향**이다. 반대 방향("공백을 지켜라")이 없어 R6-03이 시험에 걸리지 않았다.
3. 구현 측이 "전체 시험 새 실패 0"이라 보고했으나 기존 시험 1건이 새로 실패한다(R6-04). 구현 브랜치 푸시에는 `점수 게이트`만 돌고 전체 시험(CI)은 돌지 않아, 게이트의 수용 시험 단계가 22 XPASS로 먼저 실패하자 이후 회귀·하드코딩·버전 단계가 건너뛰어진 채 가려졌다. 이는 **평가 측 인프라의 결함**이다(6절에서 고침).

## 4. 감사와 다른 점
- 감사는 "개발 과정이 정상"이라 평가한다. 평가 측은 **같은 유형(한 방향 기본값, 낱말 예외 추가)이 5차·6차에 연속 재발**했다는 점을 더해, 7차에 **시험 설계 규칙**(고칠 입력 / 비슷하지만 다른 결론 / 이전 성공의 3종 세트, 실제 소비 경로, 커밋마다 전체 시험)을 지시서의 필수 항목으로 넣는다.
- 감사는 xfail 승격을 "평가 담당자 요청 처리"로 다뤘다. 평가 측 책임 지연을 인정한다: 구현 측이 22 XPASS를 보고한 뒤에도 승격이 반영되지 않아 `점수 게이트`가 5차부터 계속 빨갰고 신호가 약해졌다. 승격 패치는 준비·검증을 마쳤다(8절).

## 6. 6차 회귀 보호 시험과 승격 패치(병합 대기)
- `docs/handoff/staged/test_round6_regressions.py.txt`: R6-01~03의 보호 시험(strict xfail 40건 + 대조 일반 시험). **시작 96019c3에서는 표시된 회귀 시험이 모두 통과하고(--runxfail), 최종 01070f6에서는 모두 의도대로 실패(xfail)** 함을 확인했다. 시작에서 실패하는 3건은 6차의 정당한 개선(정상 항변 오탐 2건 해소, 법원명 결합)이다.
