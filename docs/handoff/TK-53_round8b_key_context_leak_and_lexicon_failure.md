## 2. 키 문맥이 과마스킹을 다시 요청 차단으로 바꿈 (P2, 가용성)
- **측정:** 사람 이름 없는 정상 구조화 요청 대조에서 차단은 81cdcc4 6건 → 44e73f9 14건 → **170c647 8/28**이다. 기준(6 이하)을 넘는다.
- **초과 2건:** 같은 사례가 user·system 두 위치에서 막혔다. 라벨 키의 값이 장소·직무 명사로 시작하는 경우다.
  - `detect()`는 시작 시점부터 이 문장을 PERSON으로 봤다(TK-43 과마스킹).
  - 8B가 라벨 키에 `키: 값` 문맥을 붙이면서 그 과마스킹이 요청 차단으로 이어졌다.
- 나머지 6건(법인 상호 값, 법인을 가리키는 사건 서술)은 시작과 같다.
- **요구:** 키 문맥은 **값이 이름 꼴일 때만** 붙인다. 이름 꼴이란 성씨로 시작하는 2~4음절 단일 토큰, 또는 그 뒤에 호칭·괄호가 붙은 형태다. 그 밖에는 원래 값만 검사한다. 판단이 서지 않으면 막는다.
