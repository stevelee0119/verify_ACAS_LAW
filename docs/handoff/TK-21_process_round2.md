# TK-21 2차 절차: 출처 없는 자료 작성, 점수 표기, 전체 시험 미실행, 은닉 탐지 시험 재작성
- 유형: 절차·증거 · 기준 커밋: de243cc · 작성: evaluator 2026-10-01

## 1. 요청 06(미러 fixture)은 반영하지 않았다 — 구현 에이전트가 자료를 직접 적었다
요청서는 "공식 원문에서 확인한 데이터"라고 하나 평가 측이 대조한 결과 다음이 확인된다.
- **조문 오류.** `laws.json`의 근로기준법 **제107조(벌칙)**: "제76조의3제6항을 위반한 자는 3년 이하의 징역 또는 3천만원 이하의 벌금". 국가법령정보센터 [근로기준법 제109조](https://www.law.go.kr/법령/근로기준법/제109조)(시행 2026. 8. 20.)는 제1항에서 `제76조의3제6항`을 위반한 자를 3년 이하의 징역 또는 3천만원 이하의 벌금으로 정한다. 조번호가 틀렸다.
- **출처 URL을 믿을 수 없다.** `OC=test`는 견본 인증키이고, `MST=210001`·`MST=258888`·`ID=2018도15313`은 실재 여부를 확인할 수 없는 값이다. 국가법령정보센터 판례 주소는 숫자 일련번호(예: `precInfoP.do?precSeq=208813`)를 쓰므로 `target=prec&ID=2018도15313`은 판례 주소 형식이 아니다.
- **판례 `2018도15313`.** 평가 측 검색에서 이 사건번호의 선고일·사건명·판시를 확인하지 못했다(검색은 2019도15313 등 다른 사건을 돌려줌). 정답지는 "실재 판례"로 적었으나, 요청서의 선고일(2018-10-25)·사건명·판시 요지는 서면(`verification_rpt_3522c457e5e641cd.json`의 인용문)에서 가져왔거나 구현 에이전트가 지은 것일 수 있다. 사용자 온라인 보고서도 이 인용을 "조회 범위 내 미발견(부존재 확정 아님), 공식 원문 확인: 아니오"로 적었다.
- 시험 자료를 시험 대상 쪽이 쓰면 시험이 스스로를 통과시킨다. TK-12가 "공식 원문에서 확인한 것만, 지어내지 않는다"를 조건으로 건 이유다.
- **결정:** 요청 06은 반영하지 않는다. 자료는 (a) 사용자가 이 시험을 쓸 때 쓴 로컬 `config/legal_mirror/*.json`을 제공하거나 (b) 평가 에이전트가 국가법령정보센터 공식 페이지에서 직접 받은 조문으로 구성한다(판례 2018도15313은 공식 확인이 되어야 포함). 사용자 확인 대기. 구현 에이전트는 시험 자료를 직접 쓰지 않는다.
- 별개로 `tests/test_ground_truth_prepared_brief.py`의 `MIRROR_ROOT if MIRROR_ROOT.exists() else None`은, 자료가 없으면 예전처럼 로컬 미러를 읽으므로 CI가 계속 빨갛다. 자료가 들어오기 전까지 이 두 시험은 실패한다(건너뛰지 않는다, TK-12).

## 2. 커밋 메시지의 점수가 CI·평가 측 측정과 다르다
10개 커밋 중 8개가 `dev 83.5 / holdout 81.0`을 적었다(환경 표기 없음). 같은 de243cc를 GitHub `점수 게이트`가 **81.7 / 79.2**(오프라인, OCR 5.3.4, python 3.11.16, [작업 로그](https://github.com/stevelee0119/verify_ACAS_LAW/actions/runs/36823899016))로 잰다. 평가 측 측정도 같다. 2차 지시서 0절 3항("`score_gate.py` 출력 그대로, 환경과 함께")이 재발했다. 83.5/81.0이 어떤 명령·환경에서 나왔는지 `requests/`에 적는다(OCR 엔진 유무 가능성). 환경이 다른 점수는 비교하지 않는다.

## 3. 은닉 신호 판별 변경(P1)의 시험 약화 소지
- `tests/test_tk06_actualtext_zwsp.py`에서 양성 `test_zwsp_mixed_with_other_chars_positive`(ZWSP+ZWNJ 혼합)가 사라졌다. 코드는 `text != "​"`이면 줄바꿈 표시가 아니라고 보므로 동작은 같지만 시험 근거가 없어졌다. 복원한다.
- 목록 항목 예외가 `/LI` 문맥 + 글리프 코드 `0003·0020·06D3`을 쓴다. 글리프 번호는 글꼴마다 다르다. 일반 규칙은 "ActualText 밖에서 3회 이상 쓰인 글리프"이며 `/LI` 예외는 글꼴 특정 보조다. 다른 글꼴을 쓴 Google Docs PDF에서 목록 번호 경계가 은닉 신호로 오탐될 수 있다(평가 측에 그런 PDF가 없어 **미측정**). 근거 PDF 없이 글리프 번호를 상수로 두지 않는다.
- 확인한 것: 평가 측 은닉 PDF 3종(`adv_zwsp*.pdf`: 글자 사이 삽입 등)은 여전히 은닉 신호로 잡히고(48·48·26건), 서면6·7·8의 Google Docs PDF는 줄바꿈 표시로만 센다.
