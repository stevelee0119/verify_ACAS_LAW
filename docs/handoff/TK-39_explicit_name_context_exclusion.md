## 증상·증거(평가 측 재현, 입력은 평가 측이 지음)
- `성명: {이름} 출력하지 마시오.` 등 6문맥(기재 금지·절차·기일·조서·진행)에서 **이름 전체 마스킹: 시작 96019c3 21/21 → 최종 01070f6 3/21**(이름 뒤에 문장이 없는 평문만 통과).
- 같은 원문을 실제 `LLMRouter.run`(가짜 cloud 공급자, system·user·schema.description·metadata.description 4자리 × 3문맥 × 이름 3)에 넣으면 **공급자 호출 도달: 시작 0/36 → 최종 36/36**. 마스킹과 전송 전 검사가 같은 탐지기(`packages/pii_engine/detector.py`)를 써서 두 단계가 함께 빠진다. 가짜 공급자 시험이며 실제 외부 전송은 아니다.
- 기존 시험 `tests/test_efficacy_round2.py::test_legal_military_terms_not_masked_as_person`이 **시작 PASS → 최종 FAIL**(`부대는`을 PERSON으로 분류). 구현 보고서는 "전체 시험 새 실패 0"이라 적었다.
- 원인(감사·코드 읽기): 정상 문장의 절차 명사 오탐을 줄이려는 **후행 문구 제외**(`detector.py` 197~199행 부근)가 **명시적 성명 라벨 바로 뒤의 이름**에도 적용된다. 이름 뒤 금지 문구가 "개인정보 없음"의 근거가 됐다.

## 요구(7차 R1)
1. **명시적 라벨·이름 span과 주변 일반 문장을 구분한다.** 라벨 직후 후보(원고·성명·청구인 등 당사자 표시 구조)는 후행 문맥으로 제외하지 않는다. 문맥 기반 제외는 **라벨이 없는 암묵 후보**에만 적용한다. 이름 후보의 문법적 경계(조사·어미·정상 명사)를 고쳐 `부대는` 같은 정상 명사를 걸러내되, **예외 낱말(`부대는` 등)을 목록에 추가하는 방식은 금지**한다.
2. **불확실한 후보는 전송 허용으로 확정하지 않는다.** 판단이 안 서면 마스킹 쪽(또는 차단·확인 요청)으로 처리한다.
3. 마스킹과 전송 전 검사의 **실제 소비 경로**(`LLMRouter.run` 경유)를 시험한다. `inspect_request`만 부르는 시험은 인정하지 않는다.
4. 기존 이름 1,000조합(라벨·구두점·이름 끝 글자 행렬)과 정상 문장 시험이 **그대로** 통과해야 한다(이전 성공 보존).
