# TK-41 줄 결합이 한 방향 기본값이며 같은 문단이 쪽 배치에 따라 다르게 결합됨
- 유형: 회귀(입력 계층, P2) · 기준: 6차 최종 01070f6 · 작성: evaluator 2026-10-03 · 근거: 6차 독립 감사 R6-03 + 평가 측 독립 재현 · 상세: [AUDIT_REVIEW_ROUND6](AUDIT_REVIEW_ROUND6.md)

## 증상·증거(평가 측 재현)
- `join_lines` 직접 쌍 10개(기본 호출): 시작 6/10 → 최종 4/10. `(이|사건)`·`(해당|채무)`·`(위|계약)`이 `(이사건)`·`(해당채무)`·`(위계약)`으로 **공백이 삭제**됐다(신규). `(대|법원)`은 붙게 되어 개선(TK-31 대상). `손해배|상책임`처럼 어절 중간 분절은 시작·최종 모두 공백이 끼는 기존 미해결이다.
- **두 경우는 글자만으로 구별할 수 없다**(`(대|법원)` = 어절 중간, `(이|사건)` = 어절 경계). 6차 구현은 "괄호 뒤 한글 1~2음절이면 붙인다"를 기본값으로 삼아 한쪽을 고치고 다른 쪽을 깼다. 5차에서 지적한 "한 방향 기본값" 오류의 재발이다.
- 쪽 배치 의존: 같은 두 줄 문단이 같은 쪽의 **다른 문단에 꽉 찬 줄이 2줄 이상**이면 `그 사람` → `그사람`으로 달라진다(시작은 항상 `그 사람`). 코드(`reconstruct_page_blocks`)가 쪽 전체 블록의 `x1` 분포로 `is_char_wrap_page`를 정해 모든 문단에 적용한다.
- 6차 ledger의 "Google Docs PDF 19개 패턴" 시험은 PDF가 아니라 문자열 쌍이며 **19개 모두 '붙여라'** 한 방향이다.

## 요구(7차 R3)
1. **텍스트만으로 구별되지 않는 경계는 기본값으로 확정하지 않는다.** 레이아웃 신호(글자 사이 간격·공백 글리프·줄 끝 x 좌표와 그 줄이 속한 **문단·줄 단위** 폭 분포)로 결정하고, 신호가 없으면 **불확실로 보존**한다(예: 두 결합 후보를 모두 남기거나 원문 span을 유지하고 인용 추출·검증은 후보를 모두 시도).
2. **같은 문단의 결합 결과는 다른 문단의 배치에 의존하지 않는다**(쪽 단위 문맥 판정 금지). 근거는 해당 문단의 줄들에서만 얻는다. 정규화 텍스트와 원문 위치의 대응은 유지한다.
3. 시험은 **양방향**이다: 붙여야 하는 쌍과 공백을 지켜야 하는 쌍을 같은 수로 둔다. 실제 PDF(글자 좌표) 경로 시험을 포함한다.
4. 보존: 실제 Google Docs PDF 청구 47·검증 대상 19·제22조 문장 1개, TC-06 법원명·선고일, 법령명 띄어쓰기, 합성 PDF 폭 변형 9건.

## 수용
평가 측 R6-03 시험(괄호 뒤 짧은 어절 3건·쪽 배치 불변성 1건 strict xfail → XPASS, 어절 경계 3건·법원명 결합 1건 통과 유지), 고정 dev ≥ 81.7·holdout ≥ 79.2 유지(환경 명시), 구현 측 새 시험에 양방향 쌍과 실제 PDF 경로 포함.
