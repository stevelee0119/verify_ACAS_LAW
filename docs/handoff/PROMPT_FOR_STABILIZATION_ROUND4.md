## 0. 이번 라운드의 성격과 어길 수 없는 규칙

**목적은 새 기능·새 규칙이 아니라 안정화다.** 기존 기능을 보완하고, 고쳤던 결함이 되살아나지 않게 하고, 점수를 올리려는 하드코딩을 원천 배제한다.

**A. 동결(Freeze).** 이번 라운드에는 다음을 하지 않는다. 필요하면 `docs/handoff/requests/NN_제목.md`에 (무엇이·왜·제안) 세 줄로 올리고 사용자 승인을 기다린다.
새 `rule_id`, 새 탐지 유형(FindingType), 새 설정 파일, 새 패턴·용어 목록의 단순 추가, 새 탐지 기능. 목록은 **체계로 닫는 정리**(예: 헌법 제2장 전체)에 한해 평가 측 승인 후 바꾼다. TK-24(새 규칙이 필요)는 이번 라운드 대상이 아니다.

**B. 점수 인위 상승·하드코딩 금지(원천 배제).** 아래는 **하지 않는다**. 하나라도 있으면 그 커밋은 되돌리고, 기계 점검(4절)이 먼저 걸러 낸다.
1. 시험 입력·정답지·티켓·명세(`tests/fixtures`, `docs/handoff`)의 낱말·문장·조문 번호·식별자·값·구분자를 코드·설정의 키·목록·정규식·메시지에 옮기는 것. 이미 본 서면(서면6~9·변형)도 마찬가지다.
2. 특정 서면을 알아보는 분기: 파일명·해시·문서 길이·제목·사건번호·고정 문자열로 동작을 바꾸는 것.
3. 시험·채점 환경을 알아보는 분기(`PYTEST_CURRENT_TEST`, probe·scorecard 호출 여부, 환경변수).
4. 채점 명세에 맞춘 출력: 점검 항목의 정답 낱말이 finding 본문에 들어가도록 문구를 넣는 것.
5. 시험 기대값을 바꿔 통과시키기, 시험 skip, `xfail` 임의 추가·삭제, 보호 경로 수정, 기준선(`baseline.json`) 수정.
6. 불확실을 확정으로, 경고를 지워서 점수를 맞추는 것(오탐 대조군을 약하게 만드는 것 포함).
7. 같은 결함을 소비자(인용·법리·시점·주장…)마다 따로 땜질하는 것.
8. 점수 보고에서 환경을 적지 않거나 유리한 환경을 고르는 것.
어휘를 늘려야 한다면 **한 설정 파일에, 법·체계로 닫힌 집합으로** 하고, 시험에 나온 몇 개만 고른 부분집합은 만들지 않는다. 평가 측이 `tests/acceptance/hardcoding_allow.json`에 사유와 함께 올려야 승인이다.

**C. 회귀 방지 원칙.**
- R1 **고친 결함은 고정한다.** 결함을 고칠 때마다 (재현 입력 + 정상 대조군)을 `tests/regression/`(구현 측 소관, 새 폴더)에 영구 시험으로 둔다. 입력은 구현 측이 새로 짓는다. 시작할 때 TK-01~TK-27에서 이미 고친 결함의 재현 입력을 모은 **회귀 원장**(`tests/regression/test_ledger.py`, 표 형태: 티켓·입력·기대)을 먼저 만든다.
- R2 **커밋마다** `python scripts/regression_gate.py --base HEAD~1`이 통과해야 한다(전에 통과하던 항목이 떨어지면 실패). 푸시 전에는 `--pytest`까지.
- R3 **불확실성 단조.** 변경이 UNVERIFIED·INFO를 VERIFIED나 더 높은 확신으로 바꾸려면 반례(대조군) 시험이 먼저 있어야 한다. 후보가 여럿이면 임의로 하나를 고르지 않는다.
- R4 한 입력 문제는 **입력 계층 한 곳**에서 고친다. 소비자별 땜질 금지.
- R5 **한 커밋은 한 원인.** 커밋 메시지에 원인·바꾼 파일·새 시험·게이트 출력을 적는다.
- R6 기존 시험이 새 동작과 충돌하면 조용히 붉게 두지 않는다. 옛 정책 시험이면 갱신(근거 주석), 정책 충돌이면 `requests/`에 알리고 시험은 그대로 둔다.

**D. 기본.** 보호 경로(`tests/acceptance/`, `tests/fixtures/`, `scripts/*`의 평가 도구, `.github/`, `docs/scorecards/`)는 수정하지 않는다. 시험 자료는 쓰지 않는다. 출처 미확인 법령·판례 정보는 코드·자료·주석에 쓰지 않는다. 강제 푸시 금지. 읽는 순서: `AGENTS.md` → 이 문서 → `docs/handoff/TK-19`~`TK-27`.

## 3. 일반화·안정화 설계 원칙
1. 표현이 아니라 **역할·구조**를 잡는다. 어휘는 의도·법리 **군집별로, 설정 한 곳에**.

4. 여러 약한 신호의 합산과 필수 조건을 구분하고, 단일 신호로 HIGH를 내지 않는다. 대조군을 먼저 쓴다.
5. 불확실은 불확실로 표시한다(R3).

## 4. 검증 명령 (커밋마다 1~5, 푸시 전에 전부)
```
python scripts/regression_gate.py --base HEAD~1                      # 1. 항목 단위 회귀 (푸시 전에는 --base <푸시 전 원격 커밋> --pytest)
python scripts/check_hardcoding_diff.py --base HEAD~1                # 2. 추가된 줄의 시험 입력 값·조문 번호·새 규칙

python scripts/scorecard.py && python scripts/score_gate.py          # 4. 기준 79.9/77.3 이상, 오탐 0 (환경을 함께 적는다)
python -m pytest -q tests/regression                                 # 5. 회귀 원장
python -m pytest tests/acceptance -q -rxX                            # 현재 xfail 16건(서면9 6·TK-26 8·TK-27 2). XPASS 실패는 requests로 알림
python -m pytest -q --ignore=tests/acceptance                        # 실패는 TK-12 2·사업자번호 정책 1·환경 1 외 0, 커밋별로 새 실패 0
python scripts/probe_document.py run --spec tests/fixtures/probes/<spec>.json [--text]   # 서면6 20/20·7 25/25·8 22/22·9 27/28·변형1 24/24·변형2 21/21 유지
```
`check_hardcoding_diff.py`의 **강한 신호**는 평가 측 승인 전까지 실패로 본다. **새 규칙(rule_id)** 은 이번 라운드에 0개여야 한다.
