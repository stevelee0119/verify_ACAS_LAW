# TK-46 명시 성명의 끝 음절을 조사로 떼어 앞부분이 일반 불용어면 이름 전체를 제외함 (7차 R1이 만든 P1 회귀)
- 유형: 회귀(개인정보, **P1**) · 기준: 7차 최종 4da3910(시작 7adf43f에서는 마스킹) · 작성: evaluator 2026-10-03 · 근거: 독립 감사 Astra A7-01 + 평가 측 재현([AUDIT_REVIEW_ROUND7](AUDIT_REVIEW_ROUND7.md))

## 증상·증거
- 공개 재현(합성 이름, 실제 인물 아님): **`성명: 임용은`**. 시작은 전체 마스킹, 4da3910은 PERSON 없음. 감사: 실제 `LLMRouter.run`의 system/user/schema/metadata 네 필드 모두에서 가짜 공급자까지 도달.
- 원인: `detector.py`의 라벨 문맥 인명 루프가 후보 전체를 평가하기 전에 `josa_match`로 끝 음절(`은·는·이·가·을·를·의·과·와·도·로`)을 떼어 `stem`을 `PARTY_HEADER_STOPWORDS`·`LEGAL_MILITARY_STOPWORDS`·`REPRESENTATIVE_NAME_STOPWORDS`와 비교해 제외한다. 이는 `피고 부대는`의 `부대`를 걸러내려는 7차 R1의 장치인데, **명시 성명 라벨 직후의 유효한 전체 이름 후보(`임용은` = 성 `임` + 이름 `용은`)도 같은 검사로 지워진다.**
- 평가 측 합성 확인: 불용어 목록의 2음절 stem(성씨로 시작) × 조사형 끝 음절 11종 = 605개 후보 중 시작 572 마스킹(33은 `선임·선출…` 기존 제외) → **4da3910 0**. 감사의 비공개 조합은 81 → 54(이전 성공 27개 회귀, 이름 잔존 + 공급자 도달 27). 평가 측 기존 비공개 이름 변형(330)에는 이 계열이 없어 놓쳤다.

## 요구
1. **명시 성명 라벨의 유효한 전체 이름 후보를 stem 불용어 검사 전에 보존**한다. 끝 음절이 실제 조사인지 이름의 일부인지 확정할 수 없으면 확정하지 말고 전체 후보를 이름으로 보존한다(마스킹 쪽으로 불확실을 처리하되, 전송은 막는 쪽).
2. `피고 부대는`·`원고 부사관은` 같은 **문장 속 일반명사**(성명 표지가 없는 라벨 뒤)는 계속 이름이 아니어야 한다 — 성명 표지 여부로 두 경로를 구분한다(TK-43의 완화 범위와 같은 구분을 쓴다). **이름 하나를 예외 목록에 넣는 해결은 인정하지 않는다.**
3. 마스킹과 전송 전 검사(`inspect_request`)가 같은 구조 결과를 소비한다.
