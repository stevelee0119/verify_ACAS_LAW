# TK-52 8차(774aa5a·44e73f9)가 만든 두 결함 — 조사 재귀 분리로 실명 누락(유출), 문맥 결합으로 정상 요청 과차단 + 과마스킹 일반화 실패 (P1/P2)
- 유형: 회귀(개인정보 유출, **P1**) + 가용성(과차단, P2) + 일반화 실패(과마스킹) · 기준: `antigravity/round8-privacy-boundary` 44e73f9(시작 81cdcc4) · 작성: evaluator 2026-10-03 · 근거: 평가 측 독립 측정(HISTORY 17절)

## 1. 조사 재귀 분리로 명시 성명 계열 실명이 빠짐 (P1, 유출 방향)
- `detect()`가 후보의 꼬리 조사를 **최대 3회** 떼어 가며 불용어를 찾는다(R8-B). 이름 끝 음절이 조사처럼 보이고(은·는·이·가·도…) 앞 두 음절이 불용어인 실명에 조사가 붙으면, 두 번째 분리에서 불용어에 걸려 **이름 전체가 PERSON에서 빠진다**.
- 평가 측 비공개 명시 성명 stem 계열(16): 81cdcc4 **16/16 → 44e73f9 9/16**. 빠진 7건은 모두 `{당사자 라벨} {이름}{조사} …` 형식(성명 표지 형식은 유지). 보호 시험 R7-07은 통과한다(입력 형식이 다름).
- 8차 지시서 0절 2(유출 0 하한)·R8-B 2('불용어 판정이 실명을 지우지 않는지 반드시 같이 본다')에 어긋난다.
- 요구: 조사 분리는 **한 번만**(7C 이전 동작) 하거나, 분리 전 후보 전체가 이름 구조(성씨+이름 음절 수)를 만족하면 불용어 판정을 하지 않는다. 판단이 서지 않으면 마스킹.

## 2. 문맥 결합이 과마스킹을 요청 차단으로 키움 (P2, 가용성)
- R8-A가 모든 키에 `키: 값`, 형제 값 이어 붙이기, 배열 이웃 이어 붙이기를 검사하면서, `detect()`의 라벨 뒤 일반 명사 과탐지(TK-43)가 **요청 전체 차단(NOT_SENT)** 으로 번진다. 평가 측 대조(사람 이름이 없는 정상 구조화 요청 28건): 81cdcc4 **6/28 → 44e73f9 14/28 차단**. 차단 유형(평가 측 입력 문장은 공개하지 않는다): 라벨 키의 값이 장소·직무 명사로 시작하는 경우, 법인 표지(사단법인 등)로 시작하는 경우, 라벨 낱말만 나열한 배열(이웃 결합이 두 라벨을 4음절 이름으로 읽음), '○○ 측' 같은 지칭 표현.
- 8차 지시서 R8-A 5('사람이 아닌 당사자 값과 사건 서술 값은 차단하지 않는다')를 충족하지 못했다. 유출 0 하한의 방향(과차단)이라 P2로 둔다.
- `CONTEXT_LABEL_KEYS`(detector 라벨 단일 출처)는 정의만 있고 쓰이지 않는다(모든 키에 문맥을 붙이는 방식이라 필요 없음) — 보고서의 '단일 출처' 서술과 다르다. 쓰거나 지운다.
- 요구: 형제·이웃 결합은 **라벨 값 다음에 이름 구조 값이 올 때만** 문맥을 만들거나, 결합 문맥의 탐지는 라벨 직후 후보에 한정한다. 비인명 당사자 값(법인·기관·지자체·'○○ 측')과 사건 서술 대조 시험을 구현 측이 새로 지어 넣는다.

## 3. 과마스킹 축소가 보호 시험 낱말에만 맞음 (일반화 실패)
- 추가 불용어 80개 중 보호 시험 R7-02·R7-10의 첫 낱말 **6개 전부**(`진술`·`심문`·`계정`·`서명`·`지시`·`의견`)가 들어 있다(보고서가 겹침을 밝혔다 — 규칙 준수). `계정`·`지시`·`의견`은 붙인 범주(권리·의무·법률 행위, 증거법 용어)에 잘 맞지 않는다.
- 평가 측 **새 비공개 세트**(보호 시험·이전 세트와 다른 명사): 새 라벨 + 일반 명사 **70/140 → 60/140**, 기존 당사자 라벨 + 일반 명사 **48/112 → 48/112** — 수용 기준 각 ≤ 10%에 크게 못 미친다. 보호 시험만 통과하고 처음 보는 명사에서는 거의 줄지 않았다.
- 요구: 범주를 실제로 넓히는 방식(예: 범주별로 공신력 있는 어휘 출처를 정해 일괄 반영)이나 다른 구조 신호가 필요하다. 형태소 분석기 등 새 의존성은 8차 지시서 R8-B 3대로 먼저 제안한다.
