# FR-01 검토 화면 중복 해소와 참고자료(RAG) 활용 강화 — 타당성 검토

작성: 평가 에이전트(claude-code) 2026-10-02 · 요청자: 사용자 · 대상 코드: `Steve_ACASiaLAW`(4차 구현 e6b58fd 포함, 제품 코드는 읽기만) · 후속: [작업 지시서](PROMPT_FOR_FEATURE_ROUND_F1.md)
범위: 사용자가 제시한 세 가지(① AI 탭 축소, ② 확인할 항목+주장·쟁점 통합, ③ Drive 참고자료의 법리 검토 활용)만 검토한다. 그 밖의 개선 요청은 다루지 않는다.

## 1. 결론
| 제안 | 판정 | 규모 | 한 줄 사유 |
|---|---|---|---|
| ① AI 탭을 'AI 생성 진단'과 '프롬프트 인젝션'만으로 축소 | **타당** | 소 | 이미 화면 제목이 "AI 작성 여부 판단과 별개"라 쓰고 있어 분리가 설계 의도와 맞다. 데이터 변경 없이 화면 이동으로 가능 |
| ② 확인할 항목 + 주장·쟁점을 판례 인용표 형식으로 통합 | **조건부 타당** | 중~대 | 중복과 표기 불일치가 실측으로 확인된다. 다만 '주장·쟁점' 탭에는 쟁점 매트릭스·변호사 평가 저장 기능이 있어 **통째로 합치면 안 된다**. 행마다 검토 상태를 저장할 ID가 없는 점도 먼저 풀어야 한다 |
| ③ Drive 참고자료를 법리 타당성·부합성 점검에 활용 | **방향 타당, 일부는 이미 구현, 확장 필요** | 대 | 검색·대조 골격은 있으나 문서 단위 검색이라 실측 주장 대조율이 1/17이다. 공식 DB의 대체가 될 수 없고 규범 위계 표시가 필요하다 |

**권장 순서:** 5차 안정화 검증 뒤 ①→②→③. ②의 청구 표시는 TK-22(PDF 청구 분할), ③은 TK-29(참고자료 일치 회귀)가 먼저 풀려 있어야 한다.

## 2. 현황 근거
### 2.1 중복·불일치의 실측 (서면9 온라인 보고서 1건, 3차 코드 9933548, 평가 측 JSON 분석)
- '확인할 항목' finding 13건 중 **7건이 AI·보안 유형**이다(AI 작성 참고 신호 4, AI 전체 생성 의심 1, 프롬프트 인젝션 1, 작성자 메타데이터 1). 법률·인용 유형은 6건이다. 즉 'AI 생성' 정보가 두 탭에 걸쳐 있다.
- AI 탭의 '판례 인용 오류·미확인 검토' 표 3행(2022다29841 판결, 국가배상법 제2조의3, 육군 규정 제22조)은 **모두 같은 인용이 '확인할 항목'에도 있다(3/3 중복).** 표는 세 행 모두 "공식 DB 미확인(원문 확인 필요)"인데, 같은 인용의 finding은 CRITICAL(판례 미발견), MEDIUM(조문 미발견), CRITICAL(법령 미발견)이다. **표기·심각도가 3/3 불일치**다.
- 반대로 법리 타당성 항목인 시점 모순(HIGH)과 근거 없는 청구 유형(MEDIUM)은 '확인할 항목'에만 있고 AI 탭 표에는 없다. 법리 타당성 검토가 두 화면에 쪼개져 있다.
- 인용 6건은 일부 확인(PARTIALLY_VERIFIED)으로 finding 없이 '미확인 범위' 8건 안에만 있고, 그중 1건의 사유에 내부 오류 문구("Multiple versions share the requested effective boundary")가 그대로 노출된다.
- 한계: 보고서 1건·3차 코드 기준이다. 4차 코드에서 육군 규정의 CRITICAL은 완화됐으나(TK-23 A) 표와 finding의 이중 표기 구조는 같다.

## 3. 제안별 검토
### ① AI 탭 축소 — 타당
- 인용 오류·법률 주장 검토표, 판례 요약, RAG 결과, 추가 관련 법조문은 모두 작성 주체와 무관한 내용이며 화면 문구도 그렇게 말한다. 이동만으로 해소된다.
- **조건 1(중대 항목 누락 방지):** AI·보안 유형 finding(인젝션 격리, AI 전체 생성 의심 등)이 '확인할 항목'에서 빠지면 AI 탭을 열지 않는 사용자가 격리 사실을 놓칠 수 있다. 상단 요약(`renderSummary`)의 격리·AI 판정 노출을 유지하고, HIGH 이상은 통합 탭 상단에 한 줄 고정 안내로 남긴다.
- **조건 2(분류의 완전성):** finding 유형이 새로 생겨도 어느 화면에 속하는지 정해져 있어야 한다. 유형→화면 배정표 하나를 두고 모든 `FindingType`이 배정됐는지 자동 시험으로 막는다(미배정은 실패).
- `AUTHORSHIP_METADATA_LEAK`(작성자 메타데이터)는 AI 작성 판단이 아니라 파일 정보 노출이므로 AI 탭이 아니라 '문서 보안' 묶음으로 두는 것을 권장한다(사용자 확인 사항).

### ② 통합 — 조건부 타당
유효한 부분: 한 인용에 판정이 하나여야 한다는 점(2.1의 3/3 불일치), 법리 타당성 검토가 한 곳에 있어야 한다는 점, 판례 인용표의 4열 형식(위치 / 문서 주장·인용 / 근거 확인 결과 / 법리 타당성·반박·대응)이 검토에 적합하다는 점.
**그대로 합치면 안 되는 부분(수정 제안):**
1. **'주장·쟁점'의 쟁점 매트릭스는 검증 도구가 아니라 변호사의 작업 산출물**(쟁점별 요건사실 정리, 주장별 입장·증거 연결 저장)이다. 이것을 인용 검증표에 섞으면 기능이 사라지거나 의미가 뒤섞인다. **자동 추출 주장 목록**만 통합하고, 쟁점 작업대와 사건 매트릭스는 별도 탭('쟁점 정리')으로 두며 통합 탭에서는 쟁점을 **필터**로 쓴다(권장).
2. **행마다 검토 상태를 저장할 ID가 없다.** 인용표 행에는 finding_id가 없어 '확인 전/수용/오탐/조치 완료', 우선순위, 담당자(optimistic revision 포함)를 저장할 수 없다. 모든 '확인 필요' 행은 안정적인 ID(finding_id 또는 citation_id·claim_id 기반 항목 ID)로 같은 검토 흐름에 연결되어야 하며, 기존 finding의 검토 이력은 유지된다.
3. **서버에서 단일 판정을 만든다.** 화면에서 두 데이터를 이어 붙이면 불일치가 남는다. 인용 하나의 근거 판정·심각도·문구를 서버가 한 번 계산한 `review_items`로 내려주고(추가 필드, 기존 필드 불변), 표의 '근거 확인 결과'와 finding 제목이 같은 값에서 나오게 한다. 심각도는 사용자 결정(TK-23 B)과 증거 등급 사다리를 따른다.
4. **청구(주장) 표시는 TK-22 이후.** PDF 입력은 줄 단위로 청구가 70개로 쪼개진다(실제 PDF 측정). 이 상태에서 주장을 표에 올리면 조각난 행이 쏟아진다. 통합 탭의 주장 행은 `verification_target` 주장·문단 단위 청구에 한정하고, 전체 주장 목록은 접힌 보조 목록으로 둔다.
5. **보고서·평가 도구 호환.** PDF/DOCX 보고서(`report_engine`)와 평가 측 도구(`score_report.py`, 온라인 명세)가 `documents[].findings`, `ai_hallucination_table`, `engine_data.rag`의 경로에 의존한다. 필드는 **추가만** 하고 기존 경로는 유지한다(계약 버전 명시).
6. 사용자에게 보이는 문구에 내부 오류 문자열을 쓰지 않는다('미확인 범위'의 사유를 사람 말로 변환).

### ③ 참고자료(RAG) 활용 — 방향 타당, 확장 필요
**이미 있는 것:** 관련도 기반 자료 선정(`relevance.py`는 분야 어휘 목록이 아니라 문서·자료 말뭉치 기준 IDF), 서면 인용문과 자료 인용문을 둘 다 원문에서 확인한 의견만 채택(`grounded_observations`), 관계 4종(지지·모순·맥락·불충분), 규정 조항 인용의 허용·금지 방향 규칙 대조, 내부 규정을 참고자료로 확인한 경우의 표시(TK-23 A), 모델 불가·QUICK 시 검색만 수행.
**사용자 의도(서면이 매뉴얼에 부합하는가)에 못 미치는 부분:**
- 검색 질의와 모델 입력이 모두 **분석 본문 12,000자 한도**(`analysis_text(limit=12000)`, 초과분은 `document_truncated`)로 만든 **문서 단위** 하나이고, 질의는 핵심어 40개(`QUERY_TERMS`)다. 실측 `claim_coverage`는 **검토 대상 주장 17건 중 1건 연결(5.9%)**, 참고 의견 2건(모두 '불충분')이다. 주장 단위 대조가 아니라 부수적 대조에 가깝다.
- 결과가 AI 탭 하단의 접힌 상세(`<details>`)로만 보이고 확인 상태를 기록할 수 없다.
**설계상 반드시 지킬 원칙(법적 위계·증거 사다리):**
- Drive 자료는 **공식 DB를 대체하지 못한다.** 근거 등급은 `공식 원문 확인 > 참고자료에서 확인(공식 아님) > 미확인`으로 두고, 참고자료에 있어도 공식 DB '미발견'을 지우지 않는다(TK-29: 제목 부분 일치·미독 파일로 확정도를 올리는 것은 금지, 본문 일치 필요).
- **규범 위계:** 법령 > 행정규칙(훈령·예규·고시) > 지침·매뉴얼·해설서. 서면과 매뉴얼이 다르면 '참고자료 불부합'이지 '위법'이 아니며, 매뉴얼이 상위 규범과 충돌할 가능성이 있으면 그렇게 표시한다. 출력 문구에 이 구분을 강제한다(`authority_limitation` 필드 이미 있음).
- **참고 의견의 지위:** 사용자가 TK-09(모델 의견 승격)를 꺼 두기로 했으므로, 참고자료 대조 의견은 **심각도 승격 없는 '참고 의견' 행**으로 통합 탭에 노출하고 검토 상태만 기록한다.
- **분야 비종속:** 학교폭력 매뉴얼은 설명용 예다. 코드·설정·시험 기대값에 분야 낱말을 넣지 않고, 구조가 같은 다른 분야 합성 자료(예: 조달 계약 지침)에서 같은 동작을 보여야 한다.
- **프라이버시:** 참고자료 발췌와 서면의 외부 모델 전송은 기존 정책(`LOCAL_ONLY`·`MASKED`·`ORIGINAL`)과 전송 전 검사를 그대로 거친다. `LOCAL_ONLY`면 모델을 부르지 않고 규칙 대조와 검색 결과만 낸다. 참고자료에는 내부·군 자료가 있을 수 있으므로 발췌도 마스킹 대상이다.
- 비용·시간: 주장 수×발췌 수만큼 호출이 늘 수 있다. 상한과 배치를 두고 상한에 걸려 **대조하지 못한 주장 수를 사용자에게 보인다**(전체 검토 완료로 오해하지 않게).

| 보고서·평가 도구 파손 | 필드 추가만, 기존 경로 불변 시험(JSON 키 목록 고정) |

## 5. 측정(평가 계획)과 한계
- 평가 측이 보호 시험을 **먼저** 둔다(미해결은 strict xfail, 이전 라운드와 같은 방식): T1 단일 판정, T2 손실 없음, T3 유형→화면 배정 완전성, T4 AI 탭 배타성(인용·RAG 행 0), T5 기존 JSON 키 불변, T6 참고자료 위계(공식 미발견 유지), T7 주장 대조율 표시의 정확성, T8 다른 분야 합성 자료 2세트 동작 동일, T9 `LOCAL_ONLY`에서 외부 호출 0.
- 수용 지표(서면9 온라인 재실행 JSON 기준): 인용당 표시 행 1개(현재 이중), 행별 심각도·문구 단일(현재 3/3 불일치), 통합 탭 행의 AI·보안 유형 0(현재 7/13), AI 탭의 인용·RAG 행 0, `claim_coverage` 대조율 표시.
- **오프라인으로 재지 못하는 것:** 실제 모델의 대조 품질(모델 호출 필요), Drive 연동·색인 동작, 화면의 사용 편의(점수화 불가). 오프라인은 가짜 라우터·합성 참고자료 라이브러리로 **연결 구조와 안전 규칙**만 잰다. 모델 품질은 사용자 온라인 재실행으로 확인한다.
- 버전 정책: 화면 구조 변경은 성능 변화가 아니므로 버전은 평가 측 판정서가 있을 때만 올린다(`docs/scorecards/VERSION_POLICY.md`).

## 6. 사용자 결정 필요(권장안 표시)
| # | 결정 | 선택지 | 권장 |
|---|---|---|---|
| D1 | '주장·쟁점'의 쟁점 매트릭스·변호사 평가 | **별도 '쟁점 정리' 탭으로 유지, 통합 탭은 쟁점 필터로 연동** / 통합 탭 안에 접어 넣기 / 폐지 | ★ 별도 탭 유지 |
| D2 | 중대 AI·보안 항목 노출 | **상단 요약 유지 + HIGH 이상은 통합 탭 상단 고정 안내** / AI 탭에만 | ★ 고정 안내 |
| D3 | 작성자 메타데이터 노출(AUTHORSHIP_METADATA_LEAK) | **'문서 보안' 묶음(AI 탭 안 보안 카드)** / 통합 탭 / 숨김 | ★ AI·보안 탭의 보안 카드 |
| D4 | 참고자료 불부합 의견의 지위 | **참고 의견(승격 없음, 검토 상태만 기록)** / 확인할 항목으로 승격 | ★ 참고 의견(TK-09 결정과 일치) |
| D5 | 착수 시점 | **5차 검증 뒤 F1→F2→F3** / 5차와 병행해 F1만 | ★ 5차 검증 뒤 |
| D6 | 참고자료의 외부 모델 전송 | **기존 정책·전송 전 검사 그대로(발췌도 마스킹)** / 참고자료는 항상 로컬 규칙 대조만 | ★ 기존 정책 |
위 결정 전에도 지시서의 F1·F2 설계 요청서까지는 기본값(★)으로 진행할 수 있다. 사용자가 다르게 정하면 지시서 해당 절만 고친다.
