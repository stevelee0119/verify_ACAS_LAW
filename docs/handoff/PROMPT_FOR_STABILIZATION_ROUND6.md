### R3. TK-32 법리 군집: 요건 제시와 결론 범위를 구분 + 설정의 장 이름 정정
**증거:** 5차로 민법 과대주장 양성 20건은 모두 탐지되나(보존), **요건을 구체적으로 제시하고 결론을 해당 채무로 한정한 정상 항변**도 `GEN.DEFENSE_OVERCLAIM_WITHOUT_REQUIREMENTS`로 표시된다(Astra 정상 10건 중 4차 0 → 5차 5건, 평가 측 합성 13건 중 1건: `…민법 제487조에 따라 이 사건 채무가 소멸하였으므로 피고는 이 사건 채무에 관한 책임을 질 수 없다.`). 원인은 "양보 표현 + 법리·조문 + 단정 결론(`책임을 질 수 없` 등)"의 정규식 구조만 보고 요건 제시 여부와 결론 범위를 보지 않는 데 있다. 또 `config/legal_defense_groups.json`의 사무관리·부당이득·불법행위를 제4·5·6장이라 적었으나 **국가법령정보센터 민법 원문 목차는 제3편 제3·4·5장**이다(평가 측이 원문 대조). 자세한 근거: `docs/handoff/TK-32_civil_cluster_false_positive_and_names.md`.
**개선:** (1) **요건 제시와 결론 범위를 구분**한다: 같은 채무의 소멸(해당 채무에 한정한 결론)과 다른 형사·징계책임까지 일괄 면책하는 결론을 구분하고, 요건(변제기·상계적상·의사표시 도달·금지 사유 부재 등)을 구체적으로 제시한 항변은 과대주장으로 표시하지 않는다. 요건을 확인하지 못했다면 확정적 경고 대신 **"요건 확인 요청"** 으로 표현한다. (2) **경고를 없애는 예외 문장 목록 추가, 법리 범위를 되돌리는 수정은 금지**(양성 20건이 다시 빠진다). (3) 편·장·절 이름과 `basis`를 원문 목차 URL로 정정하고 **확인하지 못한 항목은 비운다**(추측 금지). 평가 측이 원문으로 확인한 것은 제3편 제3장 사무관리(제734조~)·제4장 부당이득(제741조~)·제5장 불법행위(제750조~), 제1편 제3절 대리(제114조~)·제4절 무효와 취소(제137조~)·제7장 소멸시효(제162조~), 제2편 제2장 점유권(제192조~)의 시작 번호다. **제3편 제1장 제6절 채권의 소멸(460~507)·제2장 제1절 제3관 해제·해지(543~553)의 이름·범위는 구현 측이 원문 목차로 확인**하고 확인일을 적는다.
**수용:** `test_round5_regressions.py`의 TK-32 1건 XPASS, `test_generalization_guards.py`의 민법 5건 유지, 평가 측 정상 항변 대조군(합성 13건)에서 4차 수준(0건) 오탐, 편·장 이름이 원문 목차와 일치. **구현 측 새 시험(필수):** 요건 제시·결론 한정 정상 항변 양성 10건 이상(상계·변제·면제·공탁·혼동·해제 등 대상 바꿈), 요건 없는 과대 양성 10건 이상, 둘의 대조(평가 측 문장을 복사하지 않는다).

### R4. 절차 점검과 정리
- 위 0.2의 보고 규칙을 지킨다. 요청서는 (무엇을·어느 입력 방식에서·어떤 시험으로) 확인했는지와 **확인하지 못한 것**을 구분해 적는다.
- **커밋마다 4절 명령 전부**를 돈다(5차에서 푸시 6건의 `점수 게이트`가 모두 failure였고 요청서는 성공 단계만 적었다). 평가 측 `regression_gate.py`는 이제 **성적표 문서별 비교**와 pytest ERROR·요약 불일치도 비통과로 본다. 종료 코드 1·2를 통과로 쓰지 않는다.
- 죽은 코드·불필요한 목록(예: 조사 목록이 구조 신호로 대체된 뒤 남은 것)은 정리한다. 새 기능은 넣지 않는다.

## 2. 설계 원칙 (5차와 같음, 이번 라운드에서 특히)
1. **한 방향 기본값으로 고치지 않는다.** 줄 결합의 공백 유무, 이름 후보의 포함·배제, 경고의 표시·미표시는 모두 두 방향 시험(글자 단위/어절 단위 줄바꿈, 이름 끝 글자·라벨 종류, 요건 제시/미제시)으로 함께 고정한다.
2. **불확실을 확정으로 바꾸지 않는다.** 불확실한 경계·이름 후보·요건은 후보를 보존하거나 "확인 요청"으로 표현한다.
3. **예외 목록 대신 구조.** 특정 이름·문장·낱말 예외를 늘려 시험을 맞추지 않는다.
4. **보존 항목을 되돌리지 않는다.** 0.1의 '보존' 항목은 매 커밋 시험으로 지킨다.

## 3. 어길 수 없는 규칙
5차 3절(사건 값 하드코딩, 시험 입력에 맞춘 분기, 점수 맞춤 출력, 기대값 수정으로 통과, skip·xfail 임의 변경, 보호 경로 수정, 기준선 수정, 불확실을 확정으로 바꾸기, 소비자별 땜질, 환경을 숨긴 점수 보고) + **평가 자료 표식 분기 금지**(`eval_marker`) + **판정서 없는 버전 변경 금지**(5차 8절). **새 `rule_id`·새 설정 파일·새 탐지 유형은 0개**여야 한다(설정 변경은 기존 `legal_defense_groups.json`의 정정·`verified_at`/`source_url` 필드 추가에 한한다). 하나라도 있으면 그 커밋은 되돌린다.

## 4. 검증 명령 (커밋마다 1~7, 푸시 전에 전부)
```
python scripts/regression_gate.py --base HEAD~1                      # 1. 항목 단위 회귀 + 성적표 문서별 비교. 종료 코드 1·2는 통과가 아니다. 푸시 전에는 --base <푸시 전 원격 커밋> --pytest
python scripts/check_hardcoding_diff.py --base HEAD~1                # 2. 새 줄의 시험 입력 값·조문 번호·새 rule_id·평가 자료 표식(eval_marker)
python scripts/check_case_literals.py                                # 3. 사건 값 하드코딩(코드와 config/*.json), 새 위반 0
python scripts/scorecard.py && python scripts/score_gate.py          # 4. dev 81.2 이상(최종 81.7 이상), holdout 79.2 이상, 오탐 0 (환경 함께 기재)
python scripts/check_version_policy.py --base HEAD~1                 # 5. 작업 커밋은 버전 불변
python -m pytest -q tests/regression                                 # 6. 회귀 원장
python -m pytest -q --ignore=tests/acceptance                        # 7. 전체 시험: 알려진 실패(환경 1) 외 새 실패 0, 커밋마다
python -m pytest tests/acceptance -q -rfxX                           # 현재 미해결은 strict xfail. XPASS(strict) 실패는 requests로 알림(평가 측이 표시를 지운다)
python scripts/probe_document.py run --spec tests/fixtures/probes/<spec>.json [--text]   # 서면6~9·변형 1·2 점수 유지(서면6 20/20·7 25/25·8 22/22·9 27/28·변형1 24/24·변형2 21/21)
```
`check_hardcoding_diff.py`의 **강한 신호**(`eval_marker` 포함)는 평가 측 승인 전까지 실패로 본다. `regression_gate.py`가 **종료 코드 2**(측정 못 함)를 내면 원인을 해결한다.

## 5. 보고 형식 (묶음마다)
1. 원인 한 줄, 바꾼 파일, 새로 둔 고정 시험(`tests/regression/`)
2. **입력 방식별 해결 표**(txt·PDF·docx), 4절 1~7번 출력 요약(회귀·강한 신호·점수 **시작 상태 대비**), 환경(OS·python·OCR 유무), 푸시 후 GitHub `점수 게이트` **job 결론과 단계별 결과**(CI는 브랜치 푸시에서 실행되지 않으면 그 사실)

4. 커밋 해시(`Agent: implementer`), 버전 상태("변경 없음")
