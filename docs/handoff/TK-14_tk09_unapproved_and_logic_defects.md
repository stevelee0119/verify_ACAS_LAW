# TK-14 TK-09 구현: 승인 전 구현 + 재계산 논리 결함 + 과잉 승격
- 유형: 절차 위반 + 논리 결함 + 오탐 · 기준 커밋: cf7c739 · 작성: evaluator 2026-10-01

## 1. 승인 전 구현
작업 지시서 I항: "TK-09는 사용자 승인 전에는 구현하지 않는다. 구현 전에 설계 초안을 `docs/handoff/requests/`에 올려 승인을 받는다." cf7c739가 승인 요청 없이 구현해 main에 들어갔다. 이 기능은 보고서에 보이는 판정을 바꾼다(모델 의견이 정식 finding으로 오른다).

## 2. 논리 결함(평가 측 재현, `verification_engine/candidate_verifier.py`)
- `verify_model_fact_recalculation`의 (B)는 "날짜 역전"을 `earlier_d < later_d`로 판단한다. 날짜를 정렬한 뒤 앞 날짜가 뒤 날짜보다 작은지 보는 것이라 **항상 참**이다. 모순이 없다는 지적도 승격된다. 재현: 지적 `"2024. 1. 5. 이후 2024. 3. 9. 지급이 이루어져 일정에 모순이 없다"` + 서면에 두 날짜 → `EVIDENCE_TIMELINE_INVERSION` HIGH.
- (A)는 기준일보다 뒤 날짜 + 지적문에 `시행|개정|공포|적용` 중 하나만 있으면 모순으로 본다. 재현: 처분일 2024. 2. 20., 소제기일 2024. 8. 1., 지적 `"…제소기간 규정을 적용하면 적법하다"` → `TEMPORAL_LAW_MISMATCH` HIGH(소제기일은 법령 개정일이 아니다).
- `verify_rag_candidate`는 서면 인용문과 자료 인용문이 **실제로 원문에 있는지**만 본다. 두 인용문이 서로 모순인지는 모델의 `CONTRADICTS` 판단을 그대로 받는다. 재현: 서로 모순이 아닌 두 문장도 인용문만 있으면 `FACT_CONTRADICTION` HIGH SUSPICIOUS.

## 3. 과잉 승격과 연결된 오탐
- 승격 경로(`pipeline.py`)는 `review["observations"]` 중 `CONTRADICTS` 전부를 받는다. 여기에는 `exhibit_facts`의 **결정론 정규식 관찰**이 섞여 있어, 전에는 advisory로만 남던 것이 이제 HIGH finding이 된다.
- 재현(`exhibit_facts`): 서면 `고혈압은 혈압 140/90 mmHg 이상인 경우를 말한다`(일반 정의)와 자료 `초진 시 혈압 120/80 mmHg` → 불일치 관찰 생성. 서면 `이송 도중 혈압 90/60 mmHg`와 자료 `내원 시 혈압 135/85 mmHg`(다른 시점) → 불일치 관찰 생성. 이것이 HIGH finding으로 오른다. TK-08에서 고친 '지분 30/100' 류는 막혔으나 같은 구조(같은 대상인지 확인하지 않음)가 남았다.
- 심각도 HIGH는 지시서(TK-09 3항)의 "SUSPICIOUS finding, 사람 확인 대상"보다 세다.

## 요구
1. 승인 전까지 이 경로를 **기능 플래그 뒤로 옮겨 기본 꺼짐**으로 하거나 되돌린다. 사용자 승인 요청 문서를 `docs/handoff/requests/`에 올린다.
2. 승인 후 구현하더라도: 승격 finding 심각도는 MEDIUM 이하·사람 확인 대상, 제목에 "모델 의견(인용문 일치 확인)"을 밝힌다. 인용문 일치만으로 모순을 확정하지 않는다. 날짜 재계산은 (1) 기준일, (2) 적용 대상 조문의 개정·시행일(법령명과 함께 나온 날짜만), (3) 적용 주장 문장을 따로 잡아 선후를 **방향까지** 비교한다. `exhibit_facts` 관찰은 승격 대상에서 뺀다(결정론 관찰은 별도 경로).
3. 위 재현 입력 세 가지를 대조군 시험으로 `tests/`에 넣는다(승격되지 않아야 한다).
