  - system: 모든 형식 108/108 도달 — 라우터가 고정 머리말을 붙여(`router.py`의 `SYSTEM_BASE` 결합) JSON 해석이 깨지고, 평문 검사로는 `"원고": "이름"`의 따옴표 때문에 라벨 문맥이 이어지지 않는다(원인 추정은 코드 경로 기준이며 Codex 문서와 같다).

## 영향
F1/F3는 참고자료·주장 묶음을 JSON으로 조립해 `LLMRouter.run`에 보낸다(`packages/rag_engine/review.py`). 자료 본문 문장 속 이름은 평문 문맥으로 잡히지만, 당사자 표·추출 결과처럼 **라벨이 키로, 이름이 값으로** 들어가는 구조는 위와 같이 통과한다. 실제 외부 전송 사고 기록은 아니다(재현은 가짜 공급자).

## 요구
1. 이름 라벨 정의를 `detector.py`의 라벨 어휘와 **한 곳**에서 공유하고, 구조화 요청의 키·값·형제 필드(`role`/`name` 쌍 포함)와 프롬프트 조립 전후 모두에서 같은 판정을 쓴다. 키 몇 개를 목록에 더하는 것으로 끝내지 않는다.
2. system 조립 뒤에도 원래 JSON 구조를 검사하거나(조립 전 검사 결과 보존) 조립 문자열에서 라벨-값 쌍을 복원한다.
3. 판정이 서지 않으면 **원문을 보내지 않고 종료**한다(fail-closed) — 실제 router에서 확인.
4. 시험: 평탄·중첩·배열·문자열 JSON × user/system/schema, 원래 차단 대조 유지, 정상 법률 명사 대조(과마스킹) 보존. 입력은 구현 측이 새로 짓는다.
