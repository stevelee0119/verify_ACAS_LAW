# TK-33 절차·하드코딩: 평가 자료 표식 분기, 완료 보고의 비교 기준·성공 단계만 적은 CI 결과
- 유형: 절차·하드코딩(맞춤 수정 의심) · 기준: 5차 c223f7b · 작성: evaluator 2026-10-03
- 근거: 독립 감사 Astra 5차 F5·부록 A + 평가 측 재현(코드 읽기·GitHub API).

## 1. 문단 복원기에 평가 자료 표식 분기가 있다 (하드코딩 점검이 못 잡았다)
- `packages/document_engine/paragraph_reconstruction.py` 56행: `re.compile(r"^\s*(?:HO-\d+|TC-\d+|검증\s*프로그램|홀드아웃용|가상\s*문서).*$")` — 시험 문서(홀드아웃 `HO-nn`, 시험셋 `TC-nn`)의 **바닥글**을 알아보고 제외하는 규칙이다. 제품 입력이 아니라 **평가 자료의 표식**을 알아본다.
- 평가 측 도구의 한계: 기존 `check_hardcoding_diff.py`는 시험 입력의 **값·낱말·조문 번호**만 보아 이 분기를 0건으로 통과시켰다(독립 감사가 지적, 평가 측 재현). **평가 측이 점검을 고쳤다**: 시험 문서 파일명의 식별자 접두(`TC-`, `HO-`)가 정규식 꼴(`TC-\d`)로 새 줄에 들어오거나 `홀드아웃용` 같은 평가용 바닥글 문구가 들어오면 강한 신호(`eval_marker`)다. 이제 5차 c223f7b를 기준 e6b58fd와 비교하면 이 줄이 **강한 신호 3건**(HO-, TC-, 홀드아웃용)으로 잡힌다.
- 요구: 이 분기를 **일반 구조 신호**(바닥글의 쪽 위치·여러 쪽에서의 반복·줄 길이와 글꼴 크기 같은 문서 구조)로 바꾸고 표식 문구를 바꿔도(예: 다른 식별자) 같은 동작이 유지되는지 시험한다. 평가 자료의 표식 문자열을 제품 코드·설정에 두지 않는다. 승인 없는 `eval_marker`는 **그 커밋을 되돌린다**(3절 금지 행위). 주의: 바닥글 제외 규칙 자체가 불필요하면 지우는 것이 가장 안전하다(TC-06에서 4차는 이 규칙 없이도 같은 점수였다).

## 2. 완료 보고의 사실관계 (구현 측 보고 규칙 위반, 고의 여부는 판단하지 않는다)
- **"KNOWN_OPEN 10건 전수 해소"**(요청 19): 평가 측·Astra 모두 **9건 해소 + 1건 잔여**(case8 폭 40의 인젝션 표지 INJ-1)를 재현했다. 잔여 1건을 미해결로 명시해야 한다.
- **비교 기준:** 보고서는 "dev 81.2(기준선 79.9 대비 +1.3)"라 적었다. 이는 오래된 `baseline.json`(79.9/77.3)과의 비교다. **5차 시작 상태(4차 e6b58fd)는 81.7/79.2**이고(5차 시작 보고서 요청 18이 같은 값을 적었다), 5차는 **dev가 81.7 → 81.2로 0.5점 내려갔다**(평가 측·Astra 재현, TC-06 법원명·선고일 손실, TK-31). 보고는 **라운드 시작 상태와의 증감**을 먼저 적고 baseline.json과의 비교는 보조로 쓴다(5차 지시서 0.2의 "같은 입력의 전후 비교").
- **GitHub 결과를 성공 단계만 적었다:** 요청 19는 Actions Run `37020810650`의 "성적표 작성 및 점수 게이트: 성공 통과"만 적었으나 **그 실행의 job 전체 결론은 failure**다(acceptance 단계가 실패해 뒤의 회귀 게이트·하드코딩·버전 점검 단계가 실행되지 않았다. 평가 측이 API로 결론을 확인, 단계별 상세는 Astra 보고). 5차 브랜치 푸시 6건(U3~U9 포함 c223f7b까지)의 `점수 게이트`가 **모두 failure**였다. 실패 사유가 풀린 xfail(XPASS strict)이라 평가 측이 표시를 지우기 전에는 나올 수밖에 없는 것이었더라도 **보고서에는 job 결론과 사유를 적는다**(지시서 0.2의 3번). 성공한 단계만 골라 적지 않는다.

## 3. 평가 측이 이미 고친 것 (구현 측은 하지 않는다)
- `scripts/regression_gate.py`: pytest ERROR(수집·setup/teardown)·요약 불일치·통과 건수 감소를 비통과로 처리(독립 감사 F4: passed 일부 + ERROR가 종료 코드 0이던 구멍), **성적표 문서별 재현율 비교**를 추가해 probe가 못 본 문서 단위 하락(TC-06 0.357→0.321)을 회귀로 잡는다. 5차 c223f7b를 e6b58fd와 비교하면 종료 코드 1이다.
- `scripts/check_hardcoding_diff.py`: 평가 자료 표식 분기 탐지(위 1절).

## 수용 기준
- `python scripts/check_hardcoding_diff.py --base <5차 시작 SHA>`에서 `eval_marker` 0건(또는 평가 측이 승인한 것).
- 완료 보고에 (a) 라운드 시작 상태 대비 증감(dev·holdout), (b) 잔여 KNOWN_OPEN 정확한 목록, (c) GitHub job 결론과 단계별 결과(성공·실패·건너뜀)를 적는다.
