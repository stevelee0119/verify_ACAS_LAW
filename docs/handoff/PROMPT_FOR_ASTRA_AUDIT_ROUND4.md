# 4차 독립 검증 의뢰서 (검증 담당 에이전트, 읽기 전용)

작성: 평가 에이전트(claude-code) 2026-10-01 · 대상: 4차 안정화 라운드(`PROMPT_FOR_STABILIZATION_ROUND4.md`)의 구현 결과
이 문서는 구현을 맡지 않은 **다른 에이전트**(권장: Astra)가 구현 에이전트와 평가 에이전트 어느 쪽의 주장도 그대로 믿지 않고 직접 재현해 확인하는 일을 정의한다. 아래 전체를 그대로 붙여 넣어 쓴다.

## 0. 규칙
1. **제품 코드(`packages/ apps/ workers/ config/ migrations/ docker/`)와 보호 경로를 수정하지 않는다.** 커밋·푸시·배포도 하지 않는다. 산출물은 보고서 파일과 재현 스크립트이며 사용자에게 제출한다.
2. 구현 에이전트와 평가 에이전트의 서술·점수·커밋 메시지는 **주장**이다. 직접 재현한 것만 사실로 적고, 재현하지 못한 것은 "확인 못 함"으로 적는다. 사실·추정·의견을 구분한다.
3. 독립성: 3번 항목에서 만드는 **새 서면은 구현 에이전트에게 공개하지 않는다**(저장소에 올리지 않는다). 평가 에이전트와 의견이 다르면 보고서에 별도 절로 적는다.
4. 점수는 항상 측정 조건(입력·채점 규칙·환경)과 함께 적고, 조건이 다른 점수를 증감으로 비교하지 않는다. 오프라인 측정은 AI 작성 판별·공식 DB 대조·Drive 대조를 재지 못한다고 명시한다.

## 1. 재현 환경
`Steve_ACASiaLAW`(a64caf3 이후)와 `main`을 받아 구현 결과 커밋별 스냅샷(`git worktree`)을 만든다. 오프라인(`LV_ALLOW_NETWORK=0`)으로 먼저 재고, 네트워크가 있으면 2번까지만 별도로 시도한다. 사용 도구: `scripts/regression_gate.py`, `scripts/check_hardcoding_diff.py`, `scripts/check_case_literals.py`, `scripts/probe_document.py`, `scripts/scorecard.py`, `scripts/score_gate.py` (평가 측 도구도 검증 대상이다 — 도구의 오류를 발견하면 보고한다).

## 2. 검증 항목
**V1. 회귀 재현.** 기준(9933548)부터 4차 마지막 커밋까지 커밋마다 (a) `pytest -q --ignore=tests/acceptance` 실패 집합, (b) 모든 개발 서면(`tests/fixtures/probes/*.json`, 온라인 명세 제외)의 항목별 통과 여부를 직접 구해 **전에 통과하던 것이 떨어진 곳**을 목록으로 만든다. 평가 측 `regression_gate.py`의 결과와 대조하고 다르면 원인을 적는다.
**V2. 하드코딩·점수 맞춤 감사.** 4차 전체 diff(`git diff 9933548 HEAD -- packages config apps workers`)의 추가된 줄을 읽고, 구현 지시서 0절 B의 1~8번 금지 행위에 해당하는 것을 찾는다: 시험 입력의 낱말·문장·조문 번호·식별자가 키·목록·정규식에 있는지, 특정 서면·환경을 알아보는 분기가 있는지, 채점 항목에 맞춘 문구가 있는지, 설정 파일이 실제로 읽히는지, 새 `rule_id`가 있는지. 각 발견은 파일·줄·근거 시험 자료를 적는다.
**V3. 미공개 서면 첫 점수.** 서로 다른 사건 유형(예: 형사 1·행정 1·민사 계약 1)의 새 합성 서면 3건을 직접 쓴다(가공의 사건번호·조문·인용임을 표시하고 실재 법령·판례를 지어내지 않는다). 각 서면에 인젝션 표지·가공 인용·행위시법 위반·무리한 주장·개인정보·Drive 대조 항목을 넣고, 같은 서면의 줄 폭만 바꾼 변형(36·44·56자)과 CRLF 변형을 만들어 **구현 전(9933548)과 후의 결과를 같은 도구로** 잰다. 원본과 배치 변형의 결과 차이는 곧 배치 의존이다.
**V4. 불확실성 단조 감사.** 직접 지은 30문장 이상(날짜 여러 개, 법령 변경 표현, 시점 표기가 다른 수치, 인용 형식 변형)을 기준과 현재로 처리해 **UNVERIFIED·INFO가 VERIFIED나 더 높은 확신으로 바뀐 경우**와 후보가 하나로 줄어든 경우를 모두 찾는다.
**V5. 외부 지적 재현.** 이미 낸 경계 재현(날짜·서증 시점·개인정보 system 필드) 스크립트를 4차 결과에서 다시 돌려 해결·잔존을 적는다. 구현 에이전트의 S6 재현 시도 결과와 대조한다.
**V6. 주장 검증.** 구현 커밋 메시지의 점수·환경·"해결" 서술을 재현해 맞는지 본다(예: 환경이 다른 점수를 같은 것으로 적었는지).
**V7. 서비스 통합(네트워크·키가 있을 때만).** 업로드→분석→결과 열람이 끝까지 되는지, 모델·공식 출처·Drive 각각의 성공·실패·부분 완료가 보고서에 구분되어 나오는지, 실행 시간과 모델 호출 비용을 기록한다. 서면 1건 기준 수치를 적고 일반화하지 않는다.

3. 평가 에이전트·구현 에이전트와 의견이 다른 점(별도 절).
