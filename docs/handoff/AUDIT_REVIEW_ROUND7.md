# 독립 감사(Astra, 7차 4da3910) 검토·판정 — 평가 측 독립 재현과의 대조

작성: evaluator 2026-10-03 · 대상: Astra `7차_독립감사_4da3910.md`와 `ANTIGRAVITY_ROUND7_AUDIT_REMEDIATION.md` · 비교: 평가 측 측정([HISTORY 12절](../scorecards/HISTORY.md), [f1_gate_verdict](../scorecards/f1_gate_verdict.md)). 감사의 비공개 입력은 받지 못해 **같은 메커니즘을 평가 측 입력으로 새로 재현**했다(시작 7adf43f·4da3910 별도 작업 트리, Linux·python 3.11.15·tesseract 5.3.4, 오프라인).

## 판정
**감사의 핵심 결론(7차 완료 승인 불가, F1 보류)과 지적 6건 모두 타당하다.** 3건(A7-02·A7-03·A7-05)은 평가 측이 이미 같은 결론에 이르렀고, **3건(A7-01·A7-04·A7-06의 영향 범위)은 평가 측이 놓쳤거나 좁게 본 것을 감사가 바로잡았다.** 평가 측은 이를 받아들여 판정서·티켓·보완 지시서·보호 시험을 고쳤다. 감사의 우선순위 분류(P1 3·P2 3)도 그대로 따른다(평가 측의 TK-45는 P2 → **P1로 상향**).

## 평가 측 측정과의 차이 (어느 쪽도 틀린 것이 아니라 표본 차이)
- **비공개 이름 변형:** 감사 81 → 54, 평가 측(라벨 어휘 안 330) 290 → 330. 감사 표본에는 A7-01 계열이, 평가 측 표본에는 없었다. 두 결과 모두 같은 4da3910에서 재현 가능한 사실이며 합치면 **'후행 문맥 제외는 풀었으나 stem 제외가 새로 생겼다'**가 된다.
- **정상 문장 PERSON 오탐:** 감사 20문장 5 → 4(증가 없음), 평가 측 새 문장 `{당사자 라벨} 진술 조서는`류 0 → 12 + 비공개 1건 신규(TK-43). 감사 표본에 이 계열이 없었다. TK-43은 유지한다.
- **법리:** 감사의 기존 요건 부정·타 책임 확장 대비 입력은 9/10·10/10, 평가 측 변형은 3/8·1/5. 입력 분포 차이(감사는 R6-02 유사 구조, 평가 측은 표현을 바꿈) — 둘 다 '목록 안에서만 풀린다'는 같은 결론이다. 평가 측이 찾은 **'요건 충족 뒤 부정어 이웃' 신규 오탐 3건(TK-45)은 감사에 없다**(감사 누락이라기보다 표본 차이).
- **G7:** 감사는 Windows에서 전체 스캔을 못 돌려 미충족, 평가 측은 도구 결함(`base` 미정의)을 고친 뒤 Linux에서 지수 증가 0건(시작 2)을 실측해 충족. 감사가 지적한 도구 결함은 타당하며 `b44227d`에서 이미 고쳤다. 단 감사 지적대로 정규식 안전 일반의 증명은 아니다.
- **G10:** 감사의 '평가 측 인계 확인 필요'는 판정서(비공개 변형 5종·라우터 240·도구 보강)로 갈음. 평가 측 변형에 A7-01 계열을 추가한다.

## 감사 판단에서 수용하는 평가 절차 지적
지시서는 구현자에게 보호 xfail 표시를 지우지 말라 하고 같은 SHA의 `CI` 초록을 요구했다(7차 지시서 8절). 실제 `CI`의 `pytest -q`는 `tests/acceptance`를 포함하므로 **표시가 남은 동안 완료된 제품도 XPASS(strict)로 실패**한다(4da3910의 CI 로그에서 확인). **보완 지시서에서 정정한다**: 구현 측의 완료는 'XPASS(strict) 외 실패 0'이며, 평가 측이 독립 검증 뒤 표시를 승격한 커밋에서 같은 코드로 전 단계 초록을 확인한다.

## 재현하지 못했거나 감사 측에 맡긴 것
감사의 비공개 81개 이름 변형·정상 항변 10개·일반 문장 20개 입력, 실제 2쪽 PDF의 `구분하여` 재현, S4 접근 매트릭스(ADMIN 200·MEMBER/VIEWER 403·미인증 401 — 코드상 `/api/diagnostics`가 `require_admin`인 것만 확인), Windows 환경 시험(Python 3.14·OCR 없음)의 수치. R5 출처: 공식 조문 쪽 `https://www.law.go.kr/법령/민법/제460조`는 접속되어 제460조(변제제공의 방법)를 반환했다(시행 2026. 3. 17., 법률 제21454호) — 단 편·장·절 명칭은 그 쪽에서 확인되지 않아 **감사와 마찬가지로 9개 범위의 이름은 독립 확인하지 못했다**(조문 번호 범위가 알려진 민법 체계와 모순되지 않는다는 것은 평가 측의 기억이며 이번에 원문으로 확인한 것이 아니다).
