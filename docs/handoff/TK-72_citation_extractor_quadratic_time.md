# TK-72 인용 추출기가 긴 공백·반복 표기와 인용이 많은 문서에서 제곱 시간이 걸린다 (P2, 가용성, 기존 결함)
- 유형: 가용성(처리 시간), 기존 결함. 운영본 a8b2a7e와 Steve 0bf4ccc의 `packages/legal_engine/citation_extractor.py`가 같다(차이 0).
- 발견: 평가 측, 2026-10-10. TK-69(PR #56) 판정 중 반복 입력 시간 점검에서 나왔다. TK-69 변경과는 무관하다(기준 코드와 PR 결과가 같다).
- 측정 조건: 오프라인, Linux, Python 3.11.15, 합성 입력, 실제 경로(`parse_document` → `extract_citations`) 또는 `extract_from_text` 직접 호출.

## 1. 증상
| 입력(합성) | 길이 | 0bf4ccc | 증가 양상 |
|---|---|---|---|
| 목 인용 뒤 공백만 이어지는 한 줄(`…제1호 가목` + 공백 n + `x`) | 5KB / 20KB / 80KB | 0.20초 / 2.39초 / **42.4초** | 길이 4배에 시간 약 12~18배 |
| 목 인용 뒤 `·나목` 반복 | 5KB / 20KB / 80KB | 0.14초 / 2.05초 / **34.6초** | 같음 |
| 목 인용 뒤 ` 및 ` 반복 | 5KB / 20KB / 80KB | 0.08초 / 1.08초 / 19.6초 | 같음 |
| 정상 법령 인용 문장 반복(`extract_from_text`, 인용 수 = 반복 수) | 60KB(2,000건) / 240KB(8,000건) / 960KB(32,000건) | 0.59초 / 6.5초 / **91.6초** | 인용 수 4배에 시간 약 11~14배 |

- 업로드 상한은 80MB(`LV_MAX_UPLOAD_MB`)다. 신뢰할 수 없는 문서 하나로 검증 작업을 수 분 이상 붙잡을 수 있다(TK-38·TK-66과 같은 종류의 위험이나, 이번 것은 지수가 아니라 제곱이다).

## 2. 원인(평가 측 측정, 함수·정규식 단위)
1. **인용 수에 대한 제곱:** `extract_from_text`의 `overlaps()`가 이미 잡은 구간 목록 전체를 인용마다 훑는다(8,000건 입력에서 생성식 호출 3,200만 회, 5.0초). 같은 파일 530행 부근 문장 순회도 문장마다 인용 전체를 다시 거른다(`inside = [c for c in located if …]`, 4.9초).
2. **긴 공백·반복 구간에서 정규식 재시도:** `INTERPRETATION_RE`(`…)?\s*(?:법령해석|유권해석)`)는 시작 위치마다 공백 구간을 끝까지 훑는다(공백 20KB 2.0초). `ACADEMIC_RE`의 저자 반복 `(?:\s*[·,]\s*[가-힣]…)*`는 `·` 반복 구간에서 같은 양상이다(20KB 2.2초). `CONTINUED_ARTICLE_RE`도 앞머리 `\s*`가 있어 같은 위험이 있는지 확인한다.
3. 위 목록은 평가 측이 찾은 것이다. 같은 파일의 다른 정규식·반복문도 같은 기준으로 점검한다.

## 3. 요구
1. 인용 추출 전체가 문서 길이와 인용 수에 대해 선형(또는 n log n)이 되게 한다. 동작(추출 결과)은 바꾸지 않는다.
   - 예: 겹침 검사를 정렬된 구간·위치 색인으로, 문장별 인용 배정을 한 번의 병합 순회로, 정규식은 공백 구간 앞머리 반복을 없애거나 필수 낱말을 먼저 찾고 그 주변 유한 창에서만 일치시킨다.
2. 기존 인용 관련 시험은 그대로 통과해야 한다. 추출 결과가 바뀌지 않았음을 기준 코드와 비교한 합성 입력 묶음으로 보인다(차이 0).
3. 시간 시험: 위 1절 네 가지 입력 형태 각각을 80KB(인용 반복은 32,000건 960KB 이상)로 만들어 `extract_citations`(실제 경로)가 각 1초 이내. 짧은 반복 입력 시험(수천 번, 0.1초 이내)도 둔다.

## 4. 수용
- 3절 시간 시험 통과, 기존 시험 수정 없음, 고정 81.7/79.2/0, 은퇴 세트 3종 점수 같음.
- 평가 측이 같은 형태의 새 합성 입력(길이·반복 단위를 바꿔)으로 다시 잰다.
- 오프라인 탐지 엔진 변경이므로 수용 SHA에서 `verify_all` 전체 모드, 다음 릴리스에서 봉인 시험.

- 같은 파일을 TK-69(PR #56, Antigravity)가 고친다. TK-69가 병합된 뒤 그 위에서 시작한다.
