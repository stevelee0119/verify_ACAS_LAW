# 사용자 관리 보완 및 프론트엔드 개선안

검토 기준: main 31a68ed05caff88050312c29817232ac50601098.
코드와 운영 로그인 화면을 확인하고, 합성 계정으로 로컬 관리자 동작을 점검했다.
운영 사용자 자료 열람, 실제 SMTP 수신함 도착 확인은 포함하지 않는다.

## 확정된 운영 정책

- 승인 안내 및 70% 용량 경고: Render에 등록된 SMTP 사용. 반려 메일은 보내지 않는다.
- 반려 사유: 비밀번호 검증 후 로그인 화면에서만 신청자에게 안내한다.
- 문서, 보고서, 검증 결과: 프로젝트 소유자만 접근한다. 관리자도 다른 소유자의 자료를 볼 수 없다.
- 이전 공유 멤버십은 접근 권한으로 사용하지 않는다. 신규 공유 API는 차단한다.
- 애플리케이션 관리자가 다른 사용자의 토큰을 발급하거나 SSO 연결을 생성하는 경로를 차단한다.
- 기존 SSO 연결과 사용자 본인의 토큰은 유지된다. 인프라/DB 운영자 권한까지 격리하는 암호화 모델은 별도 과제다.
- 기존 프로젝트는 최초 관리자에게 일회성 이전한다. 이후 신규 프로젝트는 생성자 소유다.
- 공개 가입 신청은 설정된 최초 관리자의 조직에 귀속한다. 조직이 여러 개여도 임의 선택하지 않는다.

## 기존 구현의 주요 결함과 보완

| 항목 | 기존 문제 | 보완 내용 |
| --- | --- | --- |
| SMTP | 설정 없음도 발송 성공, 비동기 실패 유실 | DB 발송 대기열, 상태 보존, 제한된 수동 재시도 |
| 반려 | 관리자 입력 없이 고정 사유 | 반려 사유 필수 입력, 공백 거부, 이메일 미발송 |
| 조직 경계 | 새 관리자 API에서 전체 조직 조회/변경 | 목록·승인·반려·삭제·통계·CSV·메일을 조직으로 제한 |
| 승인 통제 | 기존 계정 활성화 API와 토큰 인증에서 우회 가능 | 공통 인증에서 APPROVED 검사, 재기동 시 강제 재승인 제거 |
| 월별 접속 | 모든 API_QUERY 이벤트를 로그인으로 집계 | LOGIN_SUCCEEDED만 집계, 자동 세션 갱신 제외 |
| 자원 통계 | 경과시간을 CPU/GPU 시간으로 표현 | 대기를 포함한 처리 경과시간으로 명시 |
| 과거 저장량 | 현재 저장량을 과거 월에도 반복 | 월말 스냅샷 없음 명시, 월별 신규 업로드만 제공 |
| 집계 비용 | 사용자 수에 비례한 개별 쿼리 | 사용자 목록 월별 집계는 6개 쿼리로 일괄 집계 |
| CSV | BOM 중복, 수식 주입, 내보내기 감사 누락 | BOM 1회, 수식 시작값 이스케이프, 내보내기 기록 |
| 업로드 | 중복 검사 전에 쿼터 초과/메일 전송 | 중복 먼저 확인, 소유자 잠금, 업로드와 메일 대기열 함께 커밋 |
| 이전 배포 CI | migration head 불일치, 불필요한 로그인 재표시 | 마이그레이션 보존 테스트 갱신, 비대화형 사이드바 조회 |

## 실제 발송 확인

관리자 계정 메뉴의 **조직 사용자 → 메일 발송 기록**에서 확인한다.

- QUEUED: DB에 저장, 아직 전송되지 않음.
- SENDING: 전송 시도 중.
- SMTP_ACCEPTED: SMTP 서버가 접수했음. 수신함 도착이나 열람을 의미하지 않음.
- UNAVAILABLE: SMTP 설정 누락/잘못된 설정. 성공으로 처리하지 않음.
- FAILED: SMTP가 거절했거나 전송 준비가 실패함. 최대 총 3회까지 관리자 재시도.
- UNKNOWN: 전송 중 연결 단절 또는 프로세스 종료로 접수 여부 불명. 자동 재전송 금지.
- CANCELLED: 수신 계정이 승인/활성 상태가 아니어서 취소.

환경변수는 LV_SMTP_HOST, LV_SMTP_PORT, LV_SMTP_USER, LV_SMTP_PASSWORD,
LV_SMTP_FROM, LV_SMTP_USE_TLS, LV_SMTP_USE_SSL을 사용한다.
SMTP_ 접두사도 호환하며 LV_SMTP_가 우선이다. 비밀번호는 환경변수에만 둔다.
465는 SSL, 587은 STARTTLS를 사용하고 인증서 검증을 유지한다.
설정 있음은 연결 성공을 의미하지 않는다. 실패 코드는 기록되며 자격증명과 메일 본문은 로그에 남기지 않는다.

Render 무료 인스턴스는 SMTP 25/465/587 포트를 차단한다.
리포지토리 Blueprint는 starter지만 실제 적용 플랜은 별도 확인이 필요하다.
참조: https://render.com/docs/free

## 기존 프로젝트 이전

마이그레이션 f57a63이 적용되는 시점의 모든 프로젝트 ID와 이전 소유/조직을
legacy_project_ownership에 기록한다. 휴지통 프로젝트도 포함한다.
기동 시 LV_BOOTSTRAP_ADMIN_EMAIL과 정확히 일치하는 활성·승인 관리자에게
소유권과 조직 귀속을 이전한다. 임의의 첫 관리자 계정을 선택하지 않는다.
대상이 없거나 비활성/반려/비관리자이면 커밋하지 않고 기동을 중단한다.

문서, 검증 결과, 보고서, 원본 파일 키, 과거 감사기록은 변경하지 않는다.
재기동 시 완료된 행은 건너뛰며 이후 생성한 프로젝트는 이전하지 않는다.
이전 내역의 migrated_at/target_owner_id와 서버 로그의 완료 건수로 확인한다.
최초 관리자로 로그인한 뒤 /api/admin/ownership-migration을 조회하면
대상 전체 건수(total), 완료(completed), 미완료(pending)를 확인할 수 있다.
배포 전 Render DB 백업/복원 지점을 확보하는 것이 권장된다.

## UI 평가

장점은 중립색과 녹색 중심의 일관된 업무 화면, 원문과 검토 결과의 연결,
정형 입력 폼과 표 중심 구성이다. 현재는 기능이 늘면서 탐색 구조가 복잡해졌다.

1. **높음: 관리자 도구가 계정 메뉴 안의 중첩 대화상자에 숨어 있음.**
   사용자 관리, 승인 대기, 월별 이용 현황, 메일 기록을 독립 관리 화면의 네 탭으로 구성한다.
   일반 사용자의 프로젝트 검토 흐름과 관리자의 계정 운영 흐름을 분리한다.
2. **높음: 긴 표에서 사용자 식별·상태·조치가 섞임.**
   이름/이메일, 역할, 승인 상태를 앞쪽에 고정하고 검색·상태 필터·페이지네이션을 제공한다.
   이번 보완에서는 이메일을 별도 줄에 표시하고 도구 버튼을 아이콘/툴팁으로 정리했다.
3. **높음: 화면상 성공과 실제 작업 완료를 혼동하기 쉬움.**
   승인 완료와 메일 접수를 분리하며, 데이터 로딩 실패를 0건으로 보여주지 않는다.
   이 기준은 분석, RAG, 보고서 다운로드에도 공통 적용해야 한다.
4. **중간: 검토 업무 탭이 많고 다음 행동이 분산됨.**
   상위 구조를 자료 / 검증·검토 / 보고서로 묶고 주장·쟁점, 일지, 계산은 관련 하위 도구로 배치한다.
   각 화면에 현재 선택 사건과 분석 실행 상태를 유지한다.
5. **중간: 모바일에서 다열 표와 반복 버튼이 과밀함.**
   작은 화면에서는 사용자명·상태·주요 조치만 먼저 표시하고 상세 패널에서 나머지를 제공한다.
   비교 표는 가로 스크롤 영역으로 제한하며 문서 전체의 가로 넘침은 금지한다.
6. **중간: 브랜드가 헤더·로그인·빈 화면에서 반복됨.**
   업무 화면 헤더는 56~64px로 정리하고 빈 화면은 사건 목록과 새 프로젝트 동작을 우선한다.
   브랜드 이미지는 유지하되 동일 이미지를 여러 계층에서 크게 반복하지 않는다.
7. **중간: 읽기 전용 화면의 종료 버튼이 취소로 표시됨.**
   조회 화면은 닫기, 입력 화면은 취소/확정으로 통일한다.

## 다음 단계와 검수 기준

- P0: 이번 정책·인증·메일·집계 변경을 CI로 검증하고 운영 배포 SHA를 확인한다.
- P1: 독립 사용자 관리 화면, 검색/필터/페이지네이션, 관리자 전용 탐색 메뉴.
- P1: 390px 및 데스크톱에서 입력·오류·로딩·빈 상태·키보드 탐색·모달 포커스 회귀 테스트.
- P2: 월말 저장량 스냅샷, CPU/메모리 실측이 필요한 경우 별도 수집. 현재 경과시간으로 대체 추정하지 않는다.
- P2: 원본뿐 아니라 OCR/보고서/휴지통까지 포함한 물리 저장량 정책을 별도로 설계한다.
- P2: 기존 관리자 발급 가능 시기에 생성된 API 토큰과 SSO 연결의 운영자 재검토.

최종 사용자 검수는 승인 신청 1건 처리, 반려 사유 확인, 메일 상태 확인,
서로 다른 소유자 간 URL 직접 접근 404, 관리자 이전 프로젝트 확인 순으로 진행한다.
통계와 메일의 자동 테스트는 실제 외부 메일 수신 검증을 대신하지 않는다.

## 프론트엔드 구현 반영

- 관리자 전용 상단 메뉴와 독립 관리 화면에 사용자 / 승인 대기 / 이용 통계 / 메일 기록을 분리했다.
- 이름·이메일·소속 검색, 계정 상태·역할 필터, 20/50/100개 페이지 크기를 제공한다.
  기존 조직별 API 응답 안에서 클라이언트 페이지네이션을 적용하며, 서버 측 분할 조회는 아니다.
- 사용자 상세, 승인·반려 확인, 권한 변경, 월별 추이, 메일 상세는 단일 상세 패널로 표시한다.
  모바일에서는 핵심 열만 유지하고 상세 패널은 전체 화면을 사용한다.
- 승인 결과와 메일 상태를 구별한다. SMTP 서버 접수는 수신함 도착으로 표시하지 않는다.
  반려 사유는 로그인 화면 안내 정책을 유지하며, 불명 상태의 메일은 재시도하지 않는다.
- 비정상 응답·조회 실패는 오류와 재조회 동작으로 표시하며 통계를 임의로 0으로 채우지 않는다.
  탭·계정이 바뀐 이후 도착한 응답은 폐기하고 중복 제출을 막는다.
- 사건 검토의 10개 도구는 자료 / 검증·검토 / 보고서 상위 메뉴 아래 보존했다.
  그룹별 마지막 하위 화면을 기억하며 관리 화면 왕복 시 선택 사건·분석 상태를 유지한다.
- 헤더를 64px로 정리하고 빈 화면의 반복 브랜드 이미지를 축소했다.
  조회 전용 대화상자의 종료 문구는 닫기로 통일했다.
- 자동 브라우저 검증은 합성 사용자와 모의 API를 사용한다. 실제 SMTP 전송, 수신함 도착,
  운영 DB의 이전 건수 확인은 별도 운영 검수 대상이다.

## 초기 화면, 휴지통 및 저장 한도 추가 개선

- 중앙의 검토 프로젝트 제목과 중복 생성 버튼을 제거했다. 엠블럼은 최대 280px로 표시하며,
  같은 폭 아래에 `created by 스티브, 아나스타샤, 스텔라, 에이미, 쏘니` 문구를 배치한다.
- 프로젝트 생성은 왼쪽의 플러스 아이콘과 `새프로젝트` 버튼으로 통합했다.
  소속은 14px, 이름은 18px로 확대하고 생성 버튼은 다음 줄 전체 폭을 사용한다.
- 휴지통 비우기는 확인한 시점의 목록만 대상으로 기존 개별 영구 삭제 API를 순차 호출한다.
  권한 검사, 사용 중인 프로젝트 보호, 감사기록을 유지한다. 실행 중 중복 제출과 모달 종료를 막는다.
  사용 중인 항목은 남겨두고 나머지를 처리하며, 인증 실패나 통신 결과 불명 시 이후 요청을 중단한다.
  삭제·실패·미시도 건수와 파일 정리 실패를 구분해 표시한다. 창을 벗어난 뒤 이어지는 백그라운드 작업은 아니다.
- 일반 사용자와 조회 전용 사용자의 저장 한도는 1GB(1,073,741,824바이트)이며 관리자는 제한하지 않는다.
  기존 계정에도 역할 기준 정책이 즉시 적용된다. 과거 사용자별 DB 한도 값은 이 정책을 덮어쓰지 않는다.
- 사용량은 휴지통에 보존된 문서를 포함한 등록 원본 크기의 합이다. 소프트 삭제나 복원으로 바뀌지 않고,
  영구 삭제로 원본 등록이 제거되면 해제된다. OCR·보고서·정리에 실패한 잔여 파일의 물리 용량은 별도 관리 대상이다.
- 관리자 API와 통계는 `storage_unlimited: true`, 한도와 사용률은 `null`로 반환한다.
  관리 화면과 CSV에는 제한 없음으로 표시한다. 관리자 용량 경고를 새로 만들지 않고 과거 대기 경고도 취소한다.
- 총 저장량 정책과 파일당 업로드 제한, Render의 실제 디스크 여유 공간은 별도 제약이다.
