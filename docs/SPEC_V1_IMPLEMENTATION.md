# 법률문서 AI 검증 프로그램 구현 명세 v1.0 반영 현황

기준일: 2026-09-21. 프로그램 v0.5.0, 규칙 버전 2026.09.21.1.

명세의 각 장을 기존 기능과 대조해, 새 기능은 추가하고 이미 있는 기능은
갱신 필요성을 따져 반영했다. 갱신하지 않기로 한 항목은 그 이유를 적었다.

## 1. 오류 유형 (제1.2장)

명세의 20개 코드 가운데 6개는 이 시스템에 이미 다른 이름으로 있었다. 같은
결함에 이름을 둘 두면 한쪽만 처리하는 코드가 생기므로 멤버를 새로 만들지
않고 `SPEC_FINDING_CODE` 대응표로 연결했다. 보고서는 두 이름을 함께 싣는다.

| 명세 코드 | 이 시스템의 FindingType |
|---|---|
| `CASE_NONEXISTENT` | `CASE_NOT_FOUND` |
| `CASE_HOLDING_MISMATCH` | `CASE_HOLDING_DISTORTION` |
| `STATUTE_VERSION_ERROR` | `TEMPORAL_LAW_MISMATCH` |
| `CALCULATION_ERROR` | `ARITHMETIC_MISMATCH` |
| `SECONDARY_SOURCE_ERROR` | `ACADEMIC_CITATION_ERROR` |
| `QUOTE_MISMATCH` | 신설(판례 전용 `CASE_QUOTE_MISMATCH`와 별도) |

나머지 14개는 새로 추가했다. 20개 코드가 모두 도달 가능한지는
`test_acceptance_every_spec_finding_code_is_reachable`이 고정한다.

## 3. 이미 있던 기능의 갱신 여부

| 기능 | 판단 | 근거 |
|---|---|---|
| 법령 인용 검증(`source_review`) | 대체하지 않고 확장 | 기존 판정은 존재·버전·조항·시점·문언을 따로 기록해 명세의 여섯 값보다 세밀하다. 구조를 바꾸면 정보가 줄어든다. 명세 어휘로 읽을 수 있는 `spec_verdict`를 파생시켜 함께 실었다 |
| 판례 적용성 검토 | 확장 | 관련성 5개 축을 추가했다. 기본값은 0이 아니라 미측정이다 |
| 산술 검산(`claim_engine.calculation`) | 유지 + 신설 | 기존 모듈은 문서에 적힌 합계와 내역 합산을 대조한다. 명세 제6장이 요구하는 것은 전제에서 값을 도출하는 계산이므로 성격이 달라 별도 모듈로 두었다 |
| 결과 집계(`scoring`) | 갱신 | 축별 위험도는 그대로 두고 배포 게이트를 추가했다. 축을 하나로 합산하지 않는다는 제20.1장 원칙은 유지된다 |
| 작성자 분석(`authorship`) | 변경 없음 | 문체로 작성자를 판정하지 않는다는 기존 정책이 명세 제8.1장과 같다. 검증위험 지수에 문체 신호를 넣지 않는 것으로 경계를 고정했다 |
| 보고서 출력 | 갱신 | Finding 행에 명세 코드명을, XLSX 개요와 화면 요약에 배포가능 상태와 사유를 추가했다 |

## 4. 설계상 지키기로 한 경계

- 조회 실패(`UNVERIFIABLE`)와 원문 미발견(`NOT_FOUND`)을 끝까지 구분한다.
  섞으면 공식 API 장애가 "그런 판례는 없다"로 둔갑한다.
- 측정하지 않은 값을 0으로 쓰지 않는다. 관련성 축, 의결권 유무, 정족수 기준이
  모두 미측정 상태를 별도로 가진다.
- 가중합이 치명적 오류를 상쇄하지 못한다. 하드게이트가 지수보다 우선한다.
  주장별 신뢰도도 축 하나가 0이면 `HARD_FAIL`, 0.5 미만이면 "충분"이 아니다.
- 체크리스트 매칭으로 법률 결론을 확정하지 않는다. 누락 후보만 제시한다.
  결론이 없는 문서(계약서 등)에는 누락이라 할 대상이 없으므로 보고하지 않는다.
- 정족수 기준은 근거(법령·정관·계약)와 함께 지정받는다. 기본 기준을 자동
  적용하지 않으며, 기준이 없으면 가결 여부를 단정하지 않는다.

## 5. 아직 하지 않은 것

| 명세 | 상태 | 이유 |
|---|---|---|
| 제7.1장 IRAC 그래프 | 미구현 | 명세 제14장에서도 2단계다. 논증 요소 추출은 근거 없는 구조화를 낳기 쉬워 먼저 요건 대응 규칙을 정해야 한다 |
| 제4.2장 관련성 임베딩 | 인터페이스만 | 축을 채울 임베딩·라벨이 없다. 값이 주어지면 즉시 판정한다 |
| 제4.3장 문헌 원문 페이지 확인 | 부분 | 서지 확인은 있으나 해당 페이지의 명제 확인은 원문 접근 권한이 필요하다 |
| 제12.1장 3분할 화면 | 부분 | 원문·판정·근거를 볼 수 있으나 3분할 동시 표시는 아니다 |
| HWP/HWPX 고급 복원 | 미구현 | 명세 3단계 |

## 6. 회귀시험

`tests/test_spec_golden.py`가 명세 제13장 T01~T12와 제16장 인수기준 중 구조로
고정할 수 있는 항목을 담는다. 명세가 예로 든 원자료(주주간계약서, 회의록,
이메일)는 이 저장소에 없다. 없는 자료의 내용을 지어내면 시험이 통과해도
아무것도 보장하지 못하므로, 각 시험은 판정 구조를 최소 입력으로 재현하고
실재 여부를 확인해야 하는 사건번호와 판시 내용은 쓰지 않는다.
